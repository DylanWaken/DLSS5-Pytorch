01. Define the model piece before choosing a GPU tile

global_projection_c1024_fp16 belongs to the C1024 bottleneck, records 31–38. It projects the 32 attention heads, concatenated into A[T,1024], through Wₒ[1024,1024] and adds the separately scaled FFN residual Z. With row-vector notation the equation is Y[t,n]=Publish(Σₖ A[t,k]W[k,n]+attn_scale[n]·Z[t,n]). The result is logically [T,1024]. The scale has 1024 channel values and broadcasts over tokens. There is no activation or matrix bias in this entry.

The architecture’s 4K example has H=36,W=60,T=2160. This body uses T=BatchCount·TokensPerBatch; the prepared plan runs batch one. Inputs, matrix operands and final output use FP16. Residual scales, accumulators and intermediate split sums use Half. This public FP16 entry owns its complete kernel body. The architecture document locates this operation in the block, while this lesson derives its implementation locally.

02. Write a scalar baseline and identify the repeated work

This baseline says one output reads all 1024 channels at one token plus one residual value. There is no communication between token t and token t+1. Assigning one thread to each output would reread each input row for many output columns, and reread the same W columns for every token. Separate residual and publication kernels would add further global reads/writes. Those costs suggest grouping outputs, reusing operand panels and fusing the residual. The scalar equation is a dependency reference; exact deployment equivalence additionally requires the recovered split order and Half rounding described below.

One instruction computes a 16-token × 8-output-channel tile with a reduction of 16 channels. All 32 lanes participate in the same matrix operation. Each lane supplies four 32-bit A words, two 32-bit B words, and two 32-bit C words. Each C word contains two Half accumulators, so a lane owns four output elements. A source loop over output groups or reduction panels repeats this operation; it does not launch a new warp.

The exact instruction on this path is mma.sync.aligned.m16n8k16.row.col.f16.f16.f16.f16. Both the accumulator input and output are Half. Do not replace its numerical contract with FP32 accumulation when constructing an exact oracle. For the FP8 path, packing to E4M3 is a distinct rounding step; for the FP16 path a packed word simply holds two Half values.

Let lane L run from 0 to 31, g = L // 4 and q = L % 4. The matrix coordinates below describe instruction operands after any kernel-specific loads and shuffles. Storage layouts are designed to supply these coordinates cheaply.

03. Grow a warp primitive into the source CTA

Four M16 fragments and eight N8 fragments give one warp a 64×64 output. Represent it as four M16 groups × four N16 groups × four Half2 accumulator words per lane. Arrange four warps as two token halves and two channel halves to cover M128×N128. This keeps each output fragment in registers while reusing one A fragment across multiple N panels and one B fragment across four M panels. A CTA contains 128 threads, with lane=threadIdx.x and warp=threadIdx.y.

Let Mtiles=ceil(T/128). For block.x=b, channelBlock=floor(b/Mtiles), firstGroup=(b modMtiles)·8 and outputChannel=128·channelBlock+64·(warp mod2). The warp consumes groups firstGroup+4·floor(warp/2)+m, m=0…3. Split selection is OrderedSplit ? OrderedSplit−1 : blockIdx.z. Unlike an ordinary complete GEMM, this CTA computes only 256 of the 1024 input channels. Four such partial computations contribute to the same output addresses.

Define the packed layout before optimizing memory traffic

The public pointers address opaque packed buffers. A token group contains 16 rows. One native M16×K16 A panel consumes 512 bytes, distributed as 32 lanes ×16 bytes. For input width K and element size E, group g begins at g·16·K·E. A reduction step advances along K in whole panels. Within a panel, lane L reads the vector at L·16. The publication layout arranges token rows and channel pairs to make those four words immediately usable by MMA.

A packed B panel for 16 output channels also occupies 512 bytes. One lane’s uint4 supplies two N8 fragments: the first two words belong to the first N8, the next two words to the second. Across K panels, the record advances by N·32 bytes, where this kernel’s N is 1024. The equality follows from 16 reduction values × 2 bytes per value =32 bytes per output column. A cache-all vector load fetches those words directly to registers.

For FP16 weights, packed_f16_weight_index(k,n,N) returns a Half-element offset: panel=(k//16)·ceil(N/16)+n//16; lane=4·(n mod8)+floor((k mod8)/2); within-lane index=4·floor((n mod16)/8)+2·[k mod16≥8]+(k mod2). Multiply the result by two to obtain bytes. This gives you a scalar packer independent of the kernel’s vector-load formula.

The C/D accumulator has an easier map. In one M16×N8 result, lane L owns token rows floor(L/4) and floor(L/4)+8, and output channels 2·(L mod4) and 2·(L mod4)+1. Two packed Half words hold those four elements. An N16 tile contains two such fragments and therefore four words per lane. 04. Introduce four K splits without losing the residual or rounding order

Partition K into ranges [0,256),[256,512),[512,768),[768,1024). Split s computes its own Half MMA result Cₛ. Only s=0 starts its accumulator from HalfMul(scale,residual); later splits start from zero. Adding the residual in all four splits would multiply that path by four. Adding it after all dots instead would change the existing Half accumulation sequence.

After independent computation, publish in order: P₀=C₀; P₁=HalfAdd(P₀,C₁); P₂=HalfAdd(P₁,C₂); final=HalfAdd(P₂,C₃). The output allocation itself holds P, and becomes the final tensor after split 3 writes its final Half result. This is not an arbitrary-order atomic sum and not one FP32 reduction. The structure reproduces the recorded publication boundaries.

05. Derive input, weight, residual and partial addresses

Within one split, the reduction advances by K32, giving 8 steps. One 16-token group’s slab contains 32·16·2=1024 bytes. Its global base is A+(g·1024+s·256+i·32)·16·2. The eight groups together occupy 8192 bytes per shared stage. This specialization copies 512 bytes per producer operation, so 2 producer warp positions cooperate per group. In the source’s unified copy loop, copySlot=warp+4·Copy, group=firstGroup+floor(copySlot/2), and destination=stage·8192+copySlot·512. Projection’s 512-byte copies separate the native K panels across producer positions.

The consumer A vector is at shared (i mod2)·8192+floor(warp/2)·4·1024+lane·16+m·1024+kSubtile·512. W’s register vector starts at W+(s·256+i·32)·1024·2+outputChannel·32+lane·16+kSubtile·32768+n16·512. There are 2 native K subtiles per step. The fixed 32768 stride is 1024 output columns ×32 bytes per native K panel; it is independent of the scalar element width.

For a Half partial, the address is partial+(g·1024+outputChannel)·32+lane·16+n16·512. The factor 32 is 16 tokens ×2 bytes. A residual vector instead uses the working element width: Z+(g·1024+outputChannel)·16·2+lane·16+publicationPanel·512. Scale pairs are always Half, appended at W+1024·1024·2; within that tail, the byte offset is 2·(outputChannel+16·n16+8·n8+2·(lane mod4)). The example’s n16=2,n8=0,lane 13 therefore selects scale channels 34/35, beginning 68 bytes beyond the matrix.

06. Build a one-slot synchronous split kernel

At this point the arithmetic, addresses, residual and partial-tensor lifetime are complete. The remaining bottleneck in the scaffold is exposed copy latency between repeated matrix tiles. The source adds 2 shared stages, totaling 16384 data bytes plus 16 barrier bytes. This two-slot specialization begins with one ready stage and peels its final MMA out of the loop. B remains in registers rather than occupying another shared ring.

07. Replace the scaffold with the actual stage schedule

Make the copy barrier part of the construction

Allocate 2 shared data slots and one 8-byte mbarrier per slot. Lane 0 of warp 0 initializes each barrier with 128 expected thread arrivals, then the CTA synchronizes before any producer can issue copies. On SM90+, IsCopyProducer elects one lane per participating warp; it issues an ordinary-address cp.async.bulk and registers the transferred byte count. On SM80/89, every lane issues 16-byte cp.async.cg stripes and attaches its own copies with cp.async.mbarrier.arrive. A 512-byte transfer needs one stripe per lane, a 1024-byte transfer needs two.

ArriveAndWait makes every thread arrive, obtains the current phase token, and polls until that exact phase completes. Reusing the same barrier address next iteration requires a new token; readiness from a previous cycle is insufficient. Completion also accounts for attached asynchronous transfers. Ordinary thread arrival alone cannot establish copy completion. The schedule must separately establish that the previous tile’s readers have finished before a slot is overwritten. No tensor-map descriptor, TMEM allocation, warp-group MMA or shared-to-register ldmatrix operation is used in this path: its shared vectors already have the correct MMA fragment order.

The loop stops at steps−2, and the last ready tile is consumed once outside it. Reordering waits and refills based only on modulo arithmetic can overwrite a stage before every reader has finished.

08. Publish partials and the final tensor

Split 0 stores its Half partial with no L1 allocation. Splits 1/2 use Half2 global reductions: four scalar operations before SM90, one vector operation on SM90+. Split 3 loads the accumulated predecessor partial, performs four Half2 adds per N16 tile, then writes the final Half words directly back to the output allocation. The Half implementation uses its global-reduction helper for intermediate phases and a cache-all load before the final Half add. These choices affect instruction and cache behavior, but do not change the required ownership: one lane in the current split owns each published vector.

Order split publication independently of computation

The source supports two protocols. With OrderedSplit=0, blockIdx.z is the logical split. A later split may compute its matrix partial while its predecessor runs, but before touching the predecessor’s global partial it polls the corresponding counter until the recorded split is available. The counter starts at −1, and each producer performs a release counter store after its publication and a CTA synchronization. This entry polls relaxed counters and uses a CTA barrier, but does not call the separate acquire helper in this source snapshot. The description records that protocol; it is not a new formal memory-order proof.

With OrderedSplit=s+1, the host launches only the XY plane for split s, with grid.z=1. The same stream completes that plane before entering the next split. The kernel skips the resident predecessor wait. The launcher selects this path when the complete dependent grid cannot fit its occupancy-derived capacity; otherwise waiting consumers could occupy resources needed by unscheduled producers. It preserves all 4 partials and their Half rounding rather than replacing them with a different reduction.

Keep scratch, output, residual and counter allocations live until their final consumers finish. Registers and shared memory belong to one CTA invocation and cannot carry a result into the next split launch. The partial tensor is the explicit storage bridge. Counters govern publication, not the mathematical value of a matrix element.

For this entry the four-byte counter address is g_SplitCounters+(firstGroup+channelBlock)·4. There are eight 128-channel output blocks; firstGroup=8·tokenTile, so this indexes one counter per token tile/output-channel block. Later resident splits wait until the signed counter is at least s−1. After all lane stores and the CTA synchronization, lane 0/warp 0 releases the current split number s.

09. Complete reconstruction pseudocode

10. Test the properties that define this kernel

  1. Residual once: set W to zero. Valid output rows should equal the documented publication of HalfMul(scale,residual), with no factor of four and no contribution from other tokens.
  2. Each split contributes: place one nonzero input/weight pair in each K region and compare saved P₀,P₁,P₂ and final. They must follow the specified Half addition order. Values chosen near Half rounding boundaries distinguish this from a reassociated or FP32 sum.
  3. Scratch format: verify the output buffer holds valid Half partials before it becomes the final tensor; consumers must not read it early.
  4. Address ownership: use the worked token 83/channel 34 example and nearby lane/channel groups. Every output vector must be written once per publication phase, and guard bytes must remain unchanged.
  5. Schedule equivalence: run both admitted resident mode and forced ordered split mode on supported hardware; final bytes should agree. Include more XY blocks than fit in one wave to exercise the host’s capacity fallback.
  6. Tail and ring behavior: use legal token extents around group and CTA boundaries; exercise all 8 K steps so the 2 slots wrap repeatedly. Invalid groups must be zero during computation and omitted from output publication.

The optimization argument follows the construction: grouped MMA shares A across columns and B across tokens; the residual seed removes a separate pass; the staged A ring can overlap transfer with work; register B avoids a shared weight copy; split-specific epilogues avoid converting partials too early. Splitting also creates global scratch traffic and synchronization, and extra stages consume shared capacity. Those tradeoffs need measurements for this precision and geometry; this lesson reports no invented speedup.

68			}
69			else
70			{
71				#pragma unroll
72				for (int s_Subtile = 0; s_Subtile < Profile::s_CopyBytes / 512; ++s_Subtile)
73					*reinterpret_cast<uint4*>(s_Storage + s_Destination + s_Subtile * 512 +
74											  TileCoordinates.Lane * 16) = make_uint4(0, 0, 0, 0);
75			}
76		}
77	};
78
79	// Only a completed stage can feed the register MMA tile.
80	const auto WaitStage = [&](int ReductionTile)
81	{
82		const int s_Barrier = Profile::s_BarrierOffset + (ReductionTile % Profile::s_StageCount) * 8;
83		ArriveAndWait(s_Storage, s_Barrier);
84	};
85
86	// Initialize the shared copy barriers before any warp issues input transactions.
87	if (Lane == 0 && Warp == 0)
88		#pragma unroll
89		for (int s_Stage = 0; s_Stage < Profile::s_StageCount; ++s_Stage)
90			BarrierInit(s_Storage, Profile::s_BarrierOffset + s_Stage * 8, blockDim.x * blockDim.y);
91	__syncthreads();
92
93	uint4 r_Weights[Profile::ReductionSubtiles][4];
94
95	// Prefetch weights without changing the ring dependency order.
96	const auto LoadWeights = [&](int ReductionTile)
97	{
98		const uint64_t g_WeightTileBase = Parameters.g_PackedWeights +
99										  uint64_t(TileCoordinates.Split * Profile::SplitChannels +
100												   ReductionTile * Profile::ReductionStep) *
101											  1024 * Profile::ElementBytes +
102										  TileCoordinates.g_OutputChannel * 32 + TileCoordinates.Lane * 16;
103		#pragma unroll
104		for (int r_KSubtile = 0; r_KSubtile < Profile::ReductionSubtiles; ++r_KSubtile)
105			#pragma unroll
106			for (int r_ChannelGroup = 0; r_ChannelGroup < 4; ++r_ChannelGroup)
107				r_Weights[r_KSubtile][r_ChannelGroup] = __ldca(reinterpret_cast<const uint4*>(
108					g_WeightTileBase + r_KSubtile * 32768 + r_ChannelGroup * 512));
109	};
110
111	// Prime the weight registers and input pipeline before entering the reduction loop.
112	LoadWeights(0);
113	#pragma unroll
114	for (int s_InitialStage = 0; s_InitialStage < Profile::s_InitialStages; ++s_InitialStage)
115		StageInput(s_InitialStage);
116	WaitStage(0);
117	FGlobalContractAccumulator r_Accumulator{};
118
119	// Only the first K split seeds the accumulator from the residual.
120	if (TileCoordinates.Split == 0)
121	{
122		// The record appends 1024 Half scales to the matrix. Lane's two adjacent
123		// channels share a packed scale; words 0/1 and 2/3 belong to separate N8s.
124		uint32_t r_ResidualScales[4][2];
125		#pragma unroll
126		for (int r_ChannelGroup = 0; r_ChannelGroup < 4; ++r_ChannelGroup)
127			#pragma unroll
128			for (int r_N8 = 0; r_N8 < 2; ++r_N8)
129				r_ResidualScales[r_ChannelGroup][r_N8] = *reinterpret_cast<const uint32_t*>(
130					Parameters.g_PackedWeights + Profile::MatrixBytes +
131					(TileCoordinates.g_OutputChannel + r_ChannelGroup * 16 + r_N8 * 8 +
132					 (TileCoordinates.Lane & 3) * 2) *
133						2);
134
135		#pragma unroll
136		for (int r_Spatial = 0; r_Spatial < 4; ++r_Spatial)
137		{
138			const int g_Group =
139				TileCoordinates.bBroadcastInput
140					? 0
141					: TileCoordinates.g_TokenGroupBase + (TileCoordinates.Warp >> 1) * 4 + r_Spatial;
142			const uint64_t g_ResidualTileBase =
143				Parameters.g_Residual +
144				uint64_t(g_Group * 1024 + TileCoordinates.g_OutputChannel) * 16 * Profile::ElementBytes +
145				TileCoordinates.Lane * 16;
146			{
147				#pragma unroll
148				for (int r_ChannelGroup = 0; r_ChannelGroup < 4; ++r_ChannelGroup)
149				{
150					const uint4 r_PackedResidual = g_Group < TileCoordinates.g_PaddedGroups
151													   ? __ldcg(reinterpret_cast<const uint4*>(
152															 g_ResidualTileBase + r_ChannelGroup * 512))
153													   : make_uint4(0, 0, 0, 0);
154					auto& r_AccumulatorWords = r_Accumulator.r_AccumulatorWords[r_Spatial][r_ChannelGroup];
155					r_AccumulatorWords[0] = HalfMul(r_PackedResidual.x, r_ResidualScales[r_ChannelGroup][0]);
156					r_AccumulatorWords[1] = HalfMul(r_PackedResidual.y, r_ResidualScales[r_ChannelGroup][0]);
157					r_AccumulatorWords[2] = HalfMul(r_PackedResidual.z, r_ResidualScales[r_ChannelGroup][1]);
158					r_AccumulatorWords[3] = HalfMul(r_PackedResidual.w, r_ResidualScales[r_ChannelGroup][1]);
159				}
160			}
161		}
162	}
163
164	// Native two-stage code peels the final MMA tile out of the prefetch loop.
165	// Keeping that drain explicit removes a per-iteration tail branch. The
166	// three-stage Half contraction retains its distinct refill lifecycle.
167	#pragma unroll 1
168	for (int ReductionTile = 0;
169		 ReductionTile < Profile::ReductionTiles - (Profile::s_InitialStages == 1 ? 1 : 0); ++ReductionTile)
170	{
171#if __CUDA_ARCH__ < 900
172		// WaitStage(i) completed every thread's arrival after Consume(i-1),
173		// releasing that old slot. Prefetch i+1 into it while i's MMA runs in
174		// the other slot; the weight registers still hold i until consumption.
175		StageInput(ReductionTile + 1);
176#endif
177		ConsumeGlobalContractInputStage<Profile>(r_Accumulator, r_Weights, s_Storage, ReductionTile,
178												 TileCoordinates);
179		{
180#if __CUDA_ARCH__ >= 900
181			StageInput(ReductionTile + 1);
182#endif
183			LoadWeights(ReductionTile + 1);
184			WaitStage(ReductionTile + 1);
185		}
186	}
187
188	ConsumeGlobalContractInputStage<Profile>(r_Accumulator, r_Weights, s_Storage, Profile::ReductionTiles - 1,
189											 TileCoordinates);
190
191	// Compile-time split policy keeps the native branch outside all store loops.
192	const auto PublishFragments = [&](auto PublicationTag)
193	{
194		constexpr auto Publication = decltype(PublicationTag)::value;
195		const bool bFirstSplit = Publication == EGlobalContractSplitPublication::Runtime
196									 ? TileCoordinates.Split == 0
197									 : Publication == EGlobalContractSplitPublication::First;
198		const bool bIntermediateSplit = Publication == EGlobalContractSplitPublication::Runtime
199											? TileCoordinates.Split < 3
200											: Publication == EGlobalContractSplitPublication::Intermediate;
201
202		// Serial publication preserves the DLL's Half rounding between K splits.
203		// FP8 keeps partial sums in a separate Half buffer until the fourth split.
204		const uint64_t g_PartialSums = bFp8 ? Parameters.g_SplitAccumulator : Parameters.g_Output;
205		#pragma unroll
206		for (int r_Spatial = 0; r_Spatial < 4; ++r_Spatial)
207		{
208			const int g_Group =
209				TileCoordinates.g_TokenGroupBase + (TileCoordinates.Warp >> 1) * 4 + r_Spatial;
210			if (g_Group < TileCoordinates.g_PaddedGroups)
211			{
212				const uint64_t g_HalfBase = g_PartialSums +
213											uint64_t(g_Group * 1024 + TileCoordinates.g_OutputChannel) * 32 +
214											TileCoordinates.Lane * 16;
215				#pragma unroll
216				for (int r_ChannelGroup = 0; r_ChannelGroup < 4; ++r_ChannelGroup)
217				{
218					auto& r_AccumulatorWords = r_Accumulator.r_AccumulatorWords[r_Spatial][r_ChannelGroup];
219					const uint64_t g_PartialSumAddress = g_HalfBase + r_ChannelGroup * 512;
220					if (bFirstSplit)
221						StoreNoAllocate(g_PartialSumAddress,
222										make_uint4(r_AccumulatorWords[0], r_AccumulatorWords[1],
223												   r_AccumulatorWords[2], r_AccumulatorWords[3]));
224					else if (bIntermediateSplit)
225						ReduceHalf4(g_PartialSumAddress,
226									make_uint4(r_AccumulatorWords[0], r_AccumulatorWords[1],
227											   r_AccumulatorWords[2], r_AccumulatorWords[3]));
228					else
229					{
230						const uint4 r_PreviousSplitWords =
231							__ldca(reinterpret_cast<const uint4*>(g_PartialSumAddress));
232						r_AccumulatorWords[0] = HalfAdd(r_PreviousSplitWords.x, r_AccumulatorWords[0]);
233						r_AccumulatorWords[1] = HalfAdd(r_PreviousSplitWords.y, r_AccumulatorWords[1]);
234						r_AccumulatorWords[2] = HalfAdd(r_PreviousSplitWords.z, r_AccumulatorWords[2]);
235						r_AccumulatorWords[3] = HalfAdd(r_PreviousSplitWords.w, r_AccumulatorWords[3]);
236						StoreNoAllocate(g_PartialSumAddress,
237										make_uint4(r_AccumulatorWords[0], r_AccumulatorWords[1],
238												   r_AccumulatorWords[2], r_AccumulatorWords[3]));
239					}
240				}
241				{
242				}
243			}
244		}
245	};
246
247	const uint64_t g_SplitCounters =
248		Parameters.g_SplitCounters + (TileCoordinates.g_TokenGroupBase + TileCoordinates.g_ChannelBlock) * 4;
249	if (TileCoordinates.Split > 0)
250	{
251		// The stream boundary orders Half scratch updates without resident peers.
252		if (Parameters.OrderedSplit == 0 && TileCoordinates.Lane == 0 && TileCoordinates.Warp == 0)
253			while (int32_t(CounterLoadRelaxed(g_SplitCounters)) < TileCoordinates.Split - 1)
254				PollSleep(64);
255		__syncthreads();
256	}
257
258	PublishFragments(
259		std::integral_constant<EGlobalContractSplitPublication, EGlobalContractSplitPublication::Runtime>{});
260	__syncthreads();
261	if (TileCoordinates.Lane == 0 && TileCoordinates.Warp == 0)
262		CounterStoreRelease(g_SplitCounters, TileCoordinates.Split);
263#endif
264}

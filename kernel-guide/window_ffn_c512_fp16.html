01. The model operation this kernel must implement

window_ffn_c512_fp16 implements the premix and grouped MLP portion of a C512 FFN. It receives native tiled X with logical shape [H,W,512] and produces the contracted branch tensor B of the same shape. This is the ordinary C512 path used where the input already has native 4 × 4 tile storage, within records 23–30 and 40–47 according to launch selection. At the documented 4K geometry H=68 and W=120. Its output still needs a separate 512→512 postmix and scaled residual before becoming the block’s FFN result. Neither attention nor that postmix is silently included here.

The network architecture guide, rendered from docs/ARCHITECTURE.md, places this operation in the full encoder–bottleneck–decoder. This lesson defines the operation and its physical implementation locally so it can be read independently.

For one position p, compute u[p,:] = X[p,:] Wpre. Partition the 512 premixed channels into eight distinct slices u[p,64g:64g+64]. Group g computes B[p,64g:64g+64] = φ(u_g Wexpand_g) Wcontract_g, with matrices [64,256] and [256,64]. All eight groups execute. The first matrix is [512,512]; its purpose is to mix original channels before slicing. This differs from a full-input branch model: each grouped expansion reads only its own 64 premixed channels.

02. Build the simplest correct graph before tiling it

A first implementation can materialize u, a [H,W,8,256] hidden tensor and B. Assign one scalar output element to a thread and sum its input channels. This makes the grouping unambiguous: contraction for group 3 must read group 3’s hidden values, not any other group. It also exposes the costs we will remove: writing and rereading the dense premix, materializing a four-times-expanded hidden tensor, and fetching the same input vector independently for each output channel.

The working storage format on this page is IEEE Half / FP16. Tensor-core accumulation, residual products, the recovered activation and the reduction trees discussed here use packed Half words. A uint32_t is a bit container for two Half values, not an integer approximation to their sum. HalfMul, HalfAdd and HalfFma preserve the source’s separately rounded operations; replacing them with FP32 expressions and a final cast changes that contract. The operand and accumulator use the same element type, but their lane-word arrangements still differ by matrix role. Equal dtype does not make an arbitrary row-major uint4 a valid MMA fragment.

Start with a high-precision scalar oracle to validate which input contributes to which output. Once the connectivity is correct, introduce a second oracle that follows the source’s K chunk order and publication points. A scalar FP32 sum is not a bitwise reference for Half MMA; it is a tool for catching transposes, wrong groups and wrong spatial coordinates. Keep these two correctness goals separate throughout reconstruction.

03. Tile output ownership so a group’s intermediates stay local

A CTA covers one 8 × 8 position region and four groups. Grid Z selects groups 0–3 or 4–7, and group ownership is (warp%4)+4·blockIdx.z. The block is (32,4). Four warps each own one group over all four M16 fragments. The whole 64-position region is retained by that group’s warp. This arrangement makes expansion and contraction warp-local once the premix finishes; no inter-warp hidden exchange is required.

One instruction computes a 16-token × 8-output-channel tile with a reduction of 16 channels. All 32 lanes participate in the same matrix operation. Each lane supplies four 32-bit A words, two 32-bit B words, and two 32-bit C words. Each C word contains two Half accumulators, so a lane owns four output elements. A source loop over output groups or reduction panels repeats this operation; it does not launch a new warp.

The exact instruction on this path is mma.sync.aligned.m16n8k16.row.col.f16.f16.f16.f16. Both the accumulator input and output are Half. Do not replace its numerical contract with FP32 accumulation when constructing an exact oracle. For the FP8 path, packing to E4M3 is a distinct rounding step; for the FP16 path a packed word simply holds two Half values.

Let lane L run from 0 to 31, g = L // 4 and q = L % 4. The matrix coordinates below describe instruction operands after any kernel-specific loads and shuffles. Storage layouts are designed to supply these coordinates cheaply.

Per-lane operandLogical matrix coordinates
A word i = 0…3token row g + 8(i % 2); reduction channels 2q + 8⌊i/2⌋ + h, h = 0…1
B word j = 0…1output column g; reduction channels 2q + 8j + h, h = 0…1

The operand and accumulator coordinates follow the NVIDIA PTX matrix-fragment specification. A kernel may permute model channels before supplying these instruction coordinates; its publication and weight-packing rules must agree.

04. Derive byte addresses before writing the fast loop

A native input tile represents sixteen positions in a physical 4 × 4 image patch. Its byte extent is 16·512·2 = 16,384. Tile index q advances by that whole extent, an instruction-K stripe advances by 512 bytes, and lane l selects 16·l bytes within the stripe. Thus one A load is input + q·16384 + stripe·512 + lane·16. For q=7, stripe=1 and lane=13, the base-relative address is 115,408 bytes. The lane reads one uint4 containing eight Half values. These values are already arranged as a matrix operand; they are not simply consecutive channels of one pixel.

The weight record groups output columns into N16 panels and reduction channels into K16 instruction slices. Each instruction slice consumes 16·2=32 bytes per output column. Its lane-vector address is W + reductionStart·512·2 + outputChannel·32 + lane·16 + panel·512. For reductionStart=16, outputChannel=128, panel=1 and lane=13, this is 21,200 bytes. The panel term is relative to the warp’s output base. Adding a complete K slice advances 16,384 bytes, not 512: 512 advances N16, while 16,384 advances all 512 output columns.

Write a small host-side address decoder first. Give each logical input element a distinguishable value, encode a single native tile, and check exactly which token/channel arrives in each lane word. Repeat for one weight panel. This isolates layout errors from arithmetic errors: a wrong transpose can still produce plausible values for uniform inputs. In the kernel, all these pointer expressions use byte offsets because the public ABI passes integer addresses rather than typed multidimensional tensor views.

05. Compute premix once, then stream hidden panels

For a single instruction-K step, an input A fragment is reused across four N16 output panels, and each weight B bundle is reused across the warp’s 4 spatial fragments. That is the first improvement over scalar outputs: input and weight fetches pay for multiple independent MMA results. Four-word accumulators remain live across the full K=512 reduction. When it completes, they already represent the group’s 64 premixed channels in the order needed by the next multiply.

The hidden tensor is the next expensive allocation. We do not need all 256 hidden channels at once: the contraction is a sum over them. Visit eight panels of 32 hidden channels, allocate only that panel’s accumulator, expand from the 64-channel group, activate it, and immediately add its contraction contribution to B. This keeps the complete premix slice and final output but only one hidden panel. The tradeoff is a longer lifetime for output accumulators; the benefit is removing the full hidden image write/read and the premix image write/read.

The packed record contains 262,144 premix elements, then eight 16,384-element expansions, then eight 16,384-element contractions. Group g’s bases are (262144+16384g)·2 and (393216+16384g)·2 bytes. For group 5 these are 688,128 and 950,272 bytes. Add lane·16 and the selected hidden/K/N panel offsets only after selecting that group’s matrix. This prevents the common bug of treating each group’s expansion and contraction as interleaved in the record.

06. Overlap input movement without reusing live bytes

The scalar baseline reloads input independently for each output. Our tiled version first shares an input stripe among output-panel computations. A synchronous prototype can copy a stage, execute a CTA barrier, consume every fragment, then execute a second barrier before overwriting the stage. That establishes correct producer/consumer ownership. The deployed kernel replaces the idle copy phase with a 2-slot ring. A slot holds 4,096 data bytes; its 8-byte barrier lives after all data slots, so the allocation is 2·(4096+8) = 8,208 bytes.

CopyBulk accepts a shared byte offset, a global address, byte count and barrier offset. On SM90+ it uses a bulk asynchronous copy with transaction-byte completion and an elected producer; BarrierExpect registers the expected bytes. On supported earlier targets the helper distributes 16-byte copies across warp lanes and attaches their completion to the mbarrier. BarrierExpect is then intentionally a no-op because that path does not use the transaction-byte mechanism. Initialize every stage barrier once with the full CTA arrival count, then synchronize before any copy can refer to it. An out-of-domain stripe is filled with zeros by its lane writers; those threads still join the barrier protocol.

The prologue loads W0, issues X0 and waits for slot zero. Iteration t issues X[t+1] into the other slot before consuming X[t]. It then prefetches W[t+1] and waits on the next slot. Every warp reaches that wait only after reading its current stage, so the later producer phase can recycle it. The final iteration skips both the nonexistent refill and the next wait.

The 16 outer iterations stay rolled in the source, while spatial, N-panel and instruction-K fragment loops unroll. That lets fixed array indices select register values without expanding the entire long reduction into a huge instruction stream. More stages can hide more copy latency but consume shared memory; more fragments improve operand reuse but increase live registers. Those are the relevant tradeoffs, not a claim that a larger ring is always faster. __maxnreg__ supplies a compiler limit, not an observed register count. Inspect generated resource reports and time representative shapes before changing either knob.

07. Publish only the contracted branch tensor

For native output tile q, group g and lane l, the first vector goes to B+q·16384+g·2048+16l. Four Half vectors per lane cover the 64-channel group, one per N16 accumulator group. For q=7, g=5 and l=13, the first vector address is 125,136 bytes from B. Clip spatial tiles before storing. Every valid output group is written by exactly one warp, so no atomic is necessary.

08. The helper contracts needed to reconstruct this entry

FMmaAccumulatorTile<M,N> contains [M][N][4] 32-bit words per lane. Each N index means sixteen output channels, built from two N8 MMA instructions; it does not mean a sixteen-byte vector in logical row-major order. AccumulateTile takes an array of four-word A fragments and four-word weight bundles, uses the lower two B words for the first N8 result and upper two for the second, and updates the four Half2 words in place. When two instruction-K subtiles exist, it advances each accumulator through subtile zero before subtile one; the FP16 QKV stage supplies only one K16 subtile. The API’s by-value operands ensure an output update does not change the fragment arguments still being evaluated.

StoreNoAllocate emits an aligned 128-bit global store with an L1 no-allocation request. __ldca loads weights with cache-all policy; residual readers may use __ldcg. These are memory-policy choices rather than barriers or promises that an access reaches a particular cache level. A correct implementation must separately satisfy the synchronization protocol and vector alignment. Direct Half publication preserves the accumulator words, which is precisely why the next packed matrix operation can reuse them without an intermediate logical tensor transpose.

09. A complete reconstruction checklist in executable order

10. Reconstruction checks, in the order they isolate errors

  1. Pack an identity premix and group-distinguishing expansion/contract matrices; prove that group g reads only its own premixed 64 channels and that all eight output groups appear.
  2. Validate the numeric input and output addresses above with a single nonzero token/channel; compare native storage with a decoded logical [H,W,512] view.
  3. Run H=68,W=120 and a small multi-tile shape to exercise an incomplete 8×8 bottom edge; separately exercise the explicitly supported singleton-tile broadcast policy.
  4. Check both grid-Z group slabs and, for an eight-warp launch, both upper/lower spatial halves. Make every warp’s expected output visibly different.
  5. Use values near Half and E4 rounding boundaries to test the premix-publication, post-activation-publication and final-publication locations. Do not validate only with ones.
  6. Use synchronization checking when altering the copy loop; an input stage may be overwritten only after every participating consumer has finished.

These are concrete tests to implement when rebuilding the kernel, not claims that this documentation run executed GPU comparisons. First establish layout and numerical equivalence; then measure latency with the same weights, geometry, precision and stream behavior. A source-level eliminated allocation establishes avoided traffic, but it does not quantify the speedup or prove absence of register spills.

A global allocation is device memory addressed by a pointer; loads can be served by hardware-managed L2 and, depending on the instruction, L1. A cache hit is not another program-visible tensor and the source does not guarantee cache residency. __ldca permits caching at all levels; __ldcg and PTX .cg select global-level caching that bypasses L1. An eviction or no_allocate hint is a performance policy, not a publication barrier.

Shared memory is an explicitly indexed block-local allocation. Another warp may read a producer's values only after the required block barrier or completed asynchronous-copy protocol. A warp shuffle exchanges register values among its active lanes; it does not address shared memory. Arrays named r_… express per-thread values, but only compiler output establishes whether they stay in physical registers or spill to local memory. Tensor-core accumulator fragments are also register operands. These kernels use mma.sync, not TMEM.

74						CopyBulk(s_Storage, s_CopyOffset, g_Source, 512, s_BarrierOffset);
75						BarrierExpect(s_Storage, s_BarrierOffset, 512);
76					}
77				}
78				else
79					*reinterpret_cast<uint4*>(s_Storage + s_CopyOffset + TileCoordinates.Lane * 16) =
80						make_uint4(0, 0, 0, 0);
81			}
82		}
83	};
84
85	// Wait for the selected shared-memory stage before its fragments are consumed.
86	const auto WaitInput = [&](int ReductionTile)
87	{
88		const int s_BarrierOffset = 8192 + (ReductionTile % 2) * 8;
89		{
90		}
91
92		ArriveAndWait(s_Storage, s_BarrierOffset);
93	};
94
95	// Prime the weight registers and input pipeline before entering the reduction loop.
96	LoadWeights(0);
97	IssueInput(0);
98	WaitInput(0);
99	FMmaAccumulatorTile<Profile::SpatialFragments, 4> r_Projected{};
100
101	// Two-stage pipeline: issue the next input before current MMA work, then
102	// fetch its weights and wait. The final iteration neither refills nor waits.
103	#pragma unroll 1
104	for (int ReductionTile = 0; ReductionTile < Profile::ReductionTiles; ++ReductionTile)
105	{
106		if (ReductionTile + 1 < Profile::ReductionTiles)
107		{
108			IssueInput(ReductionTile + 1);
109		}
110
111		uint4 r_Input[Profile::SpatialFragments][2];
112		#pragma unroll
113		for (int r_Spatial = 0; r_Spatial < Profile::SpatialFragments; ++r_Spatial)
114			#pragma unroll
115			for (int r_KSubtile = 0; r_KSubtile < 2; ++r_KSubtile)
116				r_Input[r_Spatial][r_KSubtile] = *reinterpret_cast<const uint4*>(
117					s_Storage + (ReductionTile % 2) * 4096 +
118					(bFp8 && !bInputView ? (TileCoordinates.Warp / 4) * 2048 : 0) + r_Spatial * 1024 +
119					r_KSubtile * 512 + TileCoordinates.Lane * 16);
120		AccumulateTile<Profile::Precision>(r_Projected, r_Input, r_Weights);
121		if (ReductionTile + 1 < Profile::ReductionTiles)
122		{
123			LoadWeights(ReductionTile + 1);
124			WaitInput(ReductionTile + 1);
125		}
126	}
127
128	FMmaAccumulatorTile<Profile::SpatialFragments, 4> r_Output{};
129
130	// Grouped MLP keeps each hidden panel in registers through expansion and contraction.
131	const uint64_t g_Expand = Parameters.g_PackedWeights +
132							  (262144 + TileCoordinates.g_ExpertGroup * 16384) * Profile::ElementBytes +
133							  TileCoordinates.Lane * 16;
134	const uint64_t g_Contract = Parameters.g_PackedWeights +
135								(393216 + TileCoordinates.g_ExpertGroup * 16384) * Profile::ElementBytes +
136								TileCoordinates.Lane * 16;
137
138	// Hidden activations stay in registers. Processing 32 hidden channels at a
139	// time avoids materializing the 256-channel intermediate in shared/global memory.
140	#pragma unroll 1
141	for (int HiddenTileIndex = 0; HiddenTileIndex < 8; ++HiddenTileIndex)
142	{
143		FMmaAccumulatorTile<Profile::SpatialFragments, 2> r_Hidden{};
144		#pragma unroll
145		for (int r_KPair = 0; r_KPair < 2; ++r_KPair)
146		{
147			{
148				uint4 r_Input[Profile::SpatialFragments][2], r_Weights[2][2];
149				#pragma unroll
150				for (int r_KSubtile = 0; r_KSubtile < 2; ++r_KSubtile)
151				{
152					#pragma unroll
153					for (int r_Spatial = 0; r_Spatial < Profile::SpatialFragments; ++r_Spatial)
154						r_Input[r_Spatial][r_KSubtile] = LoadWindowFfnInputFragment<false>(
155							r_Projected, r_Spatial, r_KPair * 2 + r_KSubtile);
156					#pragma unroll
157					for (int r_NTile = 0; r_NTile < 2; ++r_NTile)
158						r_Weights[r_KSubtile][r_NTile] = __ldca(reinterpret_cast<const uint4*>(
159							g_Expand + HiddenTileIndex * 1024 + (r_KPair * 2 + r_KSubtile) * 8192 +
160							r_NTile * 512));
161				}
162				AccumulateTile<Profile::Precision>(r_Hidden, r_Input, r_Weights);
163			}
164		}
165
166		#pragma unroll
167		for (int r_Spatial = 0; r_Spatial < Profile::SpatialFragments; ++r_Spatial)
168			#pragma unroll
169			for (int r_NTile = 0; r_NTile < 2; ++r_NTile)
170				#pragma unroll
171				for (int r_Word = 0; r_Word < 4; ++r_Word)
172					r_Hidden.r_AccumulatorWords[r_Spatial][r_NTile][r_Word] =
173						FfnActivation(r_Hidden.r_AccumulatorWords[r_Spatial][r_NTile][r_Word]);
174
175		{
176			uint4 r_Input[Profile::SpatialFragments][2], r_Weights[2][4];
177			#pragma unroll
178			for (int r_KSubtile = 0; r_KSubtile < 2; ++r_KSubtile)
179			{
180				#pragma unroll
181				for (int r_Spatial = 0; r_Spatial < Profile::SpatialFragments; ++r_Spatial)
182					r_Input[r_Spatial][r_KSubtile] =
183						LoadWindowFfnInputFragment<false>(r_Hidden, r_Spatial, r_KSubtile);
184				#pragma unroll
185				for (int r_NTile = 0; r_NTile < 4; ++r_NTile)
186					r_Weights[r_KSubtile][r_NTile] = __ldca(reinterpret_cast<const uint4*>(
187						g_Contract + HiddenTileIndex * 4096 + r_KSubtile * 2048 + r_NTile * 512));
188			}
189			AccumulateTile<Profile::Precision>(r_Output, r_Input, r_Weights);
190		}
191	}
192
193	// Publish contracted expert fragments only for valid spatial tiles.
194	#pragma unroll
195	for (int r_Spatial = 0; r_Spatial < Profile::SpatialFragments; ++r_Spatial)
196	{
197		const int g_Y =
198			TileCoordinates.g_TileY + (bFp8 && !bInputView ? TileCoordinates.Warp / 4 : r_Spatial / 2);
199		const int g_X = TileCoordinates.g_TileX + (bFp8 && !bInputView ? r_Spatial : r_Spatial % 2);
200		if (g_Y >= TileCoordinates.g_TilesHigh || g_X >= TileCoordinates.g_TilesWide)
201			continue;
202		const uint64_t g_OutputTileBase =
203			Parameters.g_Output +
204			uint64_t(g_Y * TileCoordinates.g_TilesWide + g_X) * Profile::SpatialTileBytes +
205			TileCoordinates.g_ExpertGroup * 1024 * Profile::ElementBytes + TileCoordinates.Lane * 16;
206		#pragma unroll
207		for (int r_NTile = 0; r_NTile < (bFp8 ? 2 : 4); ++r_NTile)
208			StoreNoAllocate(g_OutputTileBase + r_NTile * 512,
209							LoadWindowFfnInputFragment<bFp8>(r_Output, r_Spatial, r_NTile));
210	}
211#endif
212}

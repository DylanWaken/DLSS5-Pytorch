01. The whole problem

The model asks for Y[p,n]=publish(Σk=0…511 X[p,k]W[k,n]) for 2,160 supplied low-resolution tokens and n=0…1023. X is [36,60,512], W is [512,1024], and Y is [36,60,1024]. Pooling already happened in record 30: 34 valid pooled rows occupy a 36-row field. This operation changes channel count only; it has no residual, bias, activation or spatial reduction.

The network architecture guide places this operation in the full encoder–bottleneck–decoder. This lesson defines the operation and its physical implementation locally so it can be read independently.

A scalar baseline gives one output dot product to one thread. It is an excellent connectivity oracle, but the same 512 input channels are needed for 1,024 outputs and the same weight column for many tokens. Our first optimization question is how much of that reuse to expose to one CTA without retaining an excessively wide output. We will keep the pointwise equation fixed while choosing spatial tiles, channel bands and K stages. channel_projection_c512_to_c1024_fp16 is the resulting candidate, which connects the encoder to the C1024 bottleneck.

02. One CTA: its concrete subproblem

A native M16 tile with 64 outputs is a compact first tensor-core job. There are 9×15=135 native spatial tiles and sixteen output bands, giving 2,160 CTAs. Enlarging the job to 64 positions and 256 outputs lets four bands share an A stage; ceil(36/8)×ceil(60/8)×4 = 160 CTAs. Going to all 1,024 outputs reduces this to 40 CTAs, but with the same eight warps the accumulator payload rises from 32 to 128 Half2 words per lane. The middle candidate limits retained output while exposing reuse; the larger candidate needs its own occupancy and timing experiment.

Encode the chosen job as grid=(32,5,1), block=(32,8). Eight spatial columns and four channel slabs share grid X: slab=blockIdx.x/8, tileX=2·(blockIdx.x%8). For blockIdx.x=19 this gives slab 2 and native tile column 6. Warp 5 then owns channels 576…639 in the lower native-tile row. These are derived launch coordinates, with measured confirmation reserved for section 6. Each CTA owns all K512; out-of-field native tiles are zero-filled and their stores clipped.

03. Warp and thread ownership

The 64×256 CTA result contains 16,384 Half scalars, or 8,192 accumulator words. Four warps would average 64 words per lane; eight warps need 32. Choose eight and split both axes: channelBase=256·slab+64·(warp&3) and native tileY=2·blockIdx.y+(warp>>2). Each warp then owns two horizontal M16 tiles and four N16 output panels, a 32×64 result. This halves per-lane output state compared with four warps while each A fragment still serves four N16 panels.

Producer work must cover the whole A stage, not follow that output assignment. Let warp&1 choose one of two K stripes, (warp>>1)&1 choose the left/right tile, and warp>>2 choose the top/bottom tile. Eight producers then write eight disjoint 512-byte stripes. Consumer warp 2 reads stripes also used by the other output bands. Prove producer coverage and consumer interpretation separately; matching warp numbers is not a correctness requirement.

One warp's result has 2 M16 spatial fragments and 4 N16 channel panels. For lane l, let g=l/4 and q=l%4, using integer division. In one N16 panel, word 0 holds row g at columns 2q and 2q+1; word 1 holds row g+8 at the same pair; words 2/3 add eight columns. Coordinates in this lesson are (y,x). Native matrix row g maps to physical x=g%4,y=g/4; row g+8 adds two to y. A lane therefore owns pieces of two tokens. It never owns a complete dot product independently.

mma.sync.aligned.m16n8k16.row.col.f16.f16.f16.f16 is a converged 32-lane operation. Four A words and two B words per lane collectively describe its operands; two Half2 accumulator words per lane describe the N8 result. Two N8 instructions build an N16 panel. Input fragments are reused across output panels; a weight bundle is reused across the warp's spatial fragments. The diagram maps Half C/D words in both modes. Half accumulator words can be forwarded to the next A role only where the source helper establishes that layout contract.

04. Resource budget

Size A before choosing a pipeline: 64 positions ×K32×2 bytes = 4,096 bytes per slot. A one-slot correctness version costs 4,104 static bytes including its barrier; two slots cost 8,208 and the three-slot candidate costs 12,312. Three slots provide a larger lookahead window, but they do not prove three copies overlap compute.

For contrast, the unique B panel for this CTA is 256 outputs ×K32×2 = 16,384 bytes per K step. Staging B alongside A in three slots would add 49,152 shared bytes. The current candidate instead keeps the two-K/four-N B bundle in each warp's registers and lets hardware caches service repeated global requests. This predicts lower explicit shared usage, not a particular cache hit rate. Compile and measure the resource limit after the logical arrays below are correct.

Treat this as a resource prediction before compilation. A uint4 needs four 32-bit words if scalarized into registers; one accumulator word holds two Half scalars. These declared arrays describe logical state, not an additive count of physical registers: lifetimes can overlap, compiler temporaries add state, and an array may spill into local memory. A register ceiling constrains the compiler; it does not reserve exactly that many registers.

For a candidate with compiled count R and T threads, begin with R·T register words, round using the device allocation rules, then compare the register, shared-memory, thread and block residency limits. Do not infer occupancy from static shared bytes alone. The recorded launch, physical allocation, local-memory traffic and instruction evidence appear later in section 6, after we have predictions to test.

The three slots hold only input A. Output and B remain per-warp registers. A larger stage count might reduce exposed copy latency but consumes more shared space; the source alone does not prove that a larger ring would improve residency or time.

05. Execution and scheduling

Implement one synchronous A slot and the complete K512 reduction first. After every warp produces the right answer, extend to three slots: prime the ring, consume the current panel, and recycle a slot only after all consumers have passed the next-stage wait. This ordering deliberately differs from issuing a next-slot copy at the beginning of a two-slot loop. The new invariant is that a refill targets an already retired slot.

Keep C zero-seeded because the mathematical contract has no residual. Load B through its C1024 column stride and reuse each bundle across the two M16 fragments before discarding it. The source and flowchart below are the implementation checkpoint; final capture evidence can verify the predicted load/MMA/store structure and reveal the stalls that remain. Establishing a staging speedup requires a matched timing comparison against the one-slot version.

Now implement the candidate schedule: Load W0, issue input 0 through 2, and wait for input 0. Iteration t loads its A vectors, performs all MMA work, loads W[t+1], and waits for input[t+1]. Only after that full-CTA arrival does it issue input[t+3] into the retired slot. There are 16 K iterations. The invariant is that a consumer reads a completed current slot and no producer overwrites a slot with unfinished readers. Derive the final-iteration predicates from that invariant: no next input means no next copy or wait. First test one iteration and a final partial ring before running the full reduction.

Keep the outer K loop rolled, then unroll the fixed fragment loops so constant M/N/K-subtile indices can become register selections. This predicts a smaller instruction body than unrolling all 16 reduction steps while retaining direct fragment access; confirm the compiled local-memory and instruction evidence later. The arrows show legal dependencies, not measured overlap. Likewise, __ldca requests cache-all global weight loads and StoreNoAllocate requests a 128-bit store without L1 allocation; cache residency and throughput remain measurements.

CopyBulk selects its implementation by target architecture. On SM90+ an elected lane issues the ordinary-address bulk asynchronous transfer and the mbarrier expects its byte count. On SM80/SM89 each warp lane copies sixteen bytes with cp.async.cg.shared.global; the helper attaches completion to the barrier, and transaction-byte expectation is unused. This is not a tensor-map descriptor or a software L2 allocation. The full CTA initializes and arrives at the barriers, including lanes that zero-fill invalid tiles.

Milestone 6.1 — Stage A with a layout-only diagnostic

Implement an ordinary copy and CTA barrier before adding the ring. Dump the first and second K panels for a tagged native input and compare them to an independent decoder. Each input word must appear exactly once in the staged panel, even though four output bands later read it. Verify the bottom/right synthetic tiles are zero; a tagged boundary pattern falsifies a mistaken singleton or crop rule without involving MMA.

Input native tile q has 16,384 bytes. For t=1, first K subtile, q=0, source is (q·512+t·32)·16·2=1024. Producer warp 0 copies the 512-byte stripe into slot 1 at shared+4096. Consumer warp 2 is the third output band, but reads this same spatial half and K stripe. Its lane 0 shared uint4 begins at 4096; word banks are 0,1,2,3. The next K stripe adds 512, the next spatial tile adds 1024 and the lower spatial half adds 2048.

Milestone 6.2 — Derive B addressing from the wider output dimension

Use W=[I I] as the first matrix test so each output half must reproduce X. Then permute columns across the 512 boundary to expose a mistakenly reused C512 weight stride. The invariant is that advancing one instruction-K panel preserves the output column while changing the reduction channels. Derive that byte stride from the complete packed matrix before inserting the cached vector loads.

Weight vector address is W+t·32·1024·2+outputBase·32+16·l+kSubtile·32768+N16·512. Our t=1,outputBase=128,l=0,K0,N0 gives 69,632 bytes. Milestone 6.4 — Widen the destination layout and validate the pipeline

Keep the store simple until the independently decoded output matches the scalar oracle. Test both channel halves and each CTA slab, including blockIdx.x=19; a writer using X's tile stride corrupts the next token tile even if the first tile looks correct. After this succeeds, substitute the three-slot schedule and require identical output. The invariant remains a unique token/channel owner regardless of copy timing.

Y's native tile is 16×1024×2=32,768 bytes, twice the X tile size. The lane-vector address is Y+(q·1024+outputBase)·16·2+16·l; our q=0,outputBase=128,l=0 gives 4,096. The writer directly stores the four Half words of each N16 result, yielding four vectors per lane. StoreNoAllocate uses an aligned 16-byte global store. Validate the completed candidate against its predictions

The milestones above are a reconstruction plan, not a report that alternative kernels were implemented or benchmarked. Compile the final candidate and check the predicted instructions, physical resources and memory traffic against the recorded capture. A mismatch is a reason to revisit an assumption: local loads may reveal a spilled fragment array; an unexpected lane permutation may reveal a layout conversion; different Half instructions may reveal contraction. A final-candidate capture can identify remaining bottlenecks, but attributing a speedup to a design choice requires a matched baseline experiment.

The explicitly managed storage is global allocations, shared stages and per-lane registers. L2 and L1 are hardware-managed caches on relevant accesses. Shared A vectors are loaded with ordinary aligned uint4 dereferences; there is no ldmatrix instruction or extra XOR shared-memory swizzle in these entry bodies. Bank indexing for a 32-bit word is (byteOffset/4)%32. A 16-byte lane vector spans four banks. Repeated bank indices across a whole warp do not alone prove serialization: the actual instruction's transaction decomposition and broadcast behavior matter.

The working storage format on this page is IEEE Half / FP16. Tensor-core accumulation, residual products, the recovered activation and the reduction trees discussed here use packed Half words. A uint32_t is a bit container for two Half values, not an integer approximation to their sum. HalfMul, HalfAdd and HalfFma express packed-Half source operations; replacing them with FP32 expressions and a final cast changes that arithmetic. However, ordinary CUDA Half intrinsics can be contracted by the compiler. Helper names alone do not prove a separate rounding boundary: the source-correlated SASS below establishes the actual compiled operations. The operand and accumulator use the same element type, but their lane-word arrangements still differ by matrix role. Equal dtype does not make an arbitrary row-major uint4 a valid MMA fragment.

Start with a high-precision scalar oracle to validate which input contributes to which output. Once the connectivity is correct, introduce a second oracle that follows the source’s K chunk order and publication points. A scalar FP32 sum is not a bitwise reference for Half MMA; it is a tool for catching transposes, wrong groups and wrong spatial coordinates. Keep these two correctness goals separate throughout reconstruction.

Reconstruct and check in dependency order

  1. Use a matrix that copies X to both output halves; verify all 1024 channels and no spatial displacement.
  2. Check the CTA-X quotient/remainder example at blockIdx.x=19 and the selected token trace with tagged values.
  3. Exercise the 32 KiB instruction-K weight stride, both K subtiles and every output N16 panel.
  4. Test [36,60] bottom/right partial CTA regions and native singleton read policy; no synthetic output address may be stored.

These are reconstruction checks, not a claim that this documentation build ran them. Match layouts and numerical order first; use the attached capture and its exact launch conditions when evaluating performance.

A global allocation is device memory addressed by a pointer; loads can be served by hardware-managed L2 and, depending on the instruction, L1. A cache hit is not another program-visible tensor and the source does not guarantee cache residency. __ldca permits caching at all levels; __ldcg and PTX .cg select global-level caching that bypasses L1. An eviction or no_allocate hint is a performance policy, not a publication barrier.

Shared memory is an explicitly indexed block-local allocation. Another warp may read a producer's values only after the required block barrier or completed asynchronous-copy protocol. A warp shuffle exchanges register values among its active lanes; it does not address shared memory. Arrays named r_… express per-thread values, but only compiler output establishes whether they stay in physical registers or spill to local memory. Tensor-core accumulator fragments are also register operands. These kernels use mma.sync, not TMEM.

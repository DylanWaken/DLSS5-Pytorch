The model piece: one residual FFN → attention block

The ordinary block is the recurring unit in this encoder–decoder. For one spatial token, the FFN mixes channels; attention then mixes positions. The block computes Zraw = FFN(X) + ffn_scale ⊙ R, publishes Z, projects it to Q/K/V, and finishes with Yraw = projection(attend(Q,K,V)) + attn_scale ⊙ Rattn. The first residual normally reads X; the second reads Zraw at C32 and published Z at larger widths. The architecture guide explains these choices before any GPU layout is introduced.

Here “token” means one spatial position and its channel vector. A head is a 32-channel slice used by attention. An 8×8 window contains 64 tokens; its four physical 4×4 tiles each contain 16 tokens. A CTA is one CUDA thread block; each warp contains 32 lanes. A lane owns fragments of several tokens, so one lane is not one token.

1. Separate logical tensors from physical storage

Start with a tensor's meaning, shape and precision. Then ask whether it exists as a global allocation, a shared-memory tile, or only as distributed register fragments. A drawn score matrix is an algorithmic object; it does not prove a global allocation. C32 can keep the whole ordinary block inside a warp's register state, C512 exposes intermediate global buffers between four launches, and C1024 streams key tiles without allocating the complete score matrix.

Registers and shared memory are explicitly addressed or represented in the source. L1/L2 are caches along memory paths, not software tensor buffers. The wrappers use __ldca for some reusable data, __ldcg for streaming data, and L1::no_allocate for selected output/counter traffic. These are cache controls or hints, not synchronization. A register array can spill into CUDA local memory if compilation requires it; the prefix r_ describes intended arithmetic payload, not a proof of zero spill traffic. Inspect compiled resource reports and profiling before making that claim.

These kernels execute mma.sync with register operands. Their Blackwell measurement target is SM120; do not substitute SM100 tcgen05, TMEM or warp-group MMA diagrams. Some copy intrinsics select newer operations at SM90+, while Ampere/Ada use a different copy implementation. The instruction wrappers show exactly where this choice is made.

2. Decode the warp's accumulator ownership

For an m16n8 operation, 32 lanes collectively produce 16×8 = 128 results. The four Half values held by each lane are stored in two 32-bit words. Let g = lane // 4 and q = lane % 4. The low/high halves of word 0 represent row g and columns 2q, 2q+1. Word 1 represents row g+8 at those same columns. When the output spans more than eight channels, the kernel repeats this fragment for column tiles.

For a C32 result, a lane holds four column tiles × two Half2 words = 16 Half results for each physical tile. A full window has four such tiles. To read any later diagram, first identify its row axis, channel-column tile, K reduction panel and lane pair.

3. Work one physical C32 input address by hand

In the ordinary C32 packed path, the field is tiled into 4×4 blocks. Let tile = tile_y × (Width/4) + tile_x. The global byte offset of one lane's 16-byte load is tile × TileBytes + chunk × 512 + lane × 16. FP8 stores 16×32 elements in 512 bytes and has one K32 chunk. FP16 stores the same tile in 1024 bytes as two 512-byte K16 chunks. Each chunk has 32 adjacent lane vectors.

For tile 5 and lane 17, the offset is 5×512 + 17×16 = 2832 in FP8. The FP16 chunk-0 offset is 5×1024 + 17×16 = 5392; chunk 1 starts at 5904. These are addresses of four packed u32 words, not BHWC channel addresses. A separate view loader has a different plane-major formula. Copying BHWC bytes into the ordinary packed buffer would give plausible addresses and incorrect tensors.

4. Follow rounding as carefully as addresses

“FP8 kernel” names the working publication/operand format, not every arithmetic instruction. In these bodies the E4M3 operands feed FP16-accumulating MMA. Half2 activation, residual arithmetic, reductions and some scratch buffers remain FP16. Some normalization steps widen to FP32 for approximate reciprocal or reciprocal square root, then round back to Half. Both precision paths therefore have explicitly ordered conversion boundaries.

Weight matrices are packed in reduction panels. A K32 FP8 panel and K16 FP16 panel each use 32 bytes per output column, which helps preserve 16-byte lane loads across precisions. But Half scales, biases, padding and matrix boundaries are not uniformly doubled. The source profiles are the contract. Likewise the model's activation is a recovered clamped polynomial and its attention exponential is a recovered surrogate. Replacing them with framework SiLU or stable softmax changes the computation.

5. Read an asynchronous-copy pipeline as a storage lifetime

Large tiled kernels stage operands in shared memory. Distinguish copy completion from consumer completion: before reading a stage, its copy must have completed; before overwriting the stage, every consumer of the old tile must have finished. An mbarrier tracks the copy/arrival phase. CTA barriers or the explicit schedule coordinate stage reuse. A barrier variable by itself does not prove either invariant—trace the issuer, expected transaction count, arrivals, wait and next write.

264	// increment is essential: ordinary CTA arrivals alone cannot track them.
265	asm volatile("cp.async.mbarrier.arrive.shared.b64 [%0];"

For a 512-byte transfer below SM90, lane l copies 16 bytes beginning at 16l. For 1024 bytes it also copies at 16l+512. All participating producers attach their own copies to the mbarrier. On SM90+, one elected lane issues a bulk transfer and the pipeline accounts for expected bytes. The fallback is cooperative parallel copying, not 32 copies serialized through one lane. Study the precise prefill/refill placement in the C512 and C1024 chapters next.

6. A repeatable method for reading every kernel

  1. Find the model record and operation in the architecture; write its logical shapes and precision boundaries.
  2. Find the logical entry in the source atlas; templates can give several public configurations one body.
  3. Read the launch grid and map block, warp and lane axes to tokens, heads, output columns and reduction splits.
  4. Annotate every address with its unit: element, Half pair, u32 word, uint4 vector or byte.
  5. Trace one producer and one consumer through every register/shared/global publication.
  6. Only then explain why fusion, reuse, tiling, conversion packing or launch ordering can reduce work. Keep measured results separate from the intended mechanism.

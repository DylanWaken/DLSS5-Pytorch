01. Define this kernel’s exact attention problem

global_attention_chained_c1024_fp16 performs global attention inside C1024 bottleneck records 31–38. There are 32 heads of 32 channels. For one head h, the logical inputs are Q[T,32], K[T,32], V[T,32]. Q and K have already been independently normalized across their 32 channels by the upstream QKV kernel, and Q already includes √32 and the learned head scale. This kernel does not repeat those operations. It computes one updated 32-channel vector for every query, then publishes all heads into an output logically [T,1024]. The later output projection and scaled residual are outside this entry.

Every query reads all T bottleneck positions, with no window restriction or relative-position bias. For the architecture’s 4K example, H=36,W=60,T=2160. The traversal rounds to P=ceil(T/64)·64=2176 keys. Its extra K/V rows are zero. Define s[q,k]=Σd Q[q,d]K[k,d]; the recovered Half surrogate produces E(s). The kernel returns Publish(Σₖ Publish(E(s[q,k]))V[k,:] / max(Σₖ E(s[q,k])−(P−T)E(0), ε)). Publication uses Half; numerator and denominator reduction are Half. This formula deliberately shows a publication inside the numerator.

02. Start with a scalar algorithm, including the padding correction

This baseline is intentionally explicit about artificial keys. Zero K does not give zero exponential, so simply summing over P would dilute valid attention. Zero V does eliminate their numerator contribution. The mathematical baseline also separates two goals: reproducing which values are used, and reproducing the deployed rounding sequence. A scalar floating loop generally sums in a different order from MMA fragments and warp shuffles. Use it first for dependency/layout tests, then add the exact Half chunk/reduction boundaries for stricter numerical comparison.

A naive implementation can allocate scores[T,P], exponentials[T,P], and perhaps normalized probabilities[T,P], then launch separate matrix multiplication, transform, normalization and value-product kernels. At T=2160, one head’s score matrix has 4,700,160 entries. This source retains only a 64-key tile per query warp. That removes quadratic storage and intermediate traffic, while preserving the quadratic count of query–key interactions. Do not confuse streamed storage with a linear-time attention approximation.

One instruction computes a 16-token × 8-output-channel tile with a reduction of 16 channels. All 32 lanes participate in the same matrix operation. Each lane supplies four 32-bit A words, two 32-bit B words, and two 32-bit C words. Each C word contains two Half accumulators, so a lane owns four output elements. A source loop over output groups or reduction panels repeats this operation; it does not launch a new warp.

The exact instruction on this path is mma.sync.aligned.m16n8k16.row.col.f16.f16.f16.f16. Both the accumulator input and output are Half. Do not replace its numerical contract with FP32 accumulation when constructing an exact oracle. For the FP8 path, packing to E4M3 is a distinct rounding step; for the FP16 path a packed word simply holds two Half values.

Let lane L run from 0 to 31, g = L // 4 and q = L % 4. The matrix coordinates below describe instruction operands after any kernel-specific loads and shuffles. Storage layouts are designed to supply these coordinates cheaply.

03. Derive a useful query/key tile from MMA fragments

A QKᵀ MMA computes 16 query rows by 8 key columns, reducing 16 head channels. Since the head width is 32, one score fragment needs 2 native K chunk(s). Four M16 query tiles give a warp 64 queries; eight N8 key tiles give it 64 keys. Its score state is Probability[4].Pair[8][2],64 packed Half2 words per lane. Four warps share one head and K/V tile, so the CTA covers 256 queries×64 keys per iteration.

Choose head=blockIdx.x, queryBlock256=blockIdx.y, lane=threadIdx.x and warp=threadIdx.y. The warp’s first query is 256·queryBlock+64·warp. For its M16 tile m, row-half r and lane L, the query index is 256·queryBlock+64·warp+16m+floor(L/4)+8r. The score fragment’s key pair in N8 tile c is 64·keyTile+8c+2·(L mod4)+{0,1}. Those equations explain exactly which query–key interactions one packed score word represents.

The output numerator has 32 columns, so it requires four N8 fragments for each M16 query tile: Output[4].Pair[4][2],32 words per lane. The denominator uses just one Half2 per lane, representing warp query rows L and L+32 after a register-ownership transpose. Q uses four M16×32 fragments, with 2 512-byte native chunks per M16, or 32 register words per lane. These three objects survive all key iterations. Current scores and K/V register fragments have shorter lifetimes and can be replaced after each tile contributes.

04. Derive Q, K, V and output physical addresses

Inputs are already in their consumer layouts. A16-token group contains all 1024 channels across 32 heads. Let E=2 bytes per working element. A Q lane vector for group g/head h/chunk c is Q+g·16384·E+h·512·E+c·512+L·16. This entry has 2 chunks. Its producer placed Q directly into the MMA A layout, so the consumer uses an aligned uint4 load without transposing. K uses the same group/head byte strides but its producer swapped the middle words, making it ready for the B operand of QKᵀ.

For key tile j, copySlot=warp+4·Copy with Copy=0…1. The K group is 4j+floor(copySlot/2) and its chunk is copySlot mod2. The global base follows K+group·16384·E+h·512·E+chunk·512. Shared destination is (j mod2)·4096+copySlot·512. Each copy writes 512 bytes, covering one native M16×K panel. K groups beyond the kernel’s stored-group count are synthesized as zeros.

V has been register-transposed upstream for E×V. FP16 retains M16 token groups; valueGroup equals the K group. Its global base is V+valueGroup·32768+h·1024+(copySlot mod2)·512. Its shared destination adds the V region offset 8192 to the matching stage/copy offset. These maps are not dense [T,32] array strides, and V cannot be replaced by a byte-identical copy of the Q layout.

The worked Q address identifies a 16-byte operand vector, not a scalar channel. Its output-fragment owner query 355 has local row 35 within the warp. During the final normalization it fetches the high Half of lane 3’s denominator pair. For example, output column tile 0 at lane 13 holds channels 2/3 of that query; column tile 1 holds10/11. The final output uses Q’s group/head/chunk/lane layout, so the next projection can consume it as an ordinary packed token tensor.

Small-profile branches are explicit and should not be extrapolated from the large-tile diagrams: FP16 remaps Q/K/V group reads to zero when T is between 1 and 16. The ordinary multi-group examples above do not take that path. Storage padding is 16 rows in the kernel’s group bound; the host can allocate a larger common 32-row-rounded buffer. A larger allocation is not permission for unpredicated extra loads.

05. Construct a synchronous streamed attention kernel

This scaffold is a useful intermediate implementation because it isolates the attention algebra from asynchronous lifetime bugs. Keep Q and N/D registers across iterations, while reusing the same shared bytes for the next 64-key tile. The next optimization is to give those bytes two alternating slots and permit transfer of the future tile while current arithmetic runs. More stages would consume extra shared memory and require a different schedule; the recovered entry uses exactly two K/V stages.

06. Build the two-stage K/V ring and predecessor protocol

The shared allocation is K0,K1,V0,V1, followed by two 8-byte barriers. Each K or V slot is 4096 bytes, so total data storage is 16384 bytes. One barrier belongs to the matched K/V slot pair: all its key and value copies register completion there. A stage is ready only when both operands and all expected arrivals have completed. The source initializes both barriers for 128 threads, synchronizes, then waits for the predecessor token groups containing its Q before loading Q.

Make the copy barrier part of the construction

Allocate 2 shared data slots and one 8-byte mbarrier per slot. Lane 0 of warp 0 initializes each barrier with 128 expected thread arrivals, then the CTA synchronizes before any producer can issue copies. On SM90+, IsCopyProducer elects one lane per participating warp; it issues an ordinary-address cp.async.bulk and registers the transferred byte count. On SM80/89, every lane issues 16-byte cp.async.cg stripes and attaches its own copies with cp.async.mbarrier.arrive. A 512-byte transfer needs one stripe per lane, a 1024-byte transfer needs two.

ArriveAndWait makes every thread arrive, obtains the current phase token, and polls until that exact phase completes. Reusing the same barrier address next iteration requires a new token; readiness from a previous cycle is insufficient. Completion also accounts for attached asynchronous transfers. Ordinary thread arrival alone cannot establish copy completion. The schedule must separately establish that the previous tile’s readers have finished before a slot is overwritten. No tensor-map descriptor, TMEM allocation, warp-group MMA or shared-to-register ldmatrix operation is used in this path: its shared vectors already have the correct MMA fragment order.

Removing the predecessor routine’s unconditional CTA barrier because its counter is “already ready” would also remove a point used by this schedule to coordinate readers.

07. Convert scores to the exact recovered exponent surrogate

For each of four query tiles and eight N8 key-column tiles, the kernel initializes two Half2 score words and accumulates 2 MMA head-channel chunk(s). It then applies a packed Half affine transform with slope 0.08953857421875 and intercept 1.708984375. Clamp the result to [1.439453125,1.9775390625]. Finally reinterpret the two Half encodings together: Ebits=(clampedBits<<4)+0x3ffc4000 with 32-bit wraparound.

The final expression is an integer encoding transform, not multiplication by 16 in floating point. It acts on the whole packed word; carries between low/high Half fields are accounted for by the recovered offset. Independently applying a guessed scalar shift to the two components changes the high component. Likewise exp, exp2, conventional stable softmax and row-maximum subtraction are different numerical programs. The clamp bounds the surrogate’s range so this source can accumulate unnormalized weights without an online rescaling scheme.

08. Derive the denominator ownership transpose

A score tile’s lane L initially owns only part of a query row: two key columns in each N8 tile, for two row halves. Four neighboring lanes jointly cover all eight key columns of an N8 fragment. To form 64-key row sums, first add the eight fragment pairs in the recorded local tree: add pair 0+1 and 2+3, add those results, then add4+5, then 6+7. Each operation is HalfAdd on packed components. The code performs this for four local row fragments at a time.

Now redistribute those partials so one lane can own a complete query sum. It first permutes the four registers with XOR of lane mod4. The source lane is ((lane&7)<<2)+(lane>>3). Four shuffles read from that source XOR the register index, and a second register permutation uses lane>>3. Adding the resulting registers 0,1,2,3 in order restores the required channel-lane summation sequence. Adding low and high Half components completes the scalar query sum. This is a transpose of who owns partial sums, not a materialized shared-memory matrix transpose.

The procedure runs for two 32-query halves, then joins their scalar results into one Half2. Consequently lane L owns D for query L in its low Half and query L+32 in its high Half. That pair is Half-added to the running denominator after every 64-key tile. Preserving the order matters: a generic butterfly across all keys or an FP32 accumulator can produce different rounding. Fixed array indices inside the register permutation also avoid requiring dynamically indexed storage for the tiny quartet; confirm actual register/local-memory behavior from compilation rather than assuming the source array never spills.

09. Reuse the exponent tile immediately as an MMA operand

After contributing to D, the same unnormalized E tile becomes A for E×V. PublishWindowChunk selects the existing Half words into the four-register A fragment. Both branches retain Half E, but the denominator uses scalar Half-add reductions while the numerator uses Tensor Core MMA. Equivalent real arithmetic does not imply identical finite-precision summation.

With uniform scores, every key begins with the same Half E. Even then, use the chunked Half denominator and MMA numerator as the exact oracle: dividing an FP32 sum of V by the token count discards the source’s accumulation and reciprocal rounding boundaries.

The key reduction has 64 elements, so the E×V loop needs 4 chunks of K16. For each query M16 tile, two V column groups supply four N8 result fragments, covering 32 output channels. The V vector’s x/y words form the lower B fragment and z/w the upper. Every MMA accumulates directly into the persistent Half N tile. E is not divided into normalized probabilities first; that would move the rounding point and require repeated denominator work across chunks.

Once this contribution finishes, the current E, K and V registers are dead. They can be reused for the next tile, while Q/N/D remain live. This is the central lifetime decision behind the kernel’s storage savings. The global inputs Q/K/V still exist and are reread by other query CTAs, so the source does not eliminate all global traffic or guarantee that all repeated data stays in cache.

10. Correct the artificial-key denominator without masking model tokens

Let S=ceil(T/16)·16 be the kernel’s stored-group bound. The host allocation may round to 32 even for Half. P=ceil(T/64)·64 is a different quantity used by the key traversal. At T=2160, S=2160 while P=2176; the final missing M16 group is staged as zeros. Rows between T and S must have zero K/V from the producer’s padding contract; groups beyond S are zero-filled by this kernel. These are separate mechanisms serving the same logical traversal padding.

At score zero, the Half affine result is 0x3ed6. The scalar correction path computes ((0x3ed6<<4)+0x4000) mod65536=0x2d60, which represents 0.083984375. With 16 artificial keys, that adds1.34375 to the uncorrected denominator. The implementation converts E(0) and the padding count to FP32, multiplies with FTZ, rounds the correction back to Half, and applies one Half subtraction. It does not subtract one value per padded key with a different sequence of Half roundings.

The correction applies to P−T only. Network spatial padding already included in H×W is part of the model’s token field and remains in attention. After correction, the kernel applies the same Half epsilon floor0x0410, then RcpHalf2: each component widens for an approximate reciprocal and rounds back to Half. This avoids division by zero for a small or zero corrected denominator under the specified rule.

13. Validate model behavior, numerical boundaries and pipeline safety

  1. Zero score: set Q or K to zero. Verify the exact surrogate produces 0.083984375, including both packed Half lanes. The denominator correction must remove only P−T contributions, and the numerator must use Half E.
  2. Key/value identity: give V distinct representable tags by token and channel. Decode using the transposed V map; changing one key’s V should affect all query rows according to that key’s weight, with no head cross-talk.
  3. Row ownership: use differing Q rows so denominators vary by query. Trace local rows 3,11,35,43 and verify the shuffle returns the correct inverse to every channel fragment. A constant-input test alone cannot expose a swapped row sum.
  4. Padding: exercise T values on both sides of 16,32,64,128 and 256 boundaries where admitted. Compare the valid-row result with a reference using only T model keys and the same rounding conventions; inspect the explicit correction separately. Invalid stored output rows must be zero and allocation guards unchanged.
  5. Precision: compare QK Half scores, transformed E bits, per 64-key Half sums, numerator fragments, reciprocal pairs and final output separately. This locates a mismatch at the first wrong boundary instead of masking it with final-output tolerance.
  6. Pipeline/counters: compare the one-slot synchronous scaffold with the two-slot entry over more than two key tiles. Verify both K and V have arrived before consumption, and both old readers have retired before refill. Test absent/present completion counters and valid predecessor initialization; do not launch against a producer schedule the host contract does not authorize.
  7. Tiny profiles: isolate the recovered 1–16-token Q/K/V broadcast branch from ordinary multi-group padding tests; the normal large-shape address derivation alone does not cover that branch.

The optimization progression can now be evaluated concretely. Register-resident Q removes repeated query loads within a CTA. Sharing 64-key K/V tiles across 256 queries reduces duplicate input fetches. Short-lived E fragments eliminate quadratic intermediate storage. The row-sum transpose avoids shared reduction storage while preserving add order. The two-slot ring permits asynchronous copies to overlap useful work. The costs are substantial register lifetimes, shared capacity and synchronization, plus repeated K/V reads across different query CTAs. This tutorial reconstructs the mechanisms and their correctness conditions; it does not claim new timings or measured cache residency.

265		const int PaddingKeys = TileCoordinates.g_KeyTiles * 64 - g_Tokens;
266		uint32_t r_CorrectedDenominator = r_Denominator;
267		if (PaddingKeys > 0)
268		{
269			// Padded keys produce the surrogate's nonzero value at score zero.
270			// Remove that mass in FP32 before one Half-rounded subtraction.
271			const uint32_t r_AffineZero =
272				HalfFma(0, CONST_GLOBAL_EXP_SLOPE_HALF2, CONST_GLOBAL_EXP_INTERCEPT_HALF2);
273			const uint32_t r_ClampedZero =
274				HalfMin(HalfMax(r_AffineZero, CONST_GLOBAL_EXP_LOWER_HALF2), CONST_GLOBAL_EXP_UPPER_HALF2);
275			const uint16_t r_ZeroScore =
276				uint16_t((uint16_t(r_ClampedZero) << CONST_GLOBAL_EXP_ENCODING_SHIFT) +
277						 CONST_GLOBAL_EXP_SCALAR_OFFSET);
278			const uint32_t r_Correction =
279				FloatToHalf2(FloatMulFtzBits(HalfToFloatBits(r_ZeroScore), UintToFloatRnBits(PaddingKeys)));
280			r_CorrectedDenominator = HalfSub(r_CorrectedDenominator, r_Correction);
281		}
282
283		r_InverseDenominator = RcpHalf2(HalfMax(r_CorrectedDenominator, CONST_NORMALIZATION_EPSILON_HALF2));
284	}
285
286	// Apply row normalization and publish the accumulated attention in its physical layout.
287	#pragma unroll
288	for (int r_QueryTile = 0; r_QueryTile < 4; ++r_QueryTile)
289	{
290		#pragma unroll
291		for (int r_Half = 0; r_Half < 2; ++r_Half)
292		{
293			const int QueryRow = r_QueryTile * 16 + TileCoordinates.Lane / 4 + r_Half * 8;
294			const uint32_t r_InverseDenominatorPair =
295				ShuffleIdx(r_InverseDenominator, QueryRow % 32, 31, 0xffffffffu);
296			const uint16_t r_InverseDenominatorHalf =
297				uint16_t(r_InverseDenominatorPair >> ((QueryRow / 32) * 16));
298			const uint32_t r_QueryNormalization =
299				JoinHalfwords(r_InverseDenominatorHalf, r_InverseDenominatorHalf);
300			#pragma unroll
301			for (int r_ColumnTile = 0; r_ColumnTile < 4; ++r_ColumnTile)
302				r_Output[r_QueryTile].r_Pair[r_ColumnTile][r_Half] =
303					HalfMul(r_Output[r_QueryTile].r_Pair[r_ColumnTile][r_Half], r_QueryNormalization);
304		}
305
306		const int g_Group = TileCoordinates.g_QueryBlock256 * 16 + TileCoordinates.Warp * 4 + r_QueryTile;
307		if (g_Group < TileCoordinates.g_Groups16)
308			#pragma unroll
309			for (int r_Chunk = 0; r_Chunk < Profile::QueryChunks; ++r_Chunk)
310			{
311				const auto r_OutputFragment = PublishWindowChunk<bFp8>(r_Output[r_QueryTile], r_Chunk);
312				StoreNoAllocate(Parameters.g_Output + uint64_t(g_Group) * 16384 * Profile::ElementBytes +
313									TileCoordinates.g_Head * 512 * Profile::ElementBytes + r_Chunk * 512 +
314									TileCoordinates.Lane * 16,
315								make_uint4(r_OutputFragment.r_Word[0], r_OutputFragment.r_Word[1],
316										   r_OutputFragment.r_Word[2], r_OutputFragment.r_Word[3]));
317			}
318	}
319
320	// Native outputs include a padded last token group. Clear only its invalid
321	// rows after all fragment stores, then release the completion counters.
322	if (g_PaddedTokens != g_Tokens)
323	{
324		__syncthreads();
325		#pragma unroll
326		for (int r_QueryTile = 0; r_QueryTile < 4; ++r_QueryTile)
327			#pragma unroll
328			for (int r_Half = 0; r_Half < 2; ++r_Half)
329			{
330				const int g_Group =
331					TileCoordinates.g_QueryBlock256 * 16 + TileCoordinates.Warp * 4 + r_QueryTile;
332				const int g_Row = g_Group * 16 + TileCoordinates.Lane / 4 + r_Half * 8;
333				if (g_Row >= g_Tokens && g_Row < g_PaddedTokens)
334					#pragma unroll
335					for (int r_Chunk = 0; r_Chunk < Profile::QueryChunks; ++r_Chunk)
336						#pragma unroll
337						for (int r_ColumnTile = 0; r_ColumnTile < 2; ++r_ColumnTile)
338							*reinterpret_cast<uint32_t*>(
339								Parameters.g_Output + uint64_t(g_Group) * 16384 * Profile::ElementBytes +
340								TileCoordinates.g_Head * 512 * Profile::ElementBytes + r_Chunk * 512 +
341								TileCoordinates.Lane * 16 + (r_ColumnTile * 2 + r_Half) * 4) = 0;
342			}
343	}
344
345	__syncthreads();
346	if (Parameters.g_CompletionCounters && TileCoordinates.Lane == 0 && TileCoordinates.Warp == 0)
347		#pragma unroll
348		for (int g_LocalGroup = 0; g_LocalGroup < 2; ++g_LocalGroup)
349		{
350			const int g_Group = TileCoordinates.g_QueryBlock256 * 2 + g_LocalGroup;
351			if (g_Group < TileCoordinates.g_QueryBlocks128)
352				CounterStoreRelease(
353					Parameters.g_CompletionCounters + (g_Group * 32 + TileCoordinates.g_Head) * 4, 0);
354		}
355#endif
356}

1. The whole model problem: dense C1024 FFN expansion

The dense C1024 FFN expansion computes Y = act(X·W) for X[T,1024] and W[1024,4096], then applies the exact recovered clamped Half polynomial. The network architecture guide places this operation inside the decoder bottleneck; the historical FP16 FFN expansion lesson keeps its own revision and evidence.

The input uses the existing globally padded physical tensor layout. One model operation expands every token from 1024 input channels to 4096 output channels. The next sections derive the CTA tile, the warp duties, the resource budget and the execution schedule before following one token through the committed source.

The left-to-right figure separates three scales that are easy to conflate. One scalar contribution is a single product inside a 1024-term dot product. A token owns all 1024 input channels and all 4096 output channels. One CTA owns only a 128×128 tile of one token tile, and one warp owns a 64×64 quadrant of that tile.

Source pin. This chapter quotes the implementation commit c6fb8f912719. The 81 legacy lessons and the two additive Small31 lessons remain owned by their existing pins in the mixed-provenance atlas. Every excerpt is read from that committed tree, never from the working tree.

The physical tensor contract is not row-major

The physical input groups 16 tokens together and stores a K32 slab as 1024 bytes. The global address is g_Input + input_group·16384·element_bytes + ReductionTile·1024; it is not token·1024 + channel. The output similarly groups 16 tokens: a token group contributes 131,072 bytes, an output block contributes 4096 bytes, and the lane/column terms select the exact vector. These equations are the contract the kernel actually reads.

The recovered activation is part of the contract

The activation is evaluated in packed Half arithmetic: t = min(x, upper), then max(t, lower); the gate is fma(t, fma(slope, |t|, intercept), offset) and the final multiply is Half-rounded. The constants are model data in csrc/common/layout/numerical_constants.h, while the composition lives in dlssnr::ops. Reordering or widening any of these steps changes the network result, so the generic library does not decide this policy.

2. The CTA subproblem: one 128×128 output tile

The CTA shape follows from the existing thread block: 128 threads in four warps. A 2×2 warp arrangement covers 128 tokens by 128 output channels, with each warp owning 64 tokens and 64 channels. The reduction then divides into 32 K32 software iterations, each with two K16 MMA subtiles.

A token tile is 128 tokens; 32 output blocks cover the 4096 expanded channels. The accumulator is distributed in registers rather than shared memory; section 4 accounts for the shared bytes and the per-thread register payload separately.

Grid coordinates and the representative tile

For the trace, blockIdx.z = 0 selects the first batch/head slice, blockIdx.x decodes to token tile 0 and output block 0, and at least 128 valid tokens make every group in the first tile real. The CTA reads the same 16-token input group through two consumer row groups: warps 0 and 1 share token row group 0, while warps 2 and 3 share row group 1. Each warp pair differs only in its 64-channel band.

3. Warp and thread duties: lane-owned fragments

An MMA fragment is a register contract, not a per-lane copy of a matrix. A lane owns four packed A words, two packed B words and, for the Half accumulator, two packed C words. All 32 lanes cooperate in a single mma.sync; the dot product is formed collectively.

The exact A, B and C mappings

For m16n8k16, A lane 21 has group = 21/4 = 5 and thread = 21%4 = 1. It owns rows 5 and 13, and K columns 2, 3, 10 and 11 of the K16 subtile. Its four words are x = (row5, K2/3), y = (row13, K2/3), z = (row5, K10/11) and w = (row13, K10/11). For the trace K16 subtile starting at K144, those are channels 146/147 and 154/155; with the 16-token group based at token 32, the rows are tokens 37 and 45.

B lane 5 has group = 5/4 = 1 and thread = 5%4 = 1. It owns column 1 inside its N8 tile and K rows 2, 3, 10 and 11. The selected weight uint4 carries two adjacent N8 fragments: x and y are the low N8 fragment, z and w the high N8 fragment. For output 81 the low N8 base is 80, so column 1 is exactly 81; the high fragment is columns 88–95 with its column 1 at 89.

C lane 20 has group = 5 and thread = 0, so it owns output rows 5 and 13 and columns 0 and 1 of the N8 fragment. The first accumulator word holds row 5, columns 0 (low Half) and 1 (high Half); therefore Y[37,81] is the high Half of that first word. This is a collective result, not a value shipped from lane 21 to lane 20.

The collective move and the separate register permutation

The MMA is a warp-wide collective: every lane supplies its own A and B fragment and receives its own C fragment. A lane contributes to several output columns, but there is no lane-to-lane scalar transport. The separate permute_quad and shuffle_index operations reorder registers for a caller; they do not change a shared or global address and are not part of the MMA result.

4. Resource budget: shared bytes, declared registers and ptxas

The kernel has two separate resource budgets. The first is a fixed shared-memory allocation of 24,600 bytes that stages A tiles and transaction barriers. The second is the per-thread register payload: source-declared word counts that the compiler may reuse, and a separate ptxas allocation when an accepted record is available. Neither is an occupancy or throughput claim.

Shared-memory byte allocation

The source reserves 24,600 bytes: three 8192-byte stages (3·8192 = 24576) plus three 8-byte transaction barriers (3·8 = 24). The barriers are at byte offsets 24576, 24584 and 24592. The slot bytes are 0, 8192 and 16384. This is a source-derived static allocation; no occupancy or achieved-bandwidth claim follows from it.

Declared register payload versus compiler allocation

The CTA's 128×128 Half output tile is 32,768 bytes of logical accumulator state, but it is distributed across threads rather than allocated in shared memory. The source payload declares 64 accumulator words, 32 A words and 32 B words per thread: 64 + 32 + 32 = 128 scalar 32-bit slots. The A payload is r_Input[4][2] (eight uint4 = 32 words); the B payload is r_Weight[2][4] (also eight uint4 = 32 words). This is a declared payload count, not a guaranteed physical-register lower bound and not proof that every value stays simultaneously live after compiler scheduling and reuse. The actual ptxas allocation is reported separately below; the source-declared __maxnreg__ cap is not an allocation measurement.

The boundary rules that make the hierarchy real

  • Generic FlashLight headers depend only on CUDA, the C++ standard library or other FlashLight headers. They have no Torch, Python, DLSSNR, CUTLASS or ThunderKittens dependency.
  • Every primitive has one canonical definition: flashlight/arch for instruction wrappers, flashlight/numeric/packed.cuh for E4M3 conversions, and csrc/common/ops/frontend_texture.h for model texture/surface operations. Higher layers add typed contracts; they do not re-spell the same instruction.
  • C++17 is the language baseline. FP16 MMA requires SM80+, FP8 requires SM89+, the CTA bulk-copy path requires SM90+, and SM80/86/89 retain the lane-striped cp.async fallback.
  • The tree uses no tcgen05, TMA, ldmatrix or address swizzle. The only matrix-adjacent warp move is movmatrix.sync.trans in arch/warp.cuh; do not describe a mechanism the source does not use.
  • Election, memory ordering, group waits and CTA synchronization stay visible at the call site. The library supplies named operations, not an automatic scheduler or an invented barrier.
  • Numerical policy stays with the model: the FFN activation is in dlssnr::ops; the Small31 Float PV/denominator policy is in csrc/common/ops/small_attention.h; Half accumulation remains the legacy/tile path.

The kernel initializes three transaction barriers with 128 arrivals, publishes the initialization with __syncthreads, primes the weight registers, fills slots 0, 1 and 2, and waits on slot 0. Each iteration reads the current A fragments from shared memory, issues the typed accumulation, preloads the next B tile, waits for the next A stage, and refills the consumed slot with iteration i+3 when it is still in range.

Practical rules for extending the library

  • Give each primitive one canonical definition. Instruction wrappers live in flashlight/arch, E4M3 conversions in flashlight/numeric/packed.cuh, and model texture/surface operations in csrc/common/ops/frontend_texture.h. If a second caller needs the same instruction, add a typed contract above it, not a second PTX spelling.
  • Type the fragment and storage contract explicitly: word count, alignment, byte units, ownership and cache policy. Do not hide a layout conversion in an accessor.
  • Compose the schedule at kernel scope. The library may name copy, expect, arrive, wait and publication operations, but the caller keeps election, ordering, bounds and the numerical policy.
  • Verify four things before adopting a change: the source and roster audit, the C++17 compile for every supported target, the numerical/rounding behavior, and the accepted measured performance. A compile-only result is not performance acceptance.

Choose the MMA initial condition before writing the loop

Start with the model equation D = A × B + C. The first MMA reads every accumulator word as an input. Decide who produces C before choosing the register type or moving the loop into a helper: a pure projection starts at zero; attention scores start at their learned bias; a residual projection starts at the decoded, scaled residual. An allocated register array is not a zero producer.

For the fused input adapter, value-initialize the typed Half accumulator at the first product, then write its two result words into the output tile. This directly expresses A × B + 0 without requiring a blanket clear of the larger tile array. The migration initially read that tile before its first write; actual-image validation exposed non-finite preprocessed features. The corrected source seeds all four FP16/FP8 full/downsample entries explicitly.

flashlight::MmaAccumulator<flashlight::AccumulatorPrecision::Half> accumulator{};
// MMA reads the zero seed, then writes the two packed Half2 accumulator words.
r_Adapter[r_Tile].pair[r_Column][0] = accumulator.word[0];
r_Adapter[r_Tile].pair[r_Column][1] = accumulator.word[1];

Follow the actual adapter MMA and stores. For bias-seeded attention, the four loaded bias words fill each pair of N8 fragments before the score MMA; replacing those values with zero would change the model.

Design the residual seed from its stored precision

In the C512 FP8 projection, residual storage is E4M3 even though the MMA accumulates packed Half2. For one lane, read a 16-byte vector from each of two 512-byte warp stripes, at base + pair × 512. Each pair contains two 16-channel groups, each split into two N8 accumulator fragments. For group g, decode the low 16 bits of words 2g and 2g+1 into accumulator words 0/1 and multiply by the first Half scale; decode their high 16 bits into words 2/3 and multiply by the second scale. The logical channel group is 2 × pair + g. A chosen residual scalar thus flows from one E4 byte, through its decoded Half2 component and scaled accumulator component, into C for the projection MMA.

pair = 0, 1;  group = 0, 1;  channel_group = 2 * pair + group;
C[0] = decode_e4x2(low16(words[2*group    ])) * scale[channel_group][0];
C[1] = decode_e4x2(low16(words[2*group + 1])) * scale[channel_group][0];
C[2] = decode_e4x2(high16(words[2*group    ])) * scale[channel_group][1];
C[3] = decode_e4x2(high16(words[2*group + 1])) * scale[channel_group][1];

These are the source's existing decode and Half2 multiply operations, shown as layout pseudocode. Reading the bytes as Half, or reading four stripes instead of two, supplies a different C and can read beyond the logical residual tile. The shared attention/FFN projection, pooling projection and output-view projection preserve this same mapping. Pool unquantized accumulators before publishing the downsampled E4 output; retain that quantization boundary.

Validate the seed independently: set projection weights to zero, vary finite E4 residual values and exactly representable Half scales, and compare all four output layouts with a logical reference while checking guards and input immutability. Then validate the full image path: the actual 4K candidate007 trace matched the original across 173 retained numeric buffers, including finite preprocessing input. Those observations test correctness at different boundaries; they are not NCU measurements or a speed claim. The promoted default library also passed both focused residual and preprocessing regression tests, with four entry points covered by each test.

01. Define the model operation and the observable outputs

Target entry: window_block_c128_fp8. This entry implements the ordinary C128 block used in records 9–14 and 56–61. Its logical input and output are both [H,W,128], with four physical 4 × 4 tiles forming each 8 × 8 attention window. Frontend and transition records wrap this same operation with additional work. The FFN is 4 complete-input branches, each 128 → 128 → 32, followed by a 128 → 128 mixing matrix. The attention has 4 heads, each with 32 channels. There is no pre-FFN LayerNorm and no sparse routing decision. Every FFN works independently at each token; the attention is where 64 positions exchange information. The architecture document is useful context, but all mechanics needed for this entry are developed below.

Write the ordinary block as Zraw=FFN(X)+sffn⊙R; Z=Publish(Zraw); Q,K,V=project(Z); A=Publish(normalize_keys(E(QKᵀ+bias))V); Yraw=project(A)+sattn⊙Z. This entry publishes working operands as E4M3, while the matrix accumulators, residual products, activation and reductions use packed Half arithmetic. “Raw” identifies a value before the next publication, not an FP32 promise. The model equation alone leaves reduction order and physical placement unspecified; those are the kernel-design problem.

02. Write the simple correctness oracle before tiling

Start with the following nested-loop interpretation. A token index denotes a spatial position, a channel index selects its feature, and a head index selects one 32-channel attention space. The oracle is deliberately expensive: it can materialize every hidden tensor and the 64 × 64 score matrix. It establishes which values may communicate and where publication belongs. To validate the final bit pattern, replace its abstract dot products and sums with the exact Half instruction/reduction order introduced below; a generic FP32 PyTorch implementation is only a mathematical and shape check.

A fully staged implementation would write the hidden FFN tensor, branch concatenation, QKV, scores, probabilities and attended values to global memory, then read them back in separate launches. For one head, a score tensor alone is 4096 Half values, or 8192 bytes; a separate write and read would transfer 16384 logical bytes before considering cache effects. The implementation removes these particular intermediate transfers by choosing an ownership map that keeps their producers and consumers together. The tradeoff is longer register lifetimes, and for multiple warps, explicit shared-memory synchronization.

03. Derive the CTA, warp, tile and lane ownership

Use a CTA shaped (32,4,1): x is the warp lane, y is the warp number. One CTA covers an 8 × 8 window whose origin is (8·blockIdx.x+OriginX,8·blockIdx.y+OriginY). Split it into four 4 × 4 tiles, indexed left-to-right then top-to-bottom. A physical tile has 16 token rows, matching the M dimension of the MMA instruction. Each C32 channel panel occupies 512 bytes, so a C128 tile occupies 2048 bytes and a whole window holds 8192 published data bytes.

Natural token t=8y+x is mapped to p=32⌊y/4⌋+16⌊x/4⌋+4(y mod4)+(x mod4). Thus natural token 13, pixel (5,1), is physical token 21 in tile 1. For the output accumulator, lane L owns token rows L/4 and L/4+8 within a tile. In column group j it owns channel pair 8j+2(L mod4), plus the following channel. Lane 6 owns rows 1 and 9; column group 2 gives channels 20 and 21 within its C32 panel. Four neighboring lanes together represent one token's channels. Do not reinterpret these per-lane words as four neighboring BHWC channels.

04. Derive all three address maps, then implement the input

For normal activation tiles use G + tileIndex·(2048) + panel·(512) + chunk·512 + lane·16, with tileIndex=tileY·(Width/4)+tileX. The final term makes adjacent lanes load adjacent aligned 16-byte vectors. Tile 7, panel 1, chunk 0, lane 6 therefore begins at byte 14944 from G. A whole warp obtains 512 bytes for one K32 fragment panel. The packed producer layout removes the need to fetch a dense image and perform a separate runtime packing pass.

The spatial channel-plane map is different: G + (((plane·H+y)·W+x)·16) + 4(lane&3), where plane=panel·2+2·chunk+word/2, x=originX+((lane/4)&3), and y=originY+lane/16+2(word&1). Four lanes gather one 16-byte pixel vector, and the word's low bit changes the token row rather than the channel plane. Half-word or byte order remains the native fragment order inside that vector. This formula is needed to distinguish this packed-tile entry from a spatial view; this entry itself loads and stores tiles.

LoadWindowWeights reads the prepacked B operand. With output count N, reduction base r, output base o, chunk q and 16-output subpanel j, its byte offset is (r/32+q)·N·32 + (o/16+j)·512 + lane·16. Each K32 panel occupies 32 bytes per output column in this precision. For N=128,r=32,o=16,j=0,q=0,lane=6 the offset is 4704. This is a packed matrix address, not (r·N+o)·sizeof(element). Load weights once and reuse them across the owned token tiles; the cost is retaining B fragments in registers while A tiles are consumed.

Lay out the complete packed weight record

Let C=128, H=C/32=4, and b=1 bytes per matrix operand. Put H expansion matrices first, each C×128×b bytes, followed by H contraction matrices, each 128×32×b bytes. Thus ContractOffset=H·C·128·b=65536, and MixOffset=ContractOffset+H·128·32·b=81920. The C×C mixing matrix follows. For the ordinary profile, 16 padding bytes precede the C Half FFN scales, and another 16 precede QKV. QKV occupies 3·C²·b bytes; the H Half attention-bias tables occupy H·8192 bytes. The H FP32 head scales are rounded up to a 16-byte allocation before the C×C projection. Finally come C Half attention-residual scales. These sizes derive every later pointer from the record base instead of relying on unexplained offsets.

MakeWindowFragment names the four loaded words without changing their bits. Normal activation loads use __ldcg, requesting an L2 path that bypasses L1; weight and bias loads use __ldca, allowing L1 and L2 reuse. Spatial-view words are ordinary explicit loads. The policies are performance hints, not evidence of a hit rate or proof of synchronization. These local kernels do not stage an asynchronous cp.async/TMA pipeline: their operand placement is direct register loading plus the shared exchanges described next. The PTX cache rules define those requests.

05. Construct the bounded physical-tile input

The entry reads physical tiles. The window origin is divided by four to obtain its first tile; the tile index selects one of the four 4 × 4 regions. If a tile-grid dimension is one, its reads broadcast tile zero; otherwise invalid tiles produce zero fragments. Stores remain bounded independently. All lanes still participate in the subsequent collective arithmetic, so a padded token must not make one lane exit before shuffles or MMA.

The E4M3 publication introduces a crucial distinction between a native MMA K coordinate and a model channel. Word 0 packs accumulator column groups 0 and 1 together. Lane 6 (q=2) therefore places model channels [4,5,12,13] in its four bytes, while the instruction consumes that word as native K coordinates [8,9,10,11]. Define k within a C32 panel, a=k&15. The producer's native-K-to-model-channel permutation is (k&16)+2·floor(a/4)+(a&1)+8·((a&2)!=0). Add the C32 panel base for a wider tensor. This is exactly packed_input_index; it leaves the upper/lower 16-channel half separate while interleaving channel pairs inside each half.

The B payload compensates for this same permutation. To create the natural matrix W, write W[modelChannel,output] into the packed slot whose native K index is inverse_packed_input_index(modelChannel). For model channel 12, that native index is 10, so lane 6's third A byte multiplies the weight for model channel 12, not the natural row 10. The matrix decoder applies the inverse permutation before packed_weight_index for exactly this reason. Copying a dense row-major matrix into the payload, or packing the A bytes in consecutive natural-channel order without changing B, breaks the dot product even though all tensor dimensions look correct. The paired publication avoids a runtime cross-lane channel shuffle; its cost is a nontrivial, precision-specific packing contract.

35						// tile. Singleton dimensions broadcast; all other OOB reads zero.

61				FWindowActivationTile<bFp8> r_InputTile;
62				#pragma unroll
63				for (int r_Chunk = 0; r_Chunk < FConfig::Chunks; ++r_Chunk)
64				{
65					const uint64_t g_InputFragmentAddress =
66						Parameters.g_Input +
67						uint64_t(g_TileY * g_TileColumns + g_TileX) * FConfig::TileBytes +
68						(Warp)*FConfig::PanelBytes + r_Chunk * 512 + int(threadIdx.x) * 16;

70						bValid ? __ldcg(reinterpret_cast<const uint4*>(g_InputFragmentAddress))
71							   : make_uint4(0, 0, 0, 0));
72				}

74			}

83													g_PackedWeights + FConfig::FfnScaleOffset, 32 * Warp);
84
85		// All experts must finish reading X before their published outputs reuse
86		// the same slab. This is a tensor lifetime barrier, not a warp shuffle.
87		__syncthreads();
88		#pragma unroll

90			s_Window.Store(r_Tile, Warp, PublishWindow32<bFp8>(r_Contracted[r_Tile]));

93		for (int PanelIndex = 0; PanelIndex < FConfig::Heads; ++PanelIndex)
94		{
95			const auto r_Weights = LoadWindowWeights<bFp8>(g_PackedWeights + FConfig::MixOffset, 32 * Warp,
96														   32 * PanelIndex, Channels);

99				LinearWindow32(s_Window.Load(r_Tile, PanelIndex), r_Weights, r_Output[r_Tile]);
100		}
101

103		#pragma unroll
104		for (int r_Tile = 0; r_Tile < 4; ++r_Tile)
105			s_Window.Store(r_Tile, Warp, PublishWindow32<bFp8>(r_Output[r_Tile]));
106		__syncthreads();
107	}

111	FWindowValueTile<bFp8> r_Value[4];

116	for (int PanelIndex = 0; PanelIndex < FConfig::Heads; ++PanelIndex)
117		#pragma unroll

122														   96 * int(threadIdx.y) + 32 * r_QkvComponent,
123														   32 * PanelIndex, 3 * Channels);

125			for (int r_Tile = 0; r_Tile < 4; ++r_Tile)
126				LinearWindow32(s_Window.Load(r_Tile, PanelIndex), r_Weights,
127							   r_Projected[r_QkvComponent][r_Tile]);
128		}

131		*reinterpret_cast<const uint32_t*>(g_PackedWeights + FConfig::HeadScaleOffset + 4 * threadIdx.y));
132	#pragma unroll
133	for (int r_Tile = 0; r_Tile < 4; ++r_Tile)
134	{
135		NormalizeWindow<true>(r_Projected[0][r_Tile], r_HeadScale);
136		NormalizeWindow<false>(r_Projected[1][r_Tile], CONST_HALF2_ONE);
137		r_Query[r_Tile] = PublishWindow32<bFp8>(r_Projected[0][r_Tile]);
138		r_Key[r_Tile] = PublishWindow32<bFp8>(r_Projected[1][r_Tile]);
139		#pragma unroll
140		for (int r_Column = 0; r_Column < 4; ++r_Column)
141		{
142			// Transpose Half accumulators before E4 publication, exactly as the
143			// DLL does, to obtain B fragments for probability times value.
144			const uint32_t r_LowerValueRows = TransposeM8n8(r_Projected[2][r_Tile].r_Pair[r_Column][0]);
145			const uint32_t r_UpperValueRows = TransposeM8n8(r_Projected[2][r_Tile].r_Pair[r_Column][1]);
146			r_Value[r_Tile].r_Column[r_Column][0] = PackHalfPairsE4(r_LowerValueRows, r_UpperValueRows);
147		}
148	}
149
150	__syncthreads();
151

153	#pragma unroll
154	for (int r_FirstTile = 0; r_FirstTile < 4; r_FirstTile += FConfig::AttentionBatch)
155	{
156		FWindowActivationTile<bFp8> r_Attended[FConfig::AttentionBatch];
157		FWindowAccumulatorTile<32> r_Output[FConfig::AttentionBatch];
158		#pragma unroll
159		for (int r_LocalTile = 0; r_LocalTile < FConfig::AttentionBatch; ++r_LocalTile)

183							   r_Output[r_LocalTile]);
184		}

187		for (int r_LocalTile = 0; r_LocalTile < FConfig::AttentionBatch; ++r_LocalTile)
188		{

191			{

193				constexpr int Chunks = FWindow32Profile<bFp8>::InputChunks;

195				const int g_Width = Parameters.ViewWidth > 0 ? Parameters.ViewWidth : Parameters.Width;
196				const int g_OriginX =
197					int(blockIdx.x) * 8 + Parameters.OriginX + ((r_FirstTile + r_LocalTile) & 1) * 4;
198				const int g_OriginY =

231					#pragma unroll
232					for (int r_Chunk = 0; r_Chunk < FConfig::Chunks; ++r_Chunk)
233					{

236							Parameters.g_Output +
237							uint64_t(g_TileY * g_TileColumns + g_TileX) * FConfig::TileBytes +

239						StoreNoAllocate(g_OutputFragmentAddress,
240										make_uint4(r_Published.r_Word[0], r_Published.r_Word[1],
241												   r_Published.r_Word[2], r_Published.r_Word[3]));
242					}
243			}
244		}
245
246		__syncthreads();
247	}

250	__trap();
251#endif

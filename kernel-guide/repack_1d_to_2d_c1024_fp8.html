01. The whole problem

This kernel sits between the last global bottleneck block and the first decoder transition (records 38→39). The logical activation has shape [H,W,1024]. Local blocks group pixels into physical 4×4 tiles. Global attention needs the same pixels in row-major sequence order, where token t = yW+x. This entry converts the sequence back into tiled storage for the spatial decoder.

No learned matrix, activation function, channel mixing, or floating-point arithmetic belongs here. A FP8 word is copied as 32 unchanged bits containing 4 values in the native E4M3 channel order. Even NaN payloads and signed-zero bits survive the copy. The model-level equation is Y[y,x,c] = X[y,x,c]; the hard part is making that identity true for two different physical address functions. The architecture companion locates the boundary, but all layout definitions needed for this kernel are below.

Write a correctness baseline before parallelizing

Begin with a CPU loop over every logical token and every channel word. Give each input word a recognizable integer bit pattern. Implement the two address functions below, and copy between their results. Integer patterns are a better first test than random floating-point activations because a wrong pixel or channel remains easy to identify.

F is the packed-word address inside either representation; S changes a row-major pixel index into a spatial-tile index. Neither function changes the channel word. For this public entry, WPT=256 and the forward packing alignment is 32 tokens. These are compile-time precision choices, not runtime tensor metadata. The prepared deployment allocator can reserve a larger buffer than a single entry writes; distinguish allocation size from the kernel's actual loop extent.

02. One CTA: its concrete subproblem

For the 3840×2160 image, the bottleneck is H=36, W=60, T=2160. The deployment launcher submits 2176 CTAs × 256 threads. One CTA owns 256 logical uint32 work items on its first iteration: one complete token (1024 bytes). Logical ownership is contiguous even though physical addresses are interleaved. There is no matrix subproblem or reuse across threads.

The launcher sizes for 2176 allocated tokens. This kernel actually covers 2160 tokens × 256 words. Thus the final 16 CTAs have no valid loop iteration. A larger allocation or grid does not enlarge the source loop bound. The measured launch table below independently checks the submitted geometry.

03. Warp and thread ownership

The prepared plan uses 256 threads per block. Flatten the launch as i=blockIdx.x×blockDim.x+threadIdx.x. Decompose the loop index as t=i//WPT and cw=i%WPT, then map to physical addresses. Notice that i is a logical work index, not the physical input or output offset. At the next iteration add gridDim.x×blockDim.x. This grid-stride loop preserves full coverage even when the launcher supplies fewer blocks than the number of words.

Each work index belongs to exactly one thread modulo the grid stride, and the address permutation is one-to-one. Consequently two threads never write the same output word. There is no cross-thread exchange, reduction, shared-memory tile, or barrier. Adjacent logical channel words are permuted within a compact 128-word panel, so the mapping retains spatial locality without a shared-memory transpose. The source uses ordinary 32-bit loads and stores; it does not explicitly vectorize them into 16-byte instructions or request asynchronous copies.

04. Resource budget

Application shared memory: 0 bytes. Shared barriers, tensor fragments, and persistent register arrays: none. Each active thread needs a 32-bit word plus integer address/control temporaries; pointer and multiply lowering can consume more than one register. The source has no register cap. Do not infer allocated registers by counting C++ variables.

No staging buffer exists, so there is no shared-memory bank map or XOR swizzle to invent. L1/L2 cache residency is managed by hardware and varies with replay; the source only specifies global-memory addresses. The profiler's driver reservation is distinct from source-declared shared bytes.

05. Execution and scheduling

The SM schedules independent CTAs in any order; nothing in this permutation depends on that order. Within each thread, calculate a work index, test the loop bound, derive token and word coordinates, then execute the direction-specific copy. Increment by the grid stride and repeat. The next kernel observes completion through stream ordering.

06. Trace one token through the source

Keep one colored payload in mind: token 309, channel word 13. It is owned by thread 13, warp 0, lane 13 in CTA 309. The following derivation follows its spatial index, packed-word address, global load, register value, and global store without changing the example midway.

Derive the spatial token permutation

Take y=t//W and x=t%W. The tile coordinate is (y//4,x//4). There are W//4 tile columns; its linear tile index is (y//4)(W//4)+x//4. Multiply by 16 to skip complete tiles. The pixel within that tile is 4(y%4)+x%4. Therefore:

For width 60 and token 309, (y,x)=(5,9). The tile is (1,2), tile index 17, and the pixel inside it has index 5. Thus S(309)=17×16+5=277. This example separates pixel permutation from the more intricate word interleave; do not apply the 4×4 permutation independently to channels.

Derive the packed-word interleave

A naive t×WPT+cw address would not match the surrounding tensor-core kernels. Their fragments interleave 16 token rows with groups of eight channel words. Split the two indices into independent bit fields. The address below is in uint32 words; multiply it by four only when adding it to a byte pointer.

11// The independently recovered FP8/Half layouts differ only in the 16-token
12// group stride: 256/512 dwords per token. Keep the shared swizzle in one template.
13// Shared by both repack directions and both storage precisions; these two
14// pure layout maps contain no allocations, synchronization or memory operations.
15template <uint32_t WordsPerToken>
16__device__ __forceinline__ uint32_t GlobalRepackPhysicalWord(uint32_t g_TokenIndex, uint32_t g_ChannelWord)
17{
18	static_assert(WordsPerToken == 256u || WordsPerToken == 512u,
19				  "Only recovered C1024 layouts are admitted");
20	return (g_TokenIndex / 16u) * (16u * WordsPerToken) + (g_ChannelWord / 8u) * 128u +
21		   (g_TokenIndex % 8u) * 16u + (g_ChannelWord % 4u) * 4u + ((g_ChannelWord % 8u) / 4u) * 2u +
22		   (g_TokenIndex % 16u) / 8u;
23}

25__device__ __forceinline__ uint32_t GlobalRepackSpatialToken(uint32_t g_TokenIndex, uint32_t g_Width)
26{
27	const uint32_t g_Y = g_TokenIndex / g_Width, g_X = g_TokenIndex % g_Width;
28	return ((g_Y / 4u) * (g_Width / 4u) + g_X / 4u) * 16u + (g_Y % 4u) * 4u + g_X % 4u;

These fields do not overlap. Within a 128-word panel, the two channel low bits occupy address bits 2–3, the channel high bit occupies bit 1, and token bits occupy bits 4–6 and bit 0. Every combination has one address; this proves the inner layout is a permutation. Complete panels and complete 16-token tiles occupy disjoint intervals.

A channel-word index labels the native packed word, not four consecutive model channels. In a C32 panel let v=cw%8, base=32×floor(cw/8), and a=base+16×floor(v/4)+2(v%4). The four bytes contain model channels [a,a+1,a+8,a+9], in that order. This follows the producer's PackHalfPairsE4 of adjacent N8 accumulator groups: cw=0 carries [0,1,8,9]. The repack kernel neither undoes nor changes this channel permutation; surrounding MMA operands and packed weights already agree on it.

Continue with cw=13. It contains model channels [50,51,58,59]. F(309,13)=78038 and F(277,13)=69846. This kernel therefore copies byte offset 312152 of its input to byte offset 279384 of its output. Compute both sides on paper before implementing the device loop. Only the token argument differs.

Execute the address derivation in the owning loop

The selected logical work item is i=79117. Its bound succeeds, integer decomposition gives token309 and word13, and the layout helpers produce the two byte offsets above. The source expresses an ordinary uint32 global load followed by a global store; there is no explicit cache operator, vector copy, shared stage or collective. The compiler selects machine instruction details, which the SASS evidence below can verify. On the documented covering grid the next grid-stride index exceeds the loop limit, so this thread executes one copy.

Handle the boundary exactly

The inverse loop covers exactly T×256 words. The input may contain padded token rows, but they have no real spatial destination and the kernel never reads them. An oversized launch simply fails its loop bound; it must not write extra spatial rows.

The supported host contract supplies positive, aligned spatial geometry and separate input and output buffers. This permutation is not generally safe in-place: a thread can overwrite a word another thread has not read. Width must be compatible with the four-pixel tiling; the prepared model geometry satisfies that contract. Unsigned 32-bit loop arithmetic also means the launcher must keep products within its validated bounds.

Reconstruct the final kernel

Implement the two pure integer functions first. Then add the launch index and grid stride. Finally add the direction-specific extent and tail rule. Keep the full 32-bit word as an integer throughout: unpacking/repacking would add work and could alter special values. The only precision-specific choices are words per token and the forward alignment.

Validate addresses before measuring bandwidth

  1. Enumerate every (token%16,cw%8) pair on CPU. Verify 128 unique offsets from 0 through 127. Then check the full geometry has no destination collisions.
  2. Fill packed words with an index-derived integer pattern. Compare this direction against the scalar baseline word for word; also run forward then inverse and compare every original bit.
  3. Use widths with more than one tile column and heights with more than one tile row. Include a token such as the worked example that moves between tile indices; a single 4×4 tile can hide permutation mistakes.
  4. Test a forward extent that requires padding where the geometry permits it, poison the destination first, and check only the specified aligned tail becomes zero. For inverse, poison padding in the input and put canaries after the spatial output.
  5. Repeat with an intentionally smaller grid to exercise a second grid-stride iteration. Test both precisions separately, because their word counts differ.

The optimization here is avoiding computation: copy packed bits, derive addresses with power-of-two divisions and remainders, and let independent threads stream through the permutation. The measured evidence below checks traffic and instructions for the documented workload; an optimization still needs a controlled before/after experiment.

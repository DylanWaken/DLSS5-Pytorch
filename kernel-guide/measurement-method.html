One lesson, six questions

  1. The whole problem: locate the model operation, name every tensor and define the equation. Follow a diagram before reading code.
  2. One CTA: use a concrete 4K field, block/grid dimensions, the exact output tile, reduction range and tail. Compare source derivation with the measured launch.
  3. Warp and thread: subdivide the CTA and identify the lane's register words, MMA operands, producer/consumer handoffs and address units.
  4. Resource budget: count source buffers and barriers, then compare compiled registers, shared allocation, occupancy limits and local traffic.
  5. Execution and scheduling: follow the control-flow diagram through prologue, steady state, drain and publication. Dependency arrows are not a prediction of hardware issue order.
  6. One token: carry one numerical coordinate through global memory, hardware caches, shared addresses/banks, lane registers and output. Read exact colored excerpts, check mapped SASS/NCU evidence, then reconstruct and validate.

What was actually measured

Collected 13 October 2026 on NVIDIA RTX PRO 6000 Blackwell Workstation Edition, SM120, using Nsight Compute 2026.3.0 and CUDA 12.8.93. A fresh native SM120 library was built with -O3 -lineinfo. Every public entry has both a full report (including PM sampling) and a separate SourceCounters report. The full/source pair has a different replay pass set, so sample totals and instrumented timings need not agree between reports.

The trunk uses 3840×2160 requested image geometry, checkpoint weights, seeded random packed inputs scaled by .02, and five warmups. The model pads intermediate fields: level 0 is 1088×1920 and the C1024 bottleneck is 36×60 (2160 tokens). Only the first logical call of each public entry is selected by NVTX; dependencies still execute in schedule order. Any multi-launch split dispatch is retained in the raw report and per-entry JSON. Renderer entries are supplemental 2176×3840 fields, valid height 2160, with constant .25 current/color textures, no history/motion/depth/conditioning, point sampling, and seeded postprocess feature inputs. The supplemental C32 output-view uses 1088×1920 and phase 1. These fixtures exercise entries, not every optional branch or real-scene distribution.

Reproduce and inspect the evidence

Build receipt and source hashes · Exact collection commands · Evidence index. The library SHA-256 is recorded in every report receipt. The build regenerated a host policy header with whitespace-only formatting changes; token-equivalence was checked and the source checkout restored. CUDA kernel sources match the pinned revision. The harness and parser are checked into tools/profile_kernel_docs.py and tools/extract_kernel_doc_evidence.py.

ncu --nvtx --nvtx-include docs/ --set full --import-source yes \
  -o fp16-full python tools/profile_kernel_docs.py \
  --extension PATH_TO_NATIVE_SM120_LIBRARY --precision fp16 --output fp16-full.json
# Repeat with --section SourceCounters --section LaunchStats; then FP8.
python tools/extract_kernel_doc_evidence.py profile/YOUR_NEW_RUN

Use a new run directory containing harness/, reports/, analysis/ and REPORT.md. The installed NCU version has no source set, so the source collection requests its sections explicitly. Open .ncu-repz files in Nsight Compute to inspect full metrics, source and SASS. The extraction uses ncu_report, not rounded CLI tables.

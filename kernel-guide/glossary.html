Design reasoning and experiments

Baseline #

A simple, correctness-checked implementation used as the starting point for a controlled comparison.

A scalar oracle defines the desired result, but it is not automatically a measured GPU performance baseline. The lessons distinguish these roles.

Oracle #

A reference computation or rule used to judge whether a candidate produces the required result.

For packed permutations compare exact bits. For arithmetic, preserve the specified rounding boundaries and state the comparison tolerance.

Hypothesis #

A prediction about why a design change should help, stated so an experiment can reject it.

For example: an additional shared slot may hide copy latency, but its storage cost may reduce residency. Measure both effects before keeping the change.

Invariant #

A property that must remain true while the implementation changes, such as one writer per output or no reuse of a live buffer.

Prove the invariant from ownership and dependencies, then use targeted tests to catch implementation mistakes. A performance counter alone does not prove correctness.

Arithmetic intensity #

The number of arithmetic operations per byte moved at a specified storage boundary.

Always state which operations and bytes are counted. Logical payload intensity, per-CTA load intensity and measured DRAM intensity can differ because of reuse, caches and padding.

Lower bound #

A minimum cost implied by stated assumptions, before additional implementation and hardware overheads.

An accumulator-word lower bound is not the compiled register allocation. Useful tensor bytes are not necessarily measured memory traffic.

Controlled comparison #

An experiment that changes one mechanism while keeping the workload, correctness contract and measurement procedure fixed.

Time the candidates outside profiler instrumentation, report variation, and use matching profiler runs to explain a difference. Final-kernel counters alone cannot establish a speedup over an unmeasured alternative.

Measurement and evidence

NCU #

NVIDIA’s CUDA kernel profiler. It measures compiled launch resources, hardware counters, sampled warp states and source-correlated instructions.

A report describes a particular GPU, binary, workload and replay protocol. It does not prove numerical correctness or track a semantic model token.

SASS #

The machine instructions executed by NVIDIA GPU hardware after PTX compilation.

One PTX operation may lower to multiple SASS instructions. Dynamic opcode totals count executed warp instructions across the measured launch.

Wavefront #

A unit of shared-memory service used by profiler counters. An instruction can require multiple service wavefronts.

Compare actual and ideal wavefronts for the same instrumented accesses; repeated bank numbers alone do not prove excessive service.

Replay #

Profiler re-execution used to collect metric groups that cannot all be measured in one pass.

Replay and cache control influence traffic and timing. Source sampling and full reports can contain different counts.

Source correlation #

Mapping compiled instruction addresses back to source lines using compiler line information.

Inlining and optimization can attribute work to a helper instead of the call site. Missing direct attribution does not prove a source step was skipped.

PM sampling #

Periodic sampling of GPU performance counters during a kernel.

A timeline shows aggregate activity over sample order. It does not reveal an exact per-warp issue schedule.

Model operations and tensor coordinates

Tensor #

A multidimensional array. Its shape describes logical axes; its layout describes where those elements live.

Keep logical coordinates such as token and channel separate from physical byte addresses.

Token #

One position in the model sequence, carrying a vector of channels. In spatial stages it usually represents one feature-map pixel.

A window reorders spatial positions into local token indices; a repack can change their addresses without changing their values.

Channel #

One feature component of a token. C32 means that each token has 32 channels.

A channel is a model dimension, not a CUDA thread or memory bank.

Attention head #

A separate attention computation over a subset of feature channels, with its own query, key and value vectors.

Head ownership can differ from FFN ownership, which is why fused blocks exchange fragments through shared memory.

QKV #

Query, key and value projections: Q and K produce attention scores; the resulting weights combine V.

Follow the lesson equations and precision boundaries to distinguish projection, normalization, score computation and value aggregation.

Window attention #

Attention restricted to tokens within one spatial window.

The window bounds the key/value set. Global attention instead traverses the wider token sequence.

Global attention #

Attention in which a query can use keys and values across the full bottleneck token sequence.

The implementation streams key/value tiles and maintains accumulators across those tiles.

FFN #

The per-token feed-forward part of a transformer: linear projections with an intervening nonlinearity.

Tokens do not mix through an ordinary per-token FFN. The dense, grouped and branched variants have different channel connectivity.

Dense #

For a channel projection, every output channel can depend on every input channel.

Dense describes connectivity, not a guarantee about physical memory contiguity.

Grouped FFN #

An FFN partitioned into channel groups, each with its own smaller projection and activation path.

For the C512 lessons, distinguish the grouped MLPs from the dense mixing operations around them. Full-input branches in other widths have a different connectivity pattern.

Residual #

A bypass value added to a transformed value, sometimes with a scale factor.

Trace the residual input separately: input-view variants may gather this value from a different physical layout.

Downsampling #

Reducing spatial resolution so that fewer tokens represent the feature map.

Pooling and channel projection are separate operations even when fused. Not every downsampling-related kernel changes channel count.

Upsampling #

Increasing spatial resolution, creating more output token positions from a coarser feature map.

The decoder lessons explain projection, spatial repetition and skip-feature merging in their actual execution order.

Normalization #

A transformation that rescales values using statistics or a norm over a specified axis.

Read the equation in each lesson: channel normalization and attention-row normalization do not use the same reduction or denominator.

Reduction #

Combining many values into fewer values, for example summing across channels or keys.

The logical reduction axis determines which lanes must exchange partial results.

Launch, ownership and matrix instructions

Kernel #

A GPU entry point launched over a grid of thread blocks.

A public template specialization may share its underlying CUDA function body with other documented entries.

Grid #

All thread blocks belonging to one kernel launch.

Grid coordinates usually select independent spatial regions, windows or work packets; the exact mapping is kernel-specific.

Thread block #

A group of CUDA threads that share block-local shared memory and can synchronize with block barriers.

CTA means cooperative thread array. Block coordinates and thread coordinates are different parts of the launch contract.

Warp #

A group of 32 CUDA threads. Warp-level instructions coordinate participating lanes within that group.

A warp diagram specifies ownership and dependencies; it does not promise a particular hardware execution timeline.

Lane #

A thread’s index from 0 to 31 within its warp.

Lane bits select the elements owned by that thread. One lane commonly owns several values from different logical rows or columns.

Warp scheduling #

Hardware selection of eligible warps to issue instructions, subject to dependencies and resource availability.

Assigning a warp a producer or consumer role does not force the hardware to run warps in numeric order.

Tile #

A bounded piece of a tensor or matrix processed as a unit.

Distinguish a logical model window, a shared-memory tile, an MMA instruction tile and a lane-owned fragment.

Fragment #

The subset of a matrix tile held in a thread’s registers for a collective matrix instruction.

An MMA operand is distributed across the warp; no individual lane holds the whole operand matrix.

MMA #

Matrix multiply-accumulate: a warp collectively computes D = A × B + C from distributed register fragments.

These kernels use mma.sync. Instruction shape and operand precision define the lane/register mapping; the lessons show the FP16 and FP8 mappings separately.

Tensor Core #

Specialized GPU arithmetic hardware used by matrix instructions such as MMA.

The kernel must first supply the required register operands. An MMA instruction does not itself gather arbitrary model tensors from global memory.

Accumulator #

A running result updated by repeated additions or multiply-accumulate instructions.

Its precision and ownership are part of the algorithm. The legacy paths use Half fragments; the additive Small31 attention entries keep Half QK scores but accumulate P times V in FP32. Read the destination type of each MMA instruction.

Shuffle #

A warp instruction that transfers a register value between participating lanes.

An XOR shuffle chooses the partner lane by XORing its index with a mask. It does not stage data in shared memory.

Occupancy #

The fraction of a GPU multiprocessor’s maximum warp capacity occupied by resident warps.

Registers, shared-memory allocation and block limits can restrict residency. Higher occupancy alone does not guarantee a faster kernel.

Storage, layout and addressing

TILE4 #

A packed C32 field layout that groups 4×4 pixels and distributes their channel words across lane slots.

Equal byte size does not make it PLANE16. In the FP16 worked example, pixel x1/y0/plane0 has words at bytes 64, 80, 96 and 112. The RGB final output-view descriptor publishes the consumer layout instead.

PLANE16 #

A field layout with one consecutive 16-byte group for each plane and pixel.

The postconsumer starts a group at ((plane*height+y)*width+x)*16. Its four words are consecutive. The base deployment plan retains its TILE4 output contract; the prepared RGB sequence publishes PLANE16.

Global memory #

Device memory addressable across thread blocks and kernel launches, commonly backed by GPU DRAM and accessed through caches.

A pointer identifies an allocation, not a guarantee that each access reaches DRAM rather than a cache.

Shared memory #

Explicitly addressed on-chip storage shared by threads in one block.

Use it to exchange values between warps or reuse a tile. Allocation, address mapping and synchronization are separate design decisions.

Register #

Thread-local storage for scalar values and instruction operands, including matrix fragments.

A register variable is owned by a thread. Actual register allocation and any spills must be checked in compiled code or profiling.

L1 cache #

A hardware-managed cache near a GPU multiprocessor that can serve eligible memory accesses.

L1 cache behavior is not the same as explicitly indexing shared memory, even where hardware resources are related.

L2 cache #

A hardware-managed cache shared across GPU multiprocessors, between many device accesses and DRAM.

Source code alone does not establish that a particular access hits this cache.

Bank #

An independently serviced part of shared memory. The documented address diagrams use 32 banks and 4-byte bank words.

For those diagrams, bank = floor(byte address / 4) mod 32. Analyze the instruction’s actual transactions before concluding that repeated bank IDs conflict.

Bank conflict #

Contention when distinct shared-memory addresses in one serviced transaction require the same bank.

Repeated bank numbers in a whole-warp diagram are not by themselves proof of a conflict; transaction grouping and same-address broadcast matter.

Swizzle #

A deliberate permutation of logical indices into physical positions, often to improve memory access patterns.

An XOR bank swizzle is one possible permutation. The native fragment slabs shown in these lessons have no additional XOR bank swizzle; follow their actual address formulas.

Stride #

The address increment for advancing one element along an axis, measured in elements or bytes as specified.

Always track the unit: multiplying an element offset by the element size produces a byte offset.

Alignment #

The requirement that an address be a multiple of a particular byte boundary.

Packed and vector accesses have alignment requirements. A 16-byte payload size does not on its own prove that its starting address is 16-byte aligned.

Coalescing #

Combining a warp’s nearby global-memory accesses into memory transactions.

Analyze the addresses requested by lanes together. Logical tensor adjacency does not guarantee adjacency in a packed layout.

Gather #

Loading elements from addresses selected by an index mapping rather than a single contiguous logical slice.

Input-view kernels derive spatial addresses and place values into the layout expected by later compute.

Repack #

Rearranging stored values into a different physical layout.

A pure repack changes addresses and ownership, not the model operation or numerical values. Precision conversion is a separate operation unless explicitly fused.

Spill #

Moving a thread value out of registers into local memory when register allocation cannot keep it resident.

CUDA local memory is thread-private address space backed by the device memory hierarchy; it is not shared memory.

Precision, handoffs and pipelines

FP32 #

A 32-bit floating-point representation with more exponent range and precision than Half.

The Small31 attention kernels widen every Half probability before denominator addition and keep the P times V numerator in FP32 across key tiles. Their QK score calculation still uses Half.

FP16 #

A 16-bit floating-point representation. Half is the corresponding scalar type used in these kernel explanations.

The exact accumulator and conversion boundaries matter: intermediate Half rounding is part of the reconstructed computation.

FP8 #

An 8-bit floating-point representation; these deployment paths use E4M3 activation and weight operands.

Operand precision and accumulation precision differ. Legacy kernels commonly accumulate in Half; Small31 global attention uses Half QK scores and FP32 P times V accumulation and denominator reduction. Conversion happens only at the stated boundaries.

E4M3 #

The FP8 format with one sign bit, four exponent bits and three stored fraction bits.

The source conversion helpers specify rounding and finite-saturation behavior. Operand packing also has to satisfy the MMA lane layout.

Quantization #

Mapping values to a limited set of representable values, introducing rounding and possibly saturation.

Track where conversion occurs. Delaying or moving an FP8 conversion can change the model’s numerical result.

Publish #

Prepare a result in the representation and location expected by its next consumer. This is a teaching term, not a CUDA instruction.

PublishWindowChunk and PublishWindow32 prepare register operand fragments: FP8 converts and packs Half results into E4M3 words; FP16 rearranges Half words. Publication can stay entirely in registers. A handoff through shared or global memory additionally needs the appropriate store and synchronization. Publishing this website is a separate use of the word.

Barrier #

A synchronization point that coordinates a defined set of participants and orders the relevant memory operations.

Its scope matters. A block barrier is not a grid barrier, and an asynchronous copy must use the completion protocol required by that copy mechanism.

Producer #

The thread, warp or stage that creates or loads a value for another stage to consume.

A producer must not overwrite a shared buffer while a consumer still depends on its previous contents.

Consumer #

The thread, warp or stage that reads a value prepared by an earlier stage.

The consumer needs both the expected representation and a valid dependency that establishes readiness.

Asynchronous copy #

A memory-copy operation whose completion can be coordinated separately from issuing it.

The SM80/89 per-lane path and the SM90 bulk path have different issue and completion mechanisms. Follow the source path selected for the target architecture.

Ring buffer #

A fixed set of storage slots reused cyclically as a stream of tiles advances.

Each slot has a lifetime: fill, make ready, consume, then reuse. Two or three stages describe buffer capacity, not guaranteed simultaneous execution.

Pipeline #

A sequence of stages arranged so that work on different tiles can overlap when dependencies and resources permit.

More stages may hide latency but require more storage. Read the slot-reuse and wait rules before assuming overlap.

Fusion #

Combining model operations into one kernel so intermediate values can often remain in registers or shared memory.

Fusion can save launches and global-memory traffic, but it also increases live state and may require ownership exchanges between stages.

Read a handoff without confusing its layers

A token is a model position. Its channels are divided among lanes as register fragments. A warp collectively issues MMA instructions and retains accumulator fragments. To publish the result, it prepares the next operand format. If the consumer is another warp, the kernel may store a tile in shared memory and coordinate the handoff with a barrier. These are separate decisions: logical value, lane ownership, representation, storage address, and readiness.

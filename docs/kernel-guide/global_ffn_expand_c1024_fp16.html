01. The whole problem

global_ffn_expand_c1024_fp16 implements the first matrix and activation of the dense FFN in bottleneck records 31–38. Let T be the token count and X be logically [T,1024]. W₁ is [1024,4096], and the result U is [T,4096]. The equation is U[t,n]=Publish(φ(Σₖ X[t,k]W₁[k,n])). Its recovered activation uses b=clamp(x,−4,4) and φ(x)=x·(b·(−0.055908203125·abs(b)+0.447265625)+0.89453125). There is no matrix bias or residual addition in this entry. The second FFN matrix will later contract U and join the residual.

At the architecture’s 4K example the bottleneck field is 36×60, so T=2160. This entry defines T as BatchCount·TokensPerBatch; its physical processing treats that product as one token extent. The prepared deployment uses batch one. Working inputs and outputs are FP16; all Tensor Core accumulators and activation arithmetic here are Half. The model architecture supplies the surrounding network, but this page defines everything required for this kernel.

Establish the mathematical dependency before choosing a tile

Make this scalar version the first dependency test: a one-hot input channel at token 83 must affect only token 83, through the matching weight row. At T=2160 there are 2160·4096=8,847,360 independent outputs, each with a 1024-term dot. Giving every output its own scalar loop repeats X[t,k] across 4096 columns and W[k,n] across 2160 tokens. That is the limitation we will address first. Do not yet add stages, counters or a shared swizzle: none helps until output ownership and operand reuse are defined.

The scalar reference establishes the equation, not final bit identity. The deployed program additionally fixes Half MMA groups, the Half activation sequence and Half publication. We will introduce those precision boundaries as implementation milestones and compare at each boundary. The candidate calculations below reconstruct reasons for the source design; they are not a history of benchmarked revisions.

02. One CTA: its concrete subproblem

First give one CTA a rectangle of complete outputs, with no K split. For M rows and N columns, each A value can serve N outputs and each B value can serve M. Under an ideal once-per-CTA operand-load model the reduction consumes (M+N)·K·2 operand bytes for 2·M·N·K operations. For a square tile this is M/2 operations per operand byte: a 64×64 tile gives 32, while 128×128 gives 64. These are reuse calculations, not measured DRAM intensity; padding, caching, duplicate warp loads and publication traffic are omitted.

Do not maximize that ratio without counting registers. With 128 threads and two Half results per word, the accumulator requirement is M·N/256 words per lane. Increasing 128×128 to 128×256 doubles C from 64 to 128 words; a 256×256 tile would need 256 words for C alone. Smaller tiles leave more operand/address capacity and more CTAs, but reload panels more often. The middle candidate is the source’s concrete compromise.

The selected 128×128 expansion already creates 17·32=544 independent output CTAs. Keep the entire K1024 reduction in each CTA: a K split would add global partial traffic and delay the nonlinear activation until all partials arrive. There is no existing split boundary to preserve for this entry. This is a reason to begin without splitting, not an A/B result proving split-K is slower.

03. Warp and thread ownership

Use the native m16n8k16 operation as the ownership unit. Four M16 fragments ×eight N8 fragments give a warp 64×64 outputs. Arrange four warps as 2×2 to cover the CTA. A plausible 4×1 arrangement would give each warp 32×128 and the same 64 accumulator words per lane, but each B panel would be loaded by four token warps. The 2×2 choice duplicates B across only two token warps, while A is read by two column warps. This balances the two reuse directions without assuming either duplicated read always hits cache.

Now write the arrays from that ownership: Accumulator[4][4][4] means M16 group, N16 group, then four Half2 result words. Warp parity chooses the 64-column half; floor(warp/2) chooses the 64-token half. The thread does not own a scalar 1024-element dot. It contributes operand registers to a warp instruction and keeps its mapped result words alive across all reduction steps.

One instruction computes a 16-token × 8-output-channel tile with a reduction of 16 channels. All 32 lanes participate in the same matrix operation. Each lane supplies four 32-bit A words, two 32-bit B words, and two 32-bit C words. Each C word contains two Half accumulators, so a lane owns four output elements. A source loop over output groups or reduction panels repeats this operation; it does not launch a new warp.

The exact instruction on this path is mma.sync.aligned.m16n8k16.row.col.f16.f16.f16.f16. Both the accumulator input and output are Half. Do not replace its numerical contract with FP32 accumulation when constructing an exact oracle. For the FP8 path, packing to E4M3 is a distinct rounding step; for the FP16 path a packed word simply holds two Half values.

Let lane L run from 0 to 31, g = L // 4 and q = L % 4. The matrix coordinates below describe instruction operands after any kernel-specific loads and shuffles. Storage layouts are designed to supply these coordinates cheaply.

04. Resource budget

Choose the reduction step and storage role together. K32 gives one A stage of 128·32·2=8,192 bytes. The step is a whole number of native MMA K panels, so producer copies need no partial-panel rearrangement. A synchronous one-stage candidate needs 8,200 bytes including its barrier; two need 16,400; three need 24,600. Each added slot buys a possible future operand, not an automatic amount of latency hiding.

Staging B as well is a plausible alternative: its CTA panel is 128·32·2=8,192 bytes, so a 3-stage B ring would add 24,576 data bytes to the allocation below. The source instead loads packed B directly into registers and reuses it over four M16 fragments. That avoids B shared copies and shared capacity, but the two token warps load the same B panel separately and depend on hardware caching. Keep both costs in the design ledger; a cache hint is not evidence that those duplicate loads are free.

Now express the chosen candidate as actual source objects. A uint4 is four 32-bit words; a Half2 word holds two values. The resulting declaration is exactly 24,600 shared bytes per CTA, including every 8-byte barrier. Alignment constrains the base address; it does not add 512 bytes to the declared size.

05. Execution and scheduling

Begin with the blocking one-slot loop in section 6: fill A, synchronize, consume A/B, synchronize before overwrite. Its limitation is exposed transfer/wait time between tiles; it also uses a register-mediated input copy in the simplest implementation. The next candidate replaces the copy with an asynchronous transfer and provides future A slots. Choose three slots only after the 24,600-byte source budget fits; hold B(i) until its last MMA, then load B(i+1). The diagram expresses those lifetime obligations, not a prediction that hardware overlaps every copy with compute.

Derive two separate conditions for reusing a shared slot

A correct blocking loop already waits after filling a slot and after consuming it. An asynchronous version must preserve both meanings: new bytes have arrived and old readers have retired. Give each of the 3 slots its own 8-byte mbarrier. Lane 0 of warp 0 initializes it for 128 thread arrivals, then synchronize the CTA before any copy. On SM90+, IsCopyProducer elects one lane per participating warp to issue ordinary-address cp.async.bulk with the expected completion byte count. On SM80/89, every lane instead issues 16-byte cp.async.cg stripes and attaches its copies with cp.async.mbarrier.arrive. Thus a 512-byte producer panel takes one stripe/lane and a 1024-byte panel takes two.

Use ArriveAndWait to obtain and wait on the current phase token. Reusing a barrier address does not reuse its previous ready state; attached copy completion also belongs to that phase. To test the resulting schedule, compare a blocking single-slot diagnostic implementation with the ring across several wraparounds, including missing groups. A mismatch appearing only after wraparound points first to slot retirement or phase reuse. The final NCU copy/barrier opcodes can verify that asynchronous instructions executed; they cannot prove absence of a race for all schedules.

Do not add an XOR swizzle or ldmatrix merely because another GEMM tutorial uses them. Those solve a different shared-to-register map. Here the producer provides native fragment vectors, and consumers load those vectors directly. Likewise, this path does not allocate TMEM or use a tensor-map descriptor or warp-group MMA. Each extra transform would need to preserve the already-derived operand map and justify its added work.

Global storage is backed by device memory; L2 and L1 are hardware-managed caches on relevant load/store paths. The source’s .ca weight loads permit all-level caching. Its pre-SM90 .cg asynchronous copies use the global cache level. L1::no_allocate output stores request no new L1 allocation. None of these hints implies a guaranteed hit rate or replaces synchronization. NVIDIA’s PTX cache specification defines those distinctions.

To implement that candidate, prime B₀ and all three A slots, then wait for A₀. Consume tile i, load Bᵢ₊₁, and wait for Aᵢ₊₁ before refilling the old slot with Aᵢ₊₃. Why this ordering? The next-stage arrival is reached by every thread after current shared reads, so it also establishes retirement before the refill. Guard future indices and drain the final slots once; otherwise the end of the loop can either fetch beyond K or repeat a tile. There are 32 reduction steps, with the same byte ring in either precision.

06. Trace one token through the source

Follow token 83 and, within it, U[83,34]. Token 83 is group 5, row 3; it belongs to token CTA 0, warp 2, M16 fragment 1, lane 13’s first output row. Lane 13 also carries token 91 because the instruction’s output fragment has two row halves. We retain token 83 as the trace identity throughout: global packed input → shared operand stage → A/B registers → Half accumulator → activation → final output. Adjacent channels and lanes appear only when the collective instruction requires them.

A global allocation is device memory addressed by a pointer; loads can be served by hardware-managed L2 and, depending on the instruction, L1. A cache hit is not another program-visible tensor and the source does not guarantee cache residency. __ldca permits caching at all levels; __ldcg and PTX .cg select global-level caching that bypasses L1. An eviction or no_allocate hint is a performance policy, not a publication barrier.

Shared memory is an explicitly indexed block-local allocation. Another warp may read a producer's values only after the required block barrier or completed asynchronous-copy protocol. A warp shuffle exchanges register values among its active lanes; it does not address shared memory. Arrays named r_… express per-thread values, but only compiler output establishes whether they stay in physical registers or spill to local memory. Tensor-core accumulator fragments are also register operands. These kernels use mma.sync, not TMEM.

Reconstruct the first working version with one shared slot

This scaffold expresses the intended reuse before any asynchronous machinery: A serves multiple output columns, B serves four M16 token tiles, and C remains live through all 32 steps. Implement its helpers in the milestones below. Logical register ownership is not a promise about physical allocation; the final compiler may need extra temporaries or local memory. The 168-register directive is a cap, so inspect the compiled result after the whole epilogue is present.

Implementation milestone 1: make a packed panel round-trip correctly

Before issuing a matrix instruction, implement the scalar pack/decode map and round-trip distinct token/channel tags. The deployment pointers are opaque packed buffers, so a dense row-major fixture would test the wrong contract. Group 16 rows together. One native M16×K16 A panel consumes 512 bytes, distributed as 32 lanes ×16 bytes. For input width K and element size E, group g begins at g·16·K·E. Advance a reduction step in whole panels, and give lane L the vector at L·16. This places four words in the instruction’s required register order without an in-kernel transpose.

A packed B panel for 16 output channels also occupies 512 bytes. One lane’s uint4 supplies two N8 fragments: the first two words belong to the first N8, the next two words to the second. Across K panels, the record advances by N·32 bytes, where this kernel’s N is 4096. The equality follows from 16 reduction values × 2 bytes per value =32 bytes per output column. A cache-all vector load fetches those words directly to registers.

For FP16 weights, packed_f16_weight_index(k,n,N) returns a Half-element offset: panel=(k//16)·ceil(N/16)+n//16; lane=4·(n mod8)+floor((k mod8)/2); within-lane index=4·floor((n mod16)/8)+2·[k mod16≥8]+(k mod2). Multiply the result by two to obtain bytes. This gives you a scalar packer independent of the kernel’s vector-load formula.

Implementation milestone 2: replace scalar loads with native vectors

The panel round-trip gives us a correct byte contract. Now coalesce each producer’s adjacent lane vectors and preserve that order in shared memory. Change only loading at this milestone; retain the blocking barriers. Compare the decoded A/B fragments for token 83 before allowing the kernel to run the full dot.

One reduction step covers K32. Eight token groups each need a 1024-byte slab, making one 8192-byte shared stage. Group g’s global slab address is X+g·16384·2+i·1024, where i is the reduction-step index. Producer warp w copies groups firstGroup+w and firstGroup+w+4 to stage·8192+w·1024 and that address+4096. Invalid groups receive zero uint4 stores from all lanes.

Here X and W name the adjusted bases used by the body: X=Parameters.g_Input+blockIdx.z·16384·2 and W=Parameters.g_PackedWeights+blockIdx.z·(1024·4096)·2. The worked example takes blockIdx.z=0. Preserve these ABI-level offsets when reconstructing a nonzero-Z invocation; they are separate from the block.x token/channel decomposition.

Consumer warp w starts at shared (i mod3)·8192+floor(w/2)·4096+L·16. M16 tile m and K subtile k add m·1024+k·512. These loads need no transpose. W’s lane-vector address is W+nBlock·4096+(w mod2)·2048+L·16+(2i+k)·131072+n16·512. The factor 131072 equals 4096 output columns ×32 bytes per native K panel. The input reduction tile has two native subtiles, each reused across every output tile.

The output address is group·65536·2+nBlock·2048·2+(w mod2)·1024·2+L·16 plus the publication-panel offset. An N16 panel’s offset is n16·512. For the example, the first two channel pairs named in the diagram belong to N16 group 2; four Half2 words cover the two token rows and both N8 halves. This is why replacing the vector store with a naive dense row-major store is incorrect.

Implementation milestone 3: fuse the activation at its legal boundary

A separate activation pass would write then reread 2160·4096 Half preactivations: 35,389,440 bytes of intermediate payload before cache effects. Remove that allocation only after the complete K reduction is available. Keep x in each accumulator word, clamp a copy b, and evaluate two ordered Half FMAs followed by the final Half multiplication. The helper below implements precisely that sequence for all 64 words/lane. Applying the gate to an unfinished dot, or replacing x with clamped b in the final multiply, fails the scalar contract.

Test the epilogue independently around −4, 0 and 4 and at Half rounding ties. Below the lower clamp the recovered gate is zero; above the upper clamp the original x remains unbounded while the gate saturates. This is the model’s specified clamped polynomial, so a standard SiLU implementation is not an admissible substitution.

For Half publication, the four accumulator words of an N16 group are assembled directly into a uint4. There is no E4M3 conversion and no wider post-activation buffer. The exact Half activation values are written once into the next kernel’s native input layout. StoreNoAllocate writes one aligned 16-byte vector with an L1 no-allocation hint. Only groups below the precision-specific bound are written; the source does not clear the caller’s entire allocation.

Implementation milestone 4: add overlap without changing a token’s arithmetic

Only now replace the blocking A slot with the three-slot schedule derived above. Preserve the same B addresses, MMA order and epilogue. Verify the traced values and lifetime boundaries

  1. Address injectivity: enumerate one valid CTA’s output locations; every published byte should have one owner, including the two rows of each lane fragment. Place canaries immediately outside the declared output extent; they should remain unchanged.
  2. Single contributing input channel: pack a one-hot X row and a single nonzero weight row using the scalar packer. Only the chosen token should change, and output values should equal the activation of the intended W row after the documented precision operations.
  3. Pipeline wrap: compare the synchronous tiled scaffold with the staged version over all 32 steps. This exercises each slot repeatedly; poison unused shared storage in a diagnostic build so a missing zero fill or wait cannot silently look correct.
  4. Numerical checkpoints: compare preactivation Half fragments, activated Half fragments, then the final Half words separately. Test values around ±4 and conversion ties; replacing the activation by FP32 should not be accepted as a bit-exact oracle.
  5. Token tails: test legal extents around 16,32 and 128. Valid rows must match the reference; no out-of-range group may be read. Include the T≤16 broadcast path separately from ordinary multi-group inputs.

The optimization sequence is explicit: independent scalar dots repeatedly load operands; tiling shares those operands; a register C tile removes intermediate result traffic; asynchronous input stages may hide load latency; fused activation removes a global preactivation pass. Larger live register state, three shared slots and barrier instructions are the corresponding costs. Establish speed with compiled resource reports and measurements of this actual kernel and geometry, not with timings from another matrix multiply.

88				r_Weight[r_KTile][r_NTile] = __ldca(reinterpret_cast<const uint4*>(

90	};

93	LoadWeights(0);
94	#pragma unroll
95	for (int s_StageIndex = 0; s_StageIndex < FProfile::s_StageCount; ++s_StageIndex)
96		StageInput(s_StageIndex, s_StageIndex);
97	WaitStage(0);

100	// are already stored in the native MMA A layout, so no transpose is needed.
101	FMmaAccumulatorTile<4, 4> r_Accumulator{};
102	#pragma unroll 1
103	for (uint32_t ReductionTile = 0; ReductionTile < FProfile::ReductionSteps; ++ReductionTile)
104	{
105		const uint32_t s_StageIndex = ReductionTile % FProfile::s_StageCount;
106		const uint32_t s_WarpInput = s_StageIndex * FProfile::s_StageBytes + (Warp / 2) * 4096 + Lane * 16;
107		uint4 r_Input[4][2];

109		for (int r_MTile = 0; r_MTile < 4; ++r_MTile)
110			#pragma unroll
111			for (int r_KTile = 0; r_KTile < 2; ++r_KTile)
112				r_Input[r_MTile][r_KTile] =
113					*reinterpret_cast<const uint4*>(s_Storage + s_WarpInput + r_MTile * 1024 + r_KTile * 512);
114		AccumulateTile<FProfile::Precision>(r_Accumulator, r_Input, r_Weight);
115
116		// Match the native software pipeline: preload B, wait for the next A
117		// stage, then recycle the consumed stage for the tile three steps ahead.
118		if (ReductionTile + 1 < FProfile::ReductionSteps)
119		{
120			LoadWeights(ReductionTile + 1);
121			WaitStage((ReductionTile + 1) % FProfile::s_StageCount);
122		}
123
124		if (ReductionTile + FProfile::s_StageCount < FProfile::ReductionSteps)
125			StageInput(ReductionTile + FProfile::s_StageCount, s_StageIndex);
126	}
127
128	// Preserve the native clamped Half polynomial and all its rounding points.
129	#pragma unroll
130	for (int r_MTile = 0; r_MTile < 4; ++r_MTile)
131		#pragma unroll
132		for (int r_NTile = 0; r_NTile < 4; ++r_NTile)
133			#pragma unroll
134			for (int r_Word = 0; r_Word < 4; ++r_Word)
135				r_Accumulator.r_AccumulatorWords[r_MTile][r_NTile][r_Word] =
136					FfnActivation(r_Accumulator.r_AccumulatorWords[r_MTile][r_NTile][r_Word]);
137
138	// Publish each valid 16-token group directly into the next layer's physical
139	// tensor layout. FP8 pairs two N16 fragments into one 128-bit vector.
140	#pragma unroll
141	for (int r_MTile = 0; r_MTile < 4; ++r_MTile)
142	{
143		const uint32_t g_TokenGroup = g_FirstTokenGroup + (Warp / 2) * 4 + r_MTile;
144		if (g_TokenGroup >= g_GroupCount)
145			continue;
146		const uint64_t g_Output = Parameters.g_Output +
147								  uint64_t(g_TokenGroup) * 65536 * FProfile::ElementBytes +
148								  g_OutputBlock * 2048 * FProfile::ElementBytes +
149								  (Warp & 1) * 1024 * FProfile::ElementBytes + Lane * 16;
150		#pragma unroll
151		for (int r_NTile = 0; r_NTile < (bFp8 ? 2 : 4); ++r_NTile)
152		{
153			uint4 r_OutputVector;
154			{
155				const auto& r_OutputWords = r_Accumulator.r_AccumulatorWords[r_MTile][r_NTile];
156				r_OutputVector =
157					make_uint4(r_OutputWords[0], r_OutputWords[1], r_OutputWords[2], r_OutputWords[3]);
158			}
159			StoreNoAllocate(g_Output + r_NTile * 512, r_OutputVector);
160		}
161	}
162#endif
163}

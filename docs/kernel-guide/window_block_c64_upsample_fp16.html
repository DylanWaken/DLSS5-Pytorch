01. Define the model operation and the observable outputs

Target entry: window_block_c64_upsample_fp16. This is decoder entry record 62. It reads a low-resolution 128-channel field, projects to 64 channels, repeats each low token to a high-resolution 2 × 2 patch, and adds the scaled skip from record 8. Its ordinary FFN/attention body then produces [H,W,64]. The FFN is 2 complete-input branches, each 64 → 128 → 32, followed by a 64 → 64 mixing matrix. The attention has 2 heads, each with 32 channels. There is no pre-FFN LayerNorm and no sparse routing decision. Every FFN works independently at each token; the attention is where 64 positions exchange information. The architecture document is useful context, but all mechanics needed for this entry are developed below.

Write the ordinary block as Zraw=FFN(X)+sffn⊙R; Z=Publish(Zraw); Q,K,V=project(Z); A=Publish(normalize_keys(E(QKᵀ+bias))V); Yraw=project(A)+sattn⊙Z. This entry publishes working operands as Half, while the matrix accumulators, residual products, activation and reductions use packed Half arithmetic. “Raw” identifies a value before the next publication, not an FP32 promise. The model equation alone leaves reduction order and physical placement unspecified; those are the kernel-design problem.

02. Write the simple correctness oracle before tiling

Start with the following nested-loop interpretation. A token index denotes a spatial position, a channel index selects its feature, and a head index selects one 32-channel attention space. The oracle is deliberately expensive: it can materialize every hidden tensor and the 64 × 64 score matrix. It establishes which values may communicate and where publication belongs. To validate the final bit pattern, replace its abstract dot products and sums with the exact Half instruction/reduction order introduced below; a generic FP32 PyTorch implementation is only a mathematical and shape check.

A fully staged implementation would write the hidden FFN tensor, branch concatenation, QKV, scores, probabilities and attended values to global memory, then read them back in separate launches. For one head, a score tensor alone is 4096 Half values, or 8192 bytes; a separate write and read would transfer 16384 logical bytes before considering cache effects. The implementation removes these particular intermediate transfers by choosing an ownership map that keeps their producers and consumers together. The tradeoff is longer register lifetimes, and for multiple warps, explicit shared-memory synchronization.

03. Derive the CTA, warp, tile and lane ownership

Use a CTA shaped (32,2,1): x is the warp lane, y is the warp number. One CTA covers an 8 × 8 window whose origin is (8·blockIdx.x+OriginX,8·blockIdx.y+OriginY). Split it into four 4 × 4 tiles, indexed left-to-right then top-to-bottom. A physical tile has 16 token rows, matching the M dimension of the MMA instruction. Each C32 channel panel occupies 1024 bytes, so a C64 tile occupies 2048 bytes and a whole window holds 8192 published data bytes.

Natural token t=8y+x is mapped to p=32⌊y/4⌋+16⌊x/4⌋+4(y mod4)+(x mod4). Thus natural token 13, pixel (5,1), is physical token 21 in tile 1. For the output accumulator, lane L owns token rows L/4 and L/4+8 within a tile. In column group j it owns channel pair 8j+2(L mod4), plus the following channel. Lane 6 owns rows 1 and 9; column group 2 gives channels 20 and 21 within its C32 panel. Four neighboring lanes together represent one token's channels. Do not reinterpret these per-lane words as four neighboring BHWC channels.

Each lane supplies four 32-bit A words, two 32-bit B words, and two 32-bit C words. Each C word contains two Half accumulators, so a lane owns four output elements. Under the microscope: what exactly enters one MMA?

For lane L, let g=L//4 and q=L%4. The highlighted A scalar uses g=3,q=1; B uses g=2,q=1. The output scalar uses g=3,q=1 again. These are three operand ownership maps, not a chain of thread-to-thread scalar multiplies. The selected result is the low Half of D word 0. For a pointwise projection, the row stays the same model token and N labels learned output channels; in QKᵀ, N instead labels key tokens.

FWindowAFragment is four 32-bit operand words per lane. FWindowAccumulatorTile<32> is four N8 column groups, each with two Half2 words for the two row halves. MmaWindowFragment combines a warp-wide A fragment, a two-word-per-lane B fragment, and that accumulator. LinearWindow32 performs all four N8 columns and all 2 reduction chunks needed for a C32 input panel. Repeating this helper over input panels extends the K reduction without changing the output ownership.

The two warps initially split tokens: warp 0 handles upper tiles 0/1 and warp 1 handles lower tiles 2/3. Each retains both C32 input panels and computes both FFN branches for its own tokens. Once Z is published into shared memory, warp 0 becomes attention head 0 and warp 1 becomes head 1 across all four tiles. The shared boundary is therefore a token-to-head ownership transpose, not merely a convenient cache.

04. Derive all three address maps, then implement the input

For normal activation tiles use G + tileIndex·(2048) + panel·(1024) + chunk·512 + lane·16, with tileIndex=tileY·(Width/4)+tileX. The final term makes adjacent lanes load adjacent aligned 16-byte vectors. Tile 7, panel 1, chunk 1, lane 6 therefore begins at byte 15968 from G. A whole warp obtains 512 bytes for one K16 fragment panel. The packed producer layout removes the need to fetch a dense image and perform a separate runtime packing pass.

The spatial channel-plane map is different: G + (((plane·H+y)·W+x)·16) + 4(lane&3), where plane=panel·4+2·chunk+word/2, x=originX+((lane/4)&3), and y=originY+lane/16+2(word&1). Four lanes gather one 16-byte pixel vector, and the word's low bit changes the token row rather than the channel plane. Half-word or byte order remains the native fragment order inside that vector. This formula is needed on the input path.

LoadWindowWeights reads the prepacked B operand. With output count N, reduction base r, output base o, chunk q and 16-output subpanel j, its byte offset is (r/16+q)·N·32 + (o/16+j)·512 + lane·16. Each K16 panel occupies 32 bytes per output column in this precision. For N=128,r=32,o=16,j=0,q=0,lane=6 the offset is 8800. This is a packed matrix address, not (r·N+o)·sizeof(element). Load weights once and reuse them across the owned token tiles; the cost is retaining B fragments in registers while A tiles are consumed.

Lay out the complete packed weight record

Let C=64, H=C/32=2, and b=2 bytes per matrix operand. Put H expansion matrices first, each C×128×b bytes, followed by H contraction matrices, each 128×32×b bytes. Thus ContractOffset=H·C·128·b=32768, and MixOffset=ContractOffset+H·128·32·b=49152. The C×C mixing matrix follows. For the ordinary profile, 16 padding bytes precede the C Half FFN scales, and another 16 precede QKV. QKV occupies 3·C²·b bytes; the H Half attention-bias tables occupy H·8192 bytes. The H FP32 head scales are rounded up to a 16-byte allocation before the C×C projection. Finally come C Half attention-residual scales. These sizes derive every later pointer from the record base instead of relying on unexplained offsets.

Before the ordinary block, read a 4 × 4 low region in spatial planes. Its field dimensions are ceil(Height/2) and ceil(Width/2), each rounded up to a multiple of four. This computes 128 → 64 once per low token; repeating first would evaluate the same linear transform four times.

06. Stream the FFN and make its storage lifetime explicit

01. The whole problem

We need to compute a feed-forward transformation independently for each of 8,160 tokens in X[68,120,512]. Its mathematical contract is u[p,:]=X[p,:]Wpre, followed by eight branches h[p,g,:]=φ(u[p,64g:64g+64]Wexpand[g]) and B[p,64g:64g+64]=h[p,g,:]Wcontract[g]. Wpre is [512,512], each expansion is [64,256], and each contraction is [256,64]. Group outputs concatenate; groups do not sum. The following postmix and residual belong to another operation.

The network architecture guide places this operation in the full encoder–bottleneck–decoder. This lesson defines the operation and its physical implementation locally so it can be read independently.

A first correct implementation can launch premix, expansion/activation and contraction separately. It would expose u[8160,512] and h[8160,8,256]: 4,177,920 and 16,711,680 scalar values. This baseline makes connectivity easy to test, but each intermediate must be written and read before its next consumer. The design question is whether one warp can retain a group's u and consume hidden panels as they are produced. We will derive that fusion from ownership and state size rather than assume the whole FFN fits in registers.

For this boundary, X arrives as channel-plane pixel packets. The baseline first decodes that view; later we will combine the conversion with staging. Working-format publication after premix and activation remains part of the numerical contract even if fusion removes the global tensors. window_ffn_input_view_c512_fp8 is the implementation we will reconstruct and validate against that contract.

02. One CTA: its concrete subproblem

Start with the smallest useful independent job: sixteen positions and one 64-channel group. The field contains 17×30=510 native 4×4 tiles; eight groups give 4,080 such CTA jobs. Each group would request the same token input for its premix. Combining four spatial tiles and four groups instead gives a 64-position, 256-output job: ceil(68/8)×ceil(120/8)×2 = 270 CTAs. Its staged A can serve four different group consumers. Combining all eight groups would halve that to 135 jobs, but doubles group state per CTA or its consumer-warp count. Reuse rises while available independent blocks fall; arithmetic alone does not prove which choice is fastest.

Implement the middle candidate first. CTA (0,0,0) owns pixels y,x=0…7 and groups 0…3; grid Z chooses groups 0–3 or 4–7. The launch derived from this decomposition is grid=(15,9,2), block=(32,4). Every group retains its full K512 reduction, so no inter-CTA reduction is needed. The last region contains four synthetic pixel rows: zero-fill them during input preparation and suppress their output stores. Native singleton-tile broadcasting and view pixel bounds must retain their distinct source rules. The actual captured launch is checked later in section 6.

03. Warp and thread ownership

Next make the grouped computation local. An M16×N16 result uses four Half2 words per lane; a 64-channel group needs four N16 panels, or sixteen words per lane per spatial fragment. Giving one group all four spatial fragments requires 64 premix words and 64 contracted-output words. A current 32-hidden-channel panel adds 32 more: 160 core words per lane before operand arrays and temporaries. Splitting the window between two warps halves those three counts to 32+32+16=80, but both warps now consume weights for the same group. This is a concrete state-versus-reuse tradeoff, not a measured performance ranking.

This E4 view candidate keeps four group warps and four fragments each. Its 128-thread gather issues eight four-byte copies per thread; changing to eight consumers would require redesigning that producer mapping as well as reassessing register pressure. Group identity is warp%4+4·blockIdx.z. Warp 2 owns group 2, output channels 128…191. Keeping a group's premix, activation and contraction in that owner removes any cross-warp hidden exchange.

Derive lane ownership from the MMA contract rather than assigning one token to one thread. Lane 0's first spatial fragment holds token (0,0) in words 0/2 and token (2,0) in words 1/3. The following map is the invariant every load, publication conversion and store must satisfy.

One warp's result has 4 M16 spatial fragments and 4 N16 channel panels. For lane l, let g=l/4 and q=l%4, using integer division. In one N16 panel, word 0 holds row g at columns 2q and 2q+1; word 1 holds row g+8 at the same pair; words 2/3 add eight columns. Coordinates in this lesson are (y,x). Native matrix row g maps to physical x=g%4,y=g/4; row g+8 adds two to y. A lane therefore owns pieces of two tokens. It never owns a complete dot product independently.

mma.sync.aligned.m16n8k32.row.col.f16.e4m3.e4m3.f16 is a converged 32-lane operation. Four A words and two B words per lane collectively describe its operands; two Half2 accumulator words per lane describe the N8 result. Two N8 instructions build an N16 panel. Input fragments are reused across output panels; a weight bundle is reused across the warp's spatial fragments. The diagram maps Half C/D words in both modes. FP8 A bytes are formed by explicit E4 publication; do not reinterpret a Half accumulator array as FP8 without that conversion.

04. Resource budget

Before adding asynchronous copies, size the state that fusion retains. Materializing all 256 hidden channels for 4 spatial fragments would require 256 Half2 words per lane just for hidden values. Streaming a 32-channel panel reduces that to 32, while the contracted result accumulates across eight panels. This is why we fuse panel by panel instead of keeping the entire hidden layer live.

An input stage covers 64 positions ×K64×1 bytes = 4,096 bytes in this precision. Including one 8-byte barrier per slot, one/two/three slots require 4,104/8,208/12,312 static bytes. Two slots are the candidate below; a third slot costs 4,104 additional bytes and requires a new schedule experiment. Predict register pressure from the live premix/output/hidden sets, then compare the compiled count and spill counters only after implementation.

Treat this as a resource prediction before compilation. A uint4 needs four 32-bit words if scalarized into registers; one accumulator word holds two Half scalars. These declared arrays describe logical state, not an additive count of physical registers: lifetimes can overlap, compiler temporaries add state, and an array may spill into local memory. A register ceiling constrains the compiler; it does not reserve exactly that many registers.

For a candidate with compiled count R and T threads, begin with R·T register words, round using the device allocation rules, then compare the register, shared-memory, thread and block residency limits. Do not infer occupancy from static shared bytes alone. The recorded launch, physical allocation, local-memory traffic and instruction evidence appear later in section 6, after we have predictions to test.

The central fusion tradeoff is the simultaneous lifetime of projected u, the contracted output and one hidden panel. The entire 256-hidden-channel tensor is never declared. The FP8 ordinary eight-warp profile halves spatial fragments per warp; the FP8 input-view profile keeps four fragments and has a different register ceiling.

05. Execution and scheduling

Begin with a synchronous premix loop: load a K panel, synchronize the CTA, update every group's accumulators, synchronize again before overwriting that panel. This gives a simple correctness checkpoint but leaves copying outside the compute interval. The next milestone adds a second A slot so input t+1 may be requested while input t is consumed. B is private to each group and loaded directly into registers; putting it in shared memory would need a separate reuse argument.

Once premix matches the baseline, add one hidden panel, activation and its contraction. Repeat that proven unit eight times before considering further overlap. The input-view milestone must wait for every thread’s four-byte gathers before any group reads the staged panel. The schedule below is the final candidate to implement. The capture can check its copy/MMA mechanism and remaining stalls; a speedup from overlap requires a matched timing comparison with the synchronous baseline.

Now implement the candidate schedule: Load W0, issue input 0, and wait for it. Iteration t issues input[t+1] into the other slot before reading its own A vectors and performing MMA. It then loads W[t+1] and waits for the next input. When a slot comes around again, every warp has already passed the intervening wait after reading the previous contents. There are 8 K iterations. The invariant is that a consumer reads a completed current slot and no producer overwrites a slot with unfinished readers. Derive the final-iteration predicates from that invariant: no next input means no next copy or wait. First test one iteration and a final partial ring before running the full reduction.

Keep the outer K loop rolled, then unroll the fixed fragment loops so constant M/N/K-subtile indices can become register selections. This predicts a smaller instruction body than unrolling all 8 reduction steps while retaining direct fragment access; confirm the compiled local-memory and instruction evidence later. The arrows show legal dependencies, not measured overlap. Likewise, __ldca requests cache-all global weight loads and StoreNoAllocate requests a 128-bit store without L1 allocation; cache residency and throughput remain measurements.

CopyAsync4 emits cp.async.ca.shared.global for four bytes. CopyCommit commits the issuing thread's copies; CopyWait0 waits for that thread's groups. The following CTA-wide ArriveAndWait is still necessary because the consuming lane may read words gathered by another thread. Invalid spatial words are explicitly zero-filled. The gather permutes image coordinates into fragment order; it does not apply an XOR bank swizzle.

06. Trace one token through the source

Fix CTA=(0,0,0), group 2/warp 2, spatial fragment 0, consumer lane 0. Follow token p=(0,0), first through input channel k=64, then through premix u[p,128], hidden panel 0 and final B[p,128]. Other channels and tokens are simultaneously represented by the warp; the trace highlights one dependency chain, not a scalar execution lane.

Milestone 6.1 — Replace the view-conversion pass with a proven gather

First decode channel-plane X into a plain tensor in the baseline. Now write the gather alone and dump its shared words before any MMA. The invariant is that every staged word equals the matching native-fragment word from that baseline, including out-of-field zeros. Tag pixels and channels independently: a swapped x bit or panel bit must fail this test even when constant images pass. Only after all 1,024 staged words match should the copy become asynchronous.

For stage t=1, the four-byte word ordinal j=0 selects local y=0,x=0, source channel panel 4 and component 0. Each panel holds 16 E4 values. The source address is ((4·68+0)·120+0)·16+0 = 522240 bytes. Destination is 4096·(1%2)+4·0 = 4096. Producer warp 0/lane 0 issues this word; consumer warp 2/lane 0 later reads it as the beginning of its uint4 A vector. Thus source panel 4 begins at logical input channel 64 for this precision.

General j=32·producerWarp+lane+128·copyIndex maps y=4⌊j/512⌋+⌊j/64⌋%2+2(j%2), x=4(⌊j/256⌋%2)+⌊j/16⌋%4, panel=4t+2(⌊j/128⌋%2)+⌊j/2⌋%2, component=⌊j/4⌋%4. There are eight copies per thread: 128×8×4=4096 bytes. This is the complete image-to-fragment permutation.

Milestone 6.2 — Implement the premix as a standalone tiled reduction

Keep expansion and contraction disabled. Use a premix matrix with one nonzero entry per selected output, so the expected u identifies exactly one input channel; then try a non-diagonal permutation to detect accidental transposes. The invariant is that every MMA adds the next K contribution to the same token/group accumulator. Milestone 6.3 — Fuse one hidden panel, then repeat the verified unit

Choose expansion/contraction weights that activate only one hidden channel in group 2. First forward premix C/D into A and compare the expanded panel with a separately published reference. Next add the recovered activation and check values below, inside and above the clamp range. Finally contract this one panel into zeroed B. The invariant is that group 2 reads only its own 64 premixed channels and publishes the activated working-format operand before contraction. Once one panel matches, iterate eight panels while keeping B live; nonzero weights in only the last panel catch an early reset or missing final contribution.

Group 2 expansion begins at (262144+2·16384)·1=294,912 bytes; contraction begins at (393216+2·16384)·1=425,984. The record lays out all expansions before all contractions. It does not interleave them per group. LoadWindowFfnInputFragment maps premix C/D words into the next A operand. It converts Half pairs with PackHalfPairsE4 and joins adjacent N16 panels. The first word packs D words 0 and 2, and the next word packs 1 and 3, preserving token row while joining channel groups. No global u store is involved.

For each of eight hidden panels, the activation first clamps a copy b=clamp(x,−4,4), then uses two Half FMAs and a final Half multiply to evaluate x·(b·(−0.055908203125·abs(b)+0.447265625)+0.89453125). The original x, not clamped b, is the final multiplier. This is the recovered activation, not a library SiLU. Publish the activated hidden panel in E4 before its contraction; changing this quantization point changes the model's arithmetic.

Validate the completed candidate against its predictions

The milestones above are a reconstruction plan, not a report that alternative kernels were implemented or benchmarked. Compile the final candidate and check the predicted instructions, physical resources and memory traffic against the recorded capture. A mismatch is a reason to revisit an assumption: local loads may reveal a spilled fragment array; an unexpected lane permutation may reveal a layout conversion; different Half instructions may reveal contraction. A final-candidate capture can identify remaining bottlenecks, but attributing a speedup to a design choice requires a matched baseline experiment.

The explicitly managed storage is global allocations, shared stages and per-lane registers. L2 and L1 are hardware-managed caches on relevant accesses. Shared A vectors are loaded with ordinary aligned uint4 dereferences; there is no ldmatrix instruction or extra XOR shared-memory swizzle in these entry bodies. Bank indexing for a 32-bit word is (byteOffset/4)%32. A 16-byte lane vector spans four banks. Repeated bank indices across a whole warp do not alone prove serialization: the actual instruction's transaction decomposition and broadcast behavior matter.

The working storage format on this page is E4M3 FP8. Tensor-core accumulation, residual products, the recovered activation and the reduction trees discussed here use packed Half words. A uint32_t is a bit container for two Half values, not an integer approximation to their sum. HalfMul, HalfAdd and HalfFma express packed-Half source operations; replacing them with FP32 expressions and a final cast changes that arithmetic. However, ordinary CUDA Half intrinsics can be contracted by the compiler. Helper names alone do not prove a separate rounding boundary: the source-correlated SASS below establishes the actual compiled operations. E4 publication calls PackHalfPairsE4 on two Half2 words and produces four bytes. DecodeE4 performs the reverse operand preparation when a residual must participate in Half arithmetic. There is no scale tensor passed to those conversions.

Start with a high-precision scalar oracle to validate which input contributes to which output. Once the connectivity is correct, introduce a second oracle that follows the source’s K chunk order and publication points. A scalar FP32 sum is not a bitwise reference for Half MMA; it is a tool for catching transposes, wrong groups and wrong spatial coordinates. Keep these two correctness goals separate throughout reconstruction.

Reconstruct and check in dependency order

  1. Start with separate scalar premix/expand/contract tensors and identity or permutation matrices; distinguish every group.
  2. Validate the worked input, shared and output byte offsets with tagged elements before adding MMA.
  3. Compare source-ordered Half arithmetic and each operand publication boundary; an FP32 sum is not a bitwise MMA oracle.
  4. Exercise both grid-Z slabs, the final four real rows, singleton input policy, and every stage wrap.

These are reconstruction checks, not a claim that this documentation build ran them. Match layouts and numerical order first; use the attached capture and its exact launch conditions when evaluating performance.

A global allocation is device memory addressed by a pointer; loads can be served by hardware-managed L2 and, depending on the instruction, L1. A cache hit is not another program-visible tensor and the source does not guarantee cache residency. __ldca permits caching at all levels; __ldcg and PTX .cg select global-level caching that bypasses L1. An eviction or no_allocate hint is a performance policy, not a publication barrier.

Shared memory is an explicitly indexed block-local allocation. Another warp may read a producer's values only after the required block barrier or completed asynchronous-copy protocol. A warp shuffle exchanges register values among its active lanes; it does not address shared memory. Arrays named r_… express per-thread values, but only compiler output establishes whether they stay in physical registers or spill to local memory. Tensor-core accumulator fragments are also register operands. These kernels use mma.sync, not TMEM.

57				const int g_LocalX = ((sl_Word / 256) % 2) * 4 + (sl_Word / 16) % 4;
58				const int g_Y = Parameters.Height == 1 ? 0 : TileCoordinates.g_TileY * 4 + g_LocalY;
59				const int g_X = Parameters.Width == 1 ? 0 : TileCoordinates.g_TileX * 4 + g_LocalX;
60				const int g_ChannelPack = ReductionTile * 4 + ((sl_Word / 128) % 2) * 2 + (sl_Word / 2) % 2;
61				const int g_Component = (sl_Word / 4) % 4;
62				const int s_Destination = (ReductionTile % 2) * 4096 + sl_Word * 4;
63				if (g_Y < Parameters.Height && g_X < Parameters.Width)
64				{
65					const uint64_t g_Source =
66						Parameters.g_Input +
67						uint64_t((g_ChannelPack * Parameters.Height + g_Y) * Parameters.Width + g_X) * 16 +
68						g_Component * 4;
69					CopyAsync4(s_Storage, s_Destination, g_Source);
70				}
71				else
72					*reinterpret_cast<uint32_t*>(s_Storage + s_Destination) = 0;
73			}
74			CopyCommit();
75		}
76	};
77
78	// Wait for the selected shared-memory stage before its fragments are consumed.
79	const auto WaitInput = [&](int ReductionTile)
80	{
81		const int s_BarrierOffset = 8192 + (ReductionTile % 2) * 8;
82		CopyWait0();
83		ArriveAndWait(s_Storage, s_BarrierOffset);
84	};
85
86	// Prime the weight registers and input pipeline before entering the reduction loop.
87	LoadWeights(0);
88	IssueInput(0);
89	WaitInput(0);
90	FMmaAccumulatorTile<Profile::SpatialFragments, 4> r_Projected{};
91
92	// Two-stage pipeline: issue the next input before current MMA work, then
93	// fetch its weights and wait. The final iteration neither refills nor waits.
94	#pragma unroll 1
95	for (int ReductionTile = 0; ReductionTile < Profile::ReductionTiles; ++ReductionTile)
96	{
97		if (ReductionTile + 1 < Profile::ReductionTiles)
98		{
99			IssueInput(ReductionTile + 1);
100		}
101
102		uint4 r_Input[Profile::SpatialFragments][2];
103		#pragma unroll
104		for (int r_Spatial = 0; r_Spatial < Profile::SpatialFragments; ++r_Spatial)
105			#pragma unroll
106			for (int r_KSubtile = 0; r_KSubtile < 2; ++r_KSubtile)
107				r_Input[r_Spatial][r_KSubtile] = *reinterpret_cast<const uint4*>(
108					s_Storage + (ReductionTile % 2) * 4096 +
109					(bFp8 && !bInputView ? (TileCoordinates.Warp / 4) * 2048 : 0) + r_Spatial * 1024 +
110					r_KSubtile * 512 + TileCoordinates.Lane * 16);
111		AccumulateTile<Profile::Precision>(r_Projected, r_Input, r_Weights);
112		if (ReductionTile + 1 < Profile::ReductionTiles)
113		{
114			LoadWeights(ReductionTile + 1);
115			WaitInput(ReductionTile + 1);
116		}
117	}
118
119	FMmaAccumulatorTile<Profile::SpatialFragments, 4> r_Output{};
120
121	// Grouped MLP keeps each hidden panel in registers through expansion and contraction.
122	const uint64_t g_Expand = Parameters.g_PackedWeights +
123							  (262144 + TileCoordinates.g_ExpertGroup * 16384) * Profile::ElementBytes +
124							  TileCoordinates.Lane * 16;
125	const uint64_t g_Contract = Parameters.g_PackedWeights +
126								(393216 + TileCoordinates.g_ExpertGroup * 16384) * Profile::ElementBytes +
127								TileCoordinates.Lane * 16;
128
129	// Hidden activations stay in registers. Processing 32 hidden channels at a
130	// time avoids materializing the 256-channel intermediate in shared/global memory.
131	#pragma unroll 1
132	for (int HiddenTileIndex = 0; HiddenTileIndex < 8; ++HiddenTileIndex)
133	{
134		FMmaAccumulatorTile<Profile::SpatialFragments, 2> r_Hidden{};
135		#pragma unroll
136		for (int r_KPair = 0; r_KPair < 2; ++r_KPair)
137		{
138			{
139				uint4 r_Input[Profile::SpatialFragments], r_Weights[2];
140				#pragma unroll
141				for (int r_Spatial = 0; r_Spatial < Profile::SpatialFragments; ++r_Spatial)
142					r_Input[r_Spatial] = LoadWindowFfnInputFragment<true>(r_Projected, r_Spatial, r_KPair);
143				#pragma unroll
144				for (int r_NTile = 0; r_NTile < 2; ++r_NTile)
145					r_Weights[r_NTile] = __ldca(reinterpret_cast<const uint4*>(
146						g_Expand + HiddenTileIndex * 1024 + r_KPair * 8192 + r_NTile * 512));
147				AccumulateWindowFfnSingleFp8(r_Hidden, r_Input, r_Weights);
148			}
149		}
150
151		#pragma unroll
152		for (int r_Spatial = 0; r_Spatial < Profile::SpatialFragments; ++r_Spatial)
153			#pragma unroll
154			for (int r_NTile = 0; r_NTile < 2; ++r_NTile)
155				#pragma unroll
156				for (int r_Word = 0; r_Word < 4; ++r_Word)
157					r_Hidden.r_AccumulatorWords[r_Spatial][r_NTile][r_Word] =
158						FfnActivation(r_Hidden.r_AccumulatorWords[r_Spatial][r_NTile][r_Word]);
159
160		{
161			uint4 r_Input[Profile::SpatialFragments], r_Weights[4];
162			#pragma unroll
163			for (int r_Spatial = 0; r_Spatial < Profile::SpatialFragments; ++r_Spatial)
164				r_Input[r_Spatial] = LoadWindowFfnInputFragment<true>(r_Hidden, r_Spatial, 0);
165			#pragma unroll
166			for (int r_NTile = 0; r_NTile < 4; ++r_NTile)
167				r_Weights[r_NTile] = __ldca(
168					reinterpret_cast<const uint4*>(g_Contract + HiddenTileIndex * 2048 + r_NTile * 512));
169			AccumulateWindowFfnSingleFp8(r_Output, r_Input, r_Weights);
170		}
171	}
172
173	// Publish contracted expert fragments only for valid spatial tiles.
174	#pragma unroll
175	for (int r_Spatial = 0; r_Spatial < Profile::SpatialFragments; ++r_Spatial)
176	{
177		const int g_Y =
178			TileCoordinates.g_TileY + (bFp8 && !bInputView ? TileCoordinates.Warp / 4 : r_Spatial / 2);
179		const int g_X = TileCoordinates.g_TileX + (bFp8 && !bInputView ? r_Spatial : r_Spatial % 2);
180		if (g_Y >= TileCoordinates.g_TilesHigh || g_X >= TileCoordinates.g_TilesWide)
181			continue;
182		const uint64_t g_OutputTileBase =
183			Parameters.g_Output +
184			uint64_t(g_Y * TileCoordinates.g_TilesWide + g_X) * Profile::SpatialTileBytes +
185			TileCoordinates.g_ExpertGroup * 1024 * Profile::ElementBytes + TileCoordinates.Lane * 16;
186		#pragma unroll
187		for (int r_NTile = 0; r_NTile < (bFp8 ? 2 : 4); ++r_NTile)
188			StoreNoAllocate(g_OutputTileBase + r_NTile * 512,
189							LoadWindowFfnInputFragment<bFp8>(r_Output, r_Spatial, r_NTile));
190	}
191#else
192	// Keep the exported entry on older targets, but never silently skip FP8 work.
193	__trap();
194#endif
195}

01. The model operation this kernel must implement

window_ffn_input_view_c512_fp8 implements the premix and grouped MLP portion of a C512 FFN. It receives channel-plane X with logical shape [H,W,512] and produces the contracted branch tensor B of the same shape. This is record 23’s entry, immediately after the C256 encoder transition; its input-view addressing is a central part of the kernel. At the documented 4K geometry H=68 and W=120. Its output still needs a separate 512→512 postmix and scaled residual before becoming the block’s FFN result. Neither attention nor that postmix is silently included here.

The network architecture guide, rendered from docs/ARCHITECTURE.md, places this operation in the full encoder–bottleneck–decoder. This lesson defines the operation and its physical implementation locally so it can be read independently.

For one position p, compute u[p,:] = X[p,:] Wpre. Partition the 512 premixed channels into eight distinct slices u[p,64g:64g+64]. Group g computes B[p,64g:64g+64] = φ(u_g Wexpand_g) Wcontract_g, with matrices [64,256] and [256,64]. All eight groups execute. The first matrix is [512,512]; its purpose is to mix original channels before slicing. This differs from a full-input branch model: each grouped expansion reads only its own 64 premixed channels.

02. Build the simplest correct graph before tiling it

A first implementation can materialize u, a [H,W,8,256] hidden tensor and B. Assign one scalar output element to a thread and sum its input channels. This makes the grouping unambiguous: contraction for group 3 must read group 3’s hidden values, not any other group. It also exposes the costs we will remove: writing and rereading the dense premix, materializing a four-times-expanded hidden tensor, and fetching the same input vector independently for each output channel.

The working storage format on this page is E4M3 FP8. Tensor-core accumulation, residual products, the recovered activation and the reduction trees discussed here use packed Half words. A uint32_t is a bit container for two Half values, not an integer approximation to their sum. HalfMul, HalfAdd and HalfFma preserve the source’s separately rounded operations; replacing them with FP32 expressions and a final cast changes that contract. E4 publication calls PackHalfPairsE4 on two Half2 words and produces four bytes. DecodeE4 performs the reverse operand preparation when a residual must participate in Half arithmetic. There is no scale tensor passed to those conversions.

Start with a high-precision scalar oracle to validate which input contributes to which output. Once the connectivity is correct, introduce a second oracle that follows the source’s K chunk order and publication points. A scalar FP32 sum is not a bitwise reference for Half MMA; it is a tool for catching transposes, wrong groups and wrong spatial coordinates. Keep these two correctness goals separate throughout reconstruction.

03. Tile output ownership so a group’s intermediates stay local

A CTA covers one 8 × 8 position region and four groups. Grid Z selects groups 0–3 or 4–7, and group ownership is (warp%4)+4·blockIdx.z. The block is (32,4). Each of four warps owns one group and four M16 fragments, so it covers all 64 positions. This input-view profile deliberately retains four warps even with E4 operands. This arrangement makes expansion and contraction warp-local once the premix finishes; no inter-warp hidden exchange is required.

One instruction computes a 16-token × 8-output-channel tile with a reduction of 32 channels. All 32 lanes participate in the same matrix operation. Each lane supplies four 32-bit A words, two 32-bit B words, and two 32-bit C words. Each C word contains two Half accumulators, so a lane owns four output elements. A source loop over output groups or reduction panels repeats this operation; it does not launch a new warp.

The exact instruction on this path is mma.sync.aligned.m16n8k32.row.col.f16.e4m3.e4m3.f16. Both the accumulator input and output are Half. Do not replace its numerical contract with FP32 accumulation when constructing an exact oracle. For the FP8 path, packing to E4M3 is a distinct rounding step; for the FP16 path a packed word simply holds two Half values.

Let lane L run from 0 to 31, g = L // 4 and q = L % 4. The matrix coordinates below describe instruction operands after any kernel-specific loads and shuffles. Storage layouts are designed to supply these coordinates cheaply.

The operand and accumulator coordinates follow the NVIDIA PTX matrix-fragment specification. A kernel may permute model channels before supplying these instruction coordinates; its publication and weight-packing rules must agree.

04. Fuse the input-view conversion into the shared-memory gather

The incoming storage is [channel panel, y, x, 16-byte pixel packet], not a native tile sequence. Each panel contains sixteen E4 channels. A separate transpose baseline would read and write the whole image before any useful matrix multiply. Instead, each CTA constructs exactly the next 4 KiB native input stage with four-byte asynchronous gathers. There are 128 threads and eight word copies per thread: 1,024 words fill the complete stage.

Give each word the ordinal j=warp·32+lane+copyIndex·128. Source local y is 4(j/512)+(j/64)%2+2(j%2); local x is 4((j/256)%2)+(j/16)%4. The source panel is 4t+2((j/128)%2)+(j/2)%2, and the four-byte component is (j/4)%4. Add the CTA’s pixel origin to x/y, and form X+((panel·H+y)·W+x)·16+4·component. Store at shared+4096(t%2)+4j. The expressions are easier to verify as separate bitfield coordinates than as one giant pointer expression.

For j=13, t=0 and origin=(0,0), the gather uses y=2, x=0, panel=0 and component=3. At W=120 the global offset is 3,852 bytes, and the shared offset is 52. The four copied bytes carry four E4 channels; the remainder of the stage gives the consumer its four spatial tiles and two instruction-K panels. Test this exact word before testing an entire matrix.

05. Compute premix once, then stream hidden panels

For a single instruction-K step, an input A fragment is reused across four N16 output panels, and each weight B bundle is reused across the warp’s 4 spatial fragments. That is the first improvement over scalar outputs: input and weight fetches pay for multiple independent MMA results. Four-word accumulators remain live across the full K=512 reduction. When it completes, they already represent the group’s 64 premixed channels in the order needed by the next multiply.

The hidden tensor is the next expensive allocation. We do not need all 256 hidden channels at once: the contraction is a sum over them. Visit eight panels of 32 hidden channels, allocate only that panel’s accumulator, expand from the 64-channel group, activate it, and immediately add its contraction contribution to B. This keeps the complete premix slice and final output but only one hidden panel. The tradeoff is a longer lifetime for output accumulators; the benefit is removing the full hidden image write/read and the premix image write/read.

The packed record contains 262,144 premix elements, then eight 16,384-element expansions, then eight 16,384-element contractions. Group g’s bases are (262144+16384g)·1 and (393216+16384g)·1 bytes. For group 5 these are 344,064 and 475,136 bytes. Add lane·16 and the selected hidden/K/N panel offsets only after selecting that group’s matrix. This prevents the common bug of treating each group’s expansion and contraction as interleaved in the record.

06. Overlap input movement without reusing live bytes

The scalar baseline reloads input independently for each output. Our tiled version first shares an input stripe among output-panel computations. A synchronous prototype can copy a stage, execute a CTA barrier, consume every fragment, then execute a second barrier before overwriting the stage. That establishes correct producer/consumer ownership. The deployed kernel replaces the idle copy phase with a 2-slot ring. A slot holds 4,096 data bytes; its 8-byte barrier lives after all data slots, so the allocation is 2·(4096+8) = 8,208 bytes.

This entry gathers four-byte words from channel planes. CopyAsync4 emits cp.async.ca.shared.global, CopyCommit groups this thread’s outstanding copies, and CopyWait0 waits for that thread’s committed groups. The subsequent ArriveAndWait is still necessary: a lane consuming shared fragments depends on copies issued by other lanes. A per-thread copy wait by itself does not coordinate the CTA. Initialize every stage barrier once with the full CTA arrival count, then synchronize before any copy can refer to it. An out-of-domain stripe is filled with zeros by its lane writers; those threads still join the barrier protocol.

The prologue loads W0, issues X0 and waits for slot zero. Iteration t issues X[t+1] into the other slot before consuming X[t]. It then prefetches W[t+1] and waits on the next slot. Every warp reaches that wait only after reading its current stage, so the later producer phase can recycle it. The final iteration skips both the nonexistent refill and the next wait.

The 8 outer iterations stay rolled in the source, while spatial, N-panel and instruction-K fragment loops unroll. That lets fixed array indices select register values without expanding the entire long reduction into a huge instruction stream. More stages can hide more copy latency but consume shared memory; more fragments improve operand reuse but increase live registers. Those are the relevant tradeoffs, not a claim that a larger ring is always faster. __maxnreg__ supplies a compiler limit, not an observed register count. Inspect generated resource reports and time representative shapes before changing either knob.

07. Publish only the contracted branch tensor

For native output tile q, group g and lane l, the first vector goes to B+q·8192+g·1024+16l. Two E4 vectors per lane cover the 64-channel group; each packs two N16 accumulator groups. For q=7, g=5 and l=13, the first vector address is 62,672 bytes from B. Clip spatial tiles before storing. Every valid output group is written by exactly one warp, so no atomic is necessary.

08. The helper contracts needed to reconstruct this entry

FMmaAccumulatorTile<M,N> contains [M][N][4] 32-bit words per lane. Each N index means sixteen output channels, built from two N8 MMA instructions; it does not mean a sixteen-byte vector in logical row-major order. AccumulateTile takes an array of four-word A fragments and four-word weight bundles, uses the lower two B words for the first N8 result and upper two for the second, and updates the four Half2 words in place. When two instruction-K subtiles exist, it advances each accumulator through subtile zero before subtile one; the FP16 QKV stage supplies only one K16 subtile. The API’s by-value operands ensure an output update does not change the fragment arguments still being evaluated.

StoreNoAllocate emits an aligned 128-bit global store with an L1 no-allocation request. __ldca loads weights with cache-all policy; residual readers may use __ldcg. These are memory-policy choices rather than barriers or promises that an access reaches a particular cache level. A correct implementation must separately satisfy the synchronization protocol and vector alignment. PackHalfPairsE4 changes both element width and which channel pairs occupy the low and high halves of a word. Its order is part of the layout; substituting any four E4 conversions without matching that order is incorrect.

09. A complete reconstruction checklist in executable order

10. Reconstruction checks, in the order they isolate errors

  1. Pack an identity premix and group-distinguishing expansion/contract matrices; prove that group g reads only its own premixed 64 channels and that all eight output groups appear.
  2. Validate the numeric input and output addresses above with a single nonzero token/channel; compare native storage with a decoded logical [H,W,512] view.
  3. Run H=68,W=120 and a small multi-tile shape to exercise an incomplete 8×8 bottom edge; separately exercise the explicitly supported singleton-tile broadcast policy.
  4. Check the j=13 gather and every j=0…1023 mapping for uniqueness and complete stage coverage; distinguish zero-filled invalid words from valid channel-plane reads.
  5. Use values near Half and E4 rounding boundaries to test the premix-publication, post-activation-publication and final-publication locations. Do not validate only with ones.
  6. Use synchronization checking when altering the copy loop; an input stage may be overwritten only after every participating consumer has finished.

These are concrete tests to implement when rebuilding the kernel, not claims that this documentation run executed GPU comparisons. First establish layout and numerical equivalence; then measure latency with the same weights, geometry, precision and stream behavior. A source-level eliminated allocation establishes avoided traffic, but it does not quantify the speedup or prove absence of register spills.

A global allocation is device memory addressed by a pointer; loads can be served by hardware-managed L2 and, depending on the instruction, L1. A cache hit is not another program-visible tensor and the source does not guarantee cache residency. __ldca permits caching at all levels; __ldcg and PTX .cg select global-level caching that bypasses L1. An eviction or no_allocate hint is a performance policy, not a publication barrier.

Shared memory is an explicitly indexed block-local allocation. Another warp may read a producer's values only after the required block barrier or completed asynchronous-copy protocol. A warp shuffle exchanges register values among its active lanes; it does not address shared memory. Arrays named r_… express per-thread values, but only compiler output establishes whether they stay in physical registers or spill to local memory. Tensor-core accumulator fragments are also register operands. These kernels use mma.sync, not TMEM.

55				const int sl_Word = TileCoordinates.Warp * 32 + TileCoordinates.Lane + CopyIndex * 128;
56				const int g_LocalY = (sl_Word / 512) * 4 + (sl_Word / 64) % 2 + (sl_Word % 2) * 2;
57				const int g_LocalX = ((sl_Word / 256) % 2) * 4 + (sl_Word / 16) % 4;
58				const int g_Y = Parameters.Height == 1 ? 0 : TileCoordinates.g_TileY * 4 + g_LocalY;
59				const int g_X = Parameters.Width == 1 ? 0 : TileCoordinates.g_TileX * 4 + g_LocalX;
60				const int g_ChannelPack = ReductionTile * 4 + ((sl_Word / 128) % 2) * 2 + (sl_Word / 2) % 2;
61				const int g_Component = (sl_Word / 4) % 4;
62				const int s_Destination = (ReductionTile % 2) * 4096 + sl_Word * 4;
63				if (g_Y < Parameters.Height && g_X < Parameters.Width)
64				{
65					const uint64_t g_Source =
66						Parameters.g_Input +
67						uint64_t((g_ChannelPack * Parameters.Height + g_Y) * Parameters.Width + g_X) * 16 +
68						g_Component * 4;
69					CopyAsync4(s_Storage, s_Destination, g_Source);
70				}
71				else
72					*reinterpret_cast<uint32_t*>(s_Storage + s_Destination) = 0;
73			}
74			CopyCommit();
75		}
76	};
77
78	// Wait for the selected shared-memory stage before its fragments are consumed.
79	const auto WaitInput = [&](int ReductionTile)
80	{
81		const int s_BarrierOffset = 8192 + (ReductionTile % 2) * 8;
82		CopyWait0();
83		ArriveAndWait(s_Storage, s_BarrierOffset);
84	};
85
86	// Prime the weight registers and input pipeline before entering the reduction loop.
87	LoadWeights(0);
88	IssueInput(0);
89	WaitInput(0);
90	FMmaAccumulatorTile<Profile::SpatialFragments, 4> r_Projected{};
91
92	// Two-stage pipeline: issue the next input before current MMA work, then
93	// fetch its weights and wait. The final iteration neither refills nor waits.
94	#pragma unroll 1
95	for (int ReductionTile = 0; ReductionTile < Profile::ReductionTiles; ++ReductionTile)
96	{
97		if (ReductionTile + 1 < Profile::ReductionTiles)
98		{
99			IssueInput(ReductionTile + 1);
100		}
101
102		uint4 r_Input[Profile::SpatialFragments][2];
103		#pragma unroll
104		for (int r_Spatial = 0; r_Spatial < Profile::SpatialFragments; ++r_Spatial)
105			#pragma unroll
106			for (int r_KSubtile = 0; r_KSubtile < 2; ++r_KSubtile)
107				r_Input[r_Spatial][r_KSubtile] = *reinterpret_cast<const uint4*>(
108					s_Storage + (ReductionTile % 2) * 4096 +
109					(bFp8 && !bInputView ? (TileCoordinates.Warp / 4) * 2048 : 0) + r_Spatial * 1024 +
110					r_KSubtile * 512 + TileCoordinates.Lane * 16);
111		AccumulateTile<Profile::Precision>(r_Projected, r_Input, r_Weights);
112		if (ReductionTile + 1 < Profile::ReductionTiles)
113		{
114			LoadWeights(ReductionTile + 1);
115			WaitInput(ReductionTile + 1);
116		}
117	}
118
119	FMmaAccumulatorTile<Profile::SpatialFragments, 4> r_Output{};
120
121	// Grouped MLP keeps each hidden panel in registers through expansion and contraction.
122	const uint64_t g_Expand = Parameters.g_PackedWeights +
123							  (262144 + TileCoordinates.g_ExpertGroup * 16384) * Profile::ElementBytes +
124							  TileCoordinates.Lane * 16;
125	const uint64_t g_Contract = Parameters.g_PackedWeights +
126								(393216 + TileCoordinates.g_ExpertGroup * 16384) * Profile::ElementBytes +
127								TileCoordinates.Lane * 16;
128
129	// Hidden activations stay in registers. Processing 32 hidden channels at a
130	// time avoids materializing the 256-channel intermediate in shared/global memory.
131	#pragma unroll 1
132	for (int HiddenTileIndex = 0; HiddenTileIndex < 8; ++HiddenTileIndex)
133	{
134		FMmaAccumulatorTile<Profile::SpatialFragments, 2> r_Hidden{};
135		#pragma unroll
136		for (int r_KPair = 0; r_KPair < 2; ++r_KPair)
137		{
138			{
139				uint4 r_Input[Profile::SpatialFragments], r_Weights[2];
140				#pragma unroll
141				for (int r_Spatial = 0; r_Spatial < Profile::SpatialFragments; ++r_Spatial)
142					r_Input[r_Spatial] = LoadWindowFfnInputFragment<true>(r_Projected, r_Spatial, r_KPair);
143				#pragma unroll
144				for (int r_NTile = 0; r_NTile < 2; ++r_NTile)
145					r_Weights[r_NTile] = __ldca(reinterpret_cast<const uint4*>(
146						g_Expand + HiddenTileIndex * 1024 + r_KPair * 8192 + r_NTile * 512));
147				AccumulateWindowFfnSingleFp8(r_Hidden, r_Input, r_Weights);
148			}
149		}
150
151		#pragma unroll
152		for (int r_Spatial = 0; r_Spatial < Profile::SpatialFragments; ++r_Spatial)
153			#pragma unroll
154			for (int r_NTile = 0; r_NTile < 2; ++r_NTile)
155				#pragma unroll
156				for (int r_Word = 0; r_Word < 4; ++r_Word)
157					r_Hidden.r_AccumulatorWords[r_Spatial][r_NTile][r_Word] =
158						FfnActivation(r_Hidden.r_AccumulatorWords[r_Spatial][r_NTile][r_Word]);
159
160		{
161			uint4 r_Input[Profile::SpatialFragments], r_Weights[4];
162			#pragma unroll
163			for (int r_Spatial = 0; r_Spatial < Profile::SpatialFragments; ++r_Spatial)
164				r_Input[r_Spatial] = LoadWindowFfnInputFragment<true>(r_Hidden, r_Spatial, 0);
165			#pragma unroll
166			for (int r_NTile = 0; r_NTile < 4; ++r_NTile)
167				r_Weights[r_NTile] = __ldca(
168					reinterpret_cast<const uint4*>(g_Contract + HiddenTileIndex * 2048 + r_NTile * 512));
169			AccumulateWindowFfnSingleFp8(r_Output, r_Input, r_Weights);
170		}
171	}
172
173	// Publish contracted expert fragments only for valid spatial tiles.
174	#pragma unroll
175	for (int r_Spatial = 0; r_Spatial < Profile::SpatialFragments; ++r_Spatial)
176	{
177		const int g_Y =
178			TileCoordinates.g_TileY + (bFp8 && !bInputView ? TileCoordinates.Warp / 4 : r_Spatial / 2);
179		const int g_X = TileCoordinates.g_TileX + (bFp8 && !bInputView ? r_Spatial : r_Spatial % 2);
180		if (g_Y >= TileCoordinates.g_TilesHigh || g_X >= TileCoordinates.g_TilesWide)
181			continue;
182		const uint64_t g_OutputTileBase =
183			Parameters.g_Output +
184			uint64_t(g_Y * TileCoordinates.g_TilesWide + g_X) * Profile::SpatialTileBytes +
185			TileCoordinates.g_ExpertGroup * 1024 * Profile::ElementBytes + TileCoordinates.Lane * 16;
186		#pragma unroll
187		for (int r_NTile = 0; r_NTile < (bFp8 ? 2 : 4); ++r_NTile)
188			StoreNoAllocate(g_OutputTileBase + r_NTile * 512,
189							LoadWindowFfnInputFragment<bFp8>(r_Output, r_Spatial, r_NTile));
190	}
191#else
192	// Keep the exported entry on older targets, but never silently skip FP8 work.
193	__trap();
194#endif
195}

01. The model operation: QKV and complete local attention

window_qkv_c512_fp8 consumes published C512 FFN output Z and produces attended features A, both logically [H,W,512]. It is used in C512 records 23–30 and 40–47. At 4K H=68,W=120. The kernel contains the [512,1536] QKV projection, sixteen 32-channel heads, separate Q/K channel normalization, per-window score normalization, and probability-times-value. It does not contain the later C512 head-mixing projection or attention residual. The model’s complete attention operation therefore spans this entry and a subsequent projection entry.

The network architecture guide, rendered from docs/ARCHITECTURE.md, places this operation in the full encoder–bottleneck–decoder. This lesson defines the operation and its physical implementation locally so it can be read independently.

Within one 8 × 8 window/head, Q,K,V each have shape [64,32]. Q and K are independently L2-normalized across their 32 channels, Q receives its learned head scalar, and V bypasses normalization. Scores are S=QKᵀ+bias, shape [64,64]. Compute P[i,j]=E(S[i,j])/Σk E(S[i,k]), then A=PV. E is the recovered clamped exponential surrogate, not exp(score−maximum) from a standard softmax implementation. Unlike global C1024 attention, this local Q path has no extra √32 factor and no correction removing padded key slots from the denominator.

02. A deliberately materialized attention baseline

Begin with separate kernels for QKV, Q/K normalization, scores, normalization and P×V. This gives explicit tensors that are easy to inspect. Use a single window and one head first, giving every token a recognizable channel vector. The cost is substantial intermediate traffic: QKV has three times the input channel count, and each head’s score tensor contains 4,096 values. Fusion will replace these intermediate allocations with warp register tensors, but only after their indexing and quantization points are established.

The working storage format on this page is E4M3 FP8. Tensor-core accumulation, residual products, the recovered activation and the reduction trees discussed here use packed Half words. A uint32_t is a bit container for two Half values, not an integer approximation to their sum. HalfMul, HalfAdd and HalfFma preserve the source’s separately rounded operations; replacing them with FP32 expressions and a final cast changes that contract. E4 publication calls PackHalfPairsE4 on two Half2 words and produces four bytes. DecodeE4 performs the reverse operand preparation when a residual must participate in Half arithmetic. There is no scale tensor passed to those conversions.

Start with a high-precision scalar oracle to validate which input contributes to which output. Once the connectivity is correct, introduce a second oracle that follows the source’s K chunk order and publication points. A scalar FP32 sum is not a bitwise reference for Half MMA; it is a tool for catching transposes, wrong groups and wrong spatial coordinates. Keep these two correctness goals separate throughout reconstruction.

03. Put an entire head/window inside one warp

A CTA has four warps and one phase-dependent 8 × 8 window. Warp w owns head h=4·blockIdx.z+w; four grid-Z slabs cover all sixteen heads. Its six N16 projection panels are Q-low,Q-high,K-low,K-high,V-low,V-high, over four M16 spatial fragments. Because all 64 Q/K/V positions for that head belong to this warp, attention requires only register reuse and shuffles after the QKV reduction. Assigning one token per warp would instead force expensive exchange to reach the other 63 keys.

The origin in each axis is zero or −4 according to the window phase. TileY is (8·blockIdx.y+OriginY)/4, tileX is the analogous X expression. Four native 4 × 4 tiles make the window. For the first phase-1 CTA, the origin is (−4,−4); only its lower-right native tile is inside the field. Inputs outside the field become zeros, but all 64 key slots still participate in local normalization. Store clipping removes only invalid query positions. This is padding and cropping, not a cyclic image roll.

One instruction computes a 16-token × 8-output-channel tile with a reduction of 32 channels. All 32 lanes participate in the same matrix operation. Each lane supplies four 32-bit A words, two 32-bit B words, and two 32-bit C words. Each C word contains two Half accumulators, so a lane owns four output elements. A source loop over output groups or reduction panels repeats this operation; it does not launch a new warp.

The exact instruction on this path is mma.sync.aligned.m16n8k32.row.col.f16.e4m3.e4m3.f16. Both the accumulator input and output are Half. Do not replace its numerical contract with FP32 accumulation when constructing an exact oracle. For the FP8 path, packing to E4M3 is a distinct rounding step; for the FP16 path a packed word simply holds two Half values.

Let lane L run from 0 to 31, g = L // 4 and q = L % 4. The matrix coordinates below describe instruction operands after any kernel-specific loads and shuffles. Storage layouts are designed to supply these coordinates cheaply.

The operand and accumulator coordinates follow the NVIDIA PTX matrix-fragment specification. A kernel may permute model channels before supplying these instruction coordinates; its publication and weight-packing rules must agree.

Under the microscope: what exactly enters one MMA?

For lane L, let g=L//4 and q=L%4. The highlighted A scalar uses g=3,q=1; B uses g=2,q=1. The output scalar uses g=3,q=1 again. These are three operand ownership maps, not a chain of thread-to-thread scalar multiplies. The selected result is the low Half of D word 0. For a pointwise projection, the row stays the same model token and N labels learned output channels; in QKᵀ, N instead labels key tokens.

In this repository’s native E4 activation packing, instruction K=4 corresponds to model channel 2: packed_input_index(4)=2. The packed weights use the matching inverse permutation. A physical byte labeled K=4 must not be read as model channel 4. For probability-times-value, apply the same distinction to the key axis.

04. Derive byte addresses before writing the fast loop

A native input tile represents sixteen positions in a physical 4 × 4 image patch. Its byte extent is 16·512·1 = 8,192. Tile index q advances by that whole extent, an instruction-K stripe advances by 512 bytes, and lane l selects 16·l bytes within the stripe. Thus one A load is input + q·8192 + stripe·512 + lane·16. For q=7, stripe=1 and lane=13, the base-relative address is 58,064 bytes. The lane reads one uint4 containing sixteen E4 values. These values are already arranged as a matrix operand; they are not simply consecutive channels of one pixel.

The weight record groups output columns into N16 panels and reduction channels into K32 instruction slices. Each instruction slice consumes 32·1=32 bytes per output column. Its lane-vector address is W + reductionStart·1536·1 + outputChannel·32 + lane·16 + panel·512. For reductionStart=32, outputChannel=192, panel=1 and lane=13, this is 56,016 bytes. The panel term is relative to the warp’s output base. Adding a complete K slice advances 49,152 bytes, not 512: 512 advances N16, while 49,152 advances all 1536 output columns.

Write a small host-side address decoder first. Give each logical input element a distinguishable value, encode a single native tile, and check exactly which token/channel arrives in each lane word. Repeat for one weight panel. This isolates layout errors from arithmetic errors: a wrong transpose can still produce plausible values for uniform inputs. In the kernel, all these pointer expressions use byte offsets because the public ABI passes integer addresses rather than typed multidimensional tensor views.

The actual QKV stage packs two K32 input stripes for every spatial tile, so one stage advances 64 channels. Its weight head base is head·3072, since 96 head-local output channels each occupy 32 packed bytes per instruction-K slice. The N16 panel stride is 512 bytes. The second K32 inside a stage adds 49,152 bytes, which is 1536×32. Do not substitute the two-K Half schedule used by other C512 matrix entries: this named QKV entry has its own blocking.

05. Give bias and head scales their own precision/address contracts

The matrix occupies 3·512·512·1 = 786,432 bytes. It is followed by sixteen 8,192-byte Half bias tables, each representing [64 query,64 key] values in packed fragment order. The head scales follow those tables as sixteen four-byte floating values. QKV conversion loads a scale’s float bits and rounds it to replicated Half2 for the normalization multiply. Thus the record contains E4 matrix bytes, Half bias and float head scales rather than one uniform scalar type.

For query tile q, key tile j, head h and lane l, the bias vector is at W+786432+8192h+2048q+512j+16l. With h=2,q=1,j=3,l=13, the byte offset is 806,608. The scale for head 2 is at 917,512. Seed score accumulators with bias before adding QKᵀ; the Half rounding order depends on that placement. K and V use matching recovered physical key order, and bias columns are already packed to match it.

06. Overlap input movement without reusing live bytes

The scalar baseline reloads input independently for each output. Our tiled version first shares an input stripe among output-panel computations. A synchronous prototype can copy a stage, execute a CTA barrier, consume every fragment, then execute a second barrier before overwriting the stage. That establishes correct producer/consumer ownership. The deployed kernel replaces the idle copy phase with a 2-slot ring. A slot holds 4,096 data bytes; its 8-byte barrier lives after all data slots, so the allocation is 2·(4096+8) = 8,208 bytes.

CopyBulk accepts a shared byte offset, a global address, byte count and barrier offset. On SM90+ it uses a bulk asynchronous copy with transaction-byte completion and an elected producer; BarrierExpect registers the expected bytes. On supported earlier targets the helper distributes 16-byte copies across warp lanes and attaches their completion to the mbarrier. BarrierExpect is then intentionally a no-op because that path does not use the transaction-byte mechanism. Initialize every stage barrier once with the full CTA arrival count, then synchronize before any copy can refer to it. An out-of-domain stripe is filled with zeros by its lane writers; those threads still join the barrier protocol.

The prologue loads W0, issues X0 and waits for slot zero. Iteration t issues X[t+1] into the other slot before consuming X[t]. It then prefetches W[t+1] and waits on the next slot. Every warp reaches that wait only after reading its current stage, so the later producer phase can recycle it. The final iteration skips both the nonexistent refill and the next wait.

The 8 outer iterations stay rolled in the source, while spatial, N-panel and instruction-K fragment loops unroll. That lets fixed array indices select register values without expanding the entire long reduction into a huge instruction stream. More stages can hide more copy latency but consume shared memory; more fragments improve operand reuse but increase live registers. Those are the relevant tradeoffs, not a claim that a larger ring is always faster. __maxnreg__ supplies a compiler limit, not an observed register count. Inspect generated resource reports and time representative shapes before changing either knob.

Shared-memory address bits and banks

The layout already matches uint4 fragment loads. A producer places lane L’s four words at panel+16L, and the consumer reads that same vector. No lane XOR row transformation is applied here. The 32-bank, four-byte-word model follows the CUDA shared-memory bank description. A bank-conflict diagnosis must use the emitted instruction and its transaction grouping; the same bank number across a whole warp is insufficient evidence.

07. Turn projected Half words into normalized operand fragments

The QKV result is r_Projected[4][6][4] words per lane. Assign pairs of N16 groups to three [32-channel] accumulator views; this is a register rearrangement, not a global transpose. For a token, four adjacent lanes collectively hold all 32 channels. In each lane, four Half2 words represent channel pairs offset by 8. The norm helper squares upper channels first, fuses lower-channel squares into them, combines column groups, then uses XOR-2 and XOR-1 shuffles across the four lanes.

Swapping the packed Half components and adding makes a replicated scalar squared norm. Clamp it to Half epsilon 0x0410 = 0.00006198883056640625, convert one Half to float, evaluate approximate reciprocal square root, round that inverse to Half2, and multiply each channel pair. Q then multiplies its learned scale. The helper NormalizeWindow<true> applies the scale; <false> does not. This reduces channels, not tokens or heads. A generic LayerNorm, RMSNorm or four-warp reduction would implement a different operation.

08. Stream query panels through scores, denominator and values

For sixteen query rows, allocate eight N8 score columns, covering all 64 keys. The score accumulator is 16×64 Half values distributed as sixteen words per lane. Bias seeds these words. Score MMA consumes the query and each key tile in one K32 chunk because head width is 32. The exponential helper computes a Half FMA with slope 0.044921875 and intercept 1.30078125, clamps to [1.03125,1.5693359375], then evaluates (packedClampedBits<<5)+0x7ff88000 with 32-bit wraparound. The denominator uses the same Half epsilon 0x0410 before its reciprocal. Keep that whole-word operation: independent shifts of the two halfwords alter carry behavior.

This E4 entry uses a paired-query schedule. It produces two adjacent sixteen-query panels, then SoftmaxWindowPair normalizes their 32 logical rows together. An independent-panel baseline repeats each denominator reciprocal in four lanes. The paired schedule instead transposes four row-half partial vectors so each lane owns one complete row sum, computes one reciprocal there, and shuffles it back to the four lanes holding that row’s score fragments. This saves duplicate scalar inverse work without changing the key contribution order.

The transpose first permutes the four local partial words by lane&3. Its source lane is ((lane&7)<<2)|(lane>>3), and four XOR-indexed gathers collect the contributors. A second permutation restores contributor order 0,1,2,3 before Half addition. Lane 13 uses base source 21 and owns logical row 13. After the reciprocal, vector r at an original lane fetches inverse from 8r+lane/4. This is an ownership transformation for row sums, not a change in the score matrix’s mathematical axes.

Publication of P is another explicit boundary: normalized Half scores become E4 K32 A operands before P×V. The reduction now spans 64 key positions, requiring two K32 chunks. The meaning of the MMA axes changes inside attention

09. Return the attended head panels to global tile storage

For native spatial tile q, head h, chunk r and lane l, output is A+q·8192+h·512+512r+16l. There is one E4 fragment per 32-channel head. With q=7,h=2,r=0,l=13, the first vector starts at 58,576 bytes. Heads write disjoint channel regions and windows write disjoint real query tiles for the selected phase. Clip both negative and upper tile coordinates; do not allow the zero-padded query slots to write before the allocation.

10. The helper contracts needed to reconstruct this entry

FMmaAccumulatorTile<M,N> contains [M][N][4] 32-bit words per lane. Each N index means sixteen output channels, built from two N8 MMA instructions; it does not mean a sixteen-byte vector in logical row-major order. AccumulateTile takes an array of four-word A fragments and four-word weight bundles, uses the lower two B words for the first N8 result and upper two for the second, and updates the four Half2 words in place. When two instruction-K subtiles exist, it advances each accumulator through subtile zero before subtile one; the FP16 QKV stage supplies only one K16 subtile. The API’s by-value operands ensure an output update does not change the fragment arguments still being evaluated.

12. Reconstruction checks, in the order they isolate errors

  1. With zero Q/K matrices, use varying bias and V to verify the recovered exponential and normalized value weighting independently of projection.
  2. With distinct head scales, distinguish every one of sixteen heads and both N16 halves of Q/K/V; confirm Q receives scale while K and V do not.
  3. Test all four origin phases, especially the first shifted window and H=68’s incomplete final 8×8 row. Padded keys remain in the local denominator.
  4. Trace one lane-owned norm using asymmetric channel magnitudes; compare its source-ordered Half sum and reciprocal-square-root path. Uniform vectors conceal channel permutation mistakes.
  5. For the paired path, give all 32 query rows different denominators, then verify lane 13 and the 8r+lane/4 reciprocal broadcast. Test the second pair separately.
  6. Use rounding-sensitive probabilities to prove P is published before P×V, and compare decoded global output against the independently reconstructed head tensor.

These are concrete tests to implement when rebuilding the kernel, not claims that this documentation run executed GPU comparisons. First establish layout and numerical equivalence; then measure latency with the same weights, geometry, precision and stream behavior. A source-level eliminated allocation establishes avoided traffic, but it does not quantify the speedup or prove absence of register spills.

A global allocation is device memory addressed by a pointer; loads can be served by hardware-managed L2 and, depending on the instruction, L1. A cache hit is not another program-visible tensor and the source does not guarantee cache residency. __ldca permits caching at all levels; __ldcg and PTX .cg select global-level caching that bypasses L1. An eviction or no_allocate hint is a performance policy, not a publication barrier.

Shared memory is an explicitly indexed block-local allocation. Another warp may read a producer's values only after the required block barrier or completed asynchronous-copy protocol. A warp shuffle exchanges register values among its active lanes; it does not address shared memory. Arrays named r_… express per-thread values, but only compiler output establishes whether they stay in physical registers or spill to local memory. Tensor-core accumulator fragments are also register operands. These kernels use mma.sync, not TMEM.

01. The whole problem

window_qkv_c512_fp8 fuses C512 QKV projection and complete window attention for records 23–30 and 40–47. Its input is published FFN output Z[68,120,512] at 4K; its output A has the same shape. It contains Wqkv[512,1536], sixteen heads of width 32, Q/K channel normalization, learned query scaling, score normalization, and P×V. A separate attention projection/residual kernel follows.

The network architecture guide places this operation in the full encoder–bottleneck–decoder. This lesson defines the operation and its physical implementation locally so it can be read independently.

For each 8×8 window and head, Q,K,V are [64 tokens,32 channels]. Normalize Q and K independently across channels, multiply Q by its learned scalar, and compute S=QKᵀ+bias, shape [64,64]. The recovered E(S)/rowSum(E(S)) creates P, then A=PV. E is a clamped packed-bit exponential surrogate, not standard exp(score−max). This local path has no extra √32 multiplier and retains zero-padded key slots in its denominator.

02. One CTA: its concrete subproblem

One CTA owns a phase-dependent 8×8 window and four complete heads: four warps, 128 threads. Grid Z has four slabs; head=4·blockIdx.z+warp. For unshifted H=68,W=120, the logical coverage is 15×9 windows and four head slabs, 540 CTAs. A −4 X origin uses ceil((120+4)/8)=16 columns; a −4 Y origin still uses ceil((68+4)/8)=9 rows. Thus X-shifted phases launch 576 CTAs and unshifted-X phases launch 540, with four head slabs in each case. This is padding/cropping, not a cyclic image roll.

CTA (0,0,0) at origin (0,0) consumes pixels 0…7 and supplies heads 0…3. At origin (−4,−4), only its lower-right native 4×4 tile lies in the field. Input predicates zero-fill invalid tiles; invalid query tiles do not store. The fixed 64-key attention computation still includes the padded key slots.

03. Warp and thread ownership

A warp owns all 64 tokens for one head, allowing later attention to remain warp-local. Six N16 projection panels are Q-low,Q-high,K-low,K-high,V-low,V-high. The four M16 spatial fragments are top-left, top-right,bottom-left,bottom-right native tiles. Warp 2/head 2 owns the traced token's full Q/K/V head; other warps compute other heads from shared copies of the same input.

One warp's result has 4 M16 spatial fragments and 6 N16 channel panels. For lane l, let g=l/4 and q=l%4, using integer division. In one N16 panel, word 0 holds row g at columns 2q and 2q+1; word 1 holds row g+8 at the same pair; words 2/3 add eight columns. Native matrix row g maps to physical x=g%4,y=g/4; row g+8 adds two to y. A lane therefore owns pieces of two tokens. It never owns a complete dot product independently.

mma.sync.aligned.m16n8k32.row.col.f16.e4m3.e4m3.f16 is a converged 32-lane operation. Four A words and two B words per lane collectively describe its operands; two Half2 accumulator words per lane describe the N8 result. Two N8 instructions build an N16 panel. Input fragments are reused across output panels; a weight bundle is reused across the warp's spatial fragments. The diagram maps Half C/D words in both modes. FP8 A bytes are formed by explicit E4 publication; do not reinterpret a Half accumulator array as FP8 without that conversion.

05. Execution and scheduling

Load W0, issue input 0, and wait for it. Iteration t issues input[t+1] into the other slot before reading its own A vectors and performing MMA. It then loads W[t+1] and waits for the next input. When a slot comes around again, every warp has already passed the intervening wait after reading the previous contents. There are 8 K iterations. Conditions suppress the last nonexistent prefetch, refill and wait. Keep the outer reduction loop rolled as in the source and unroll the fixed M/N/K-subtile loops: constant fragment indices can become register selections without duplicating the entire reduction program.

These arrows specify legal data dependencies, not a guarantee that a measured GPU overlaps every copy with arithmetic. Similarly, __ldca requests cache-all global weight loads and StoreNoAllocate requests an aligned 128-bit global store without allocating an L1 line; neither instruction guarantees an L2 hit. Check the matching NCU counters before claiming latency hiding, bandwidth savings, bank-conflict freedom or absence of spills.

CopyBulk selects its implementation by target architecture. On SM90+ an elected lane issues the ordinary-address bulk asynchronous transfer and the mbarrier expects its byte count. On SM80/SM89 each warp lane copies sixteen bytes with cp.async.cg.shared.global; the helper attaches completion to the barrier, and transaction-byte expectation is unused. This is not a tensor-map descriptor or a software L2 allocation. The full CTA initializes and arrives at the barriers, including lanes that zero-fill invalid tiles.

6.3 Normalize the selected token across four lanes

For one 32-channel token, lanes 0,1,2,3 collectively hold all channels. The helper squares upper channel groups, fuses lower-channel squares, combines groups and uses XOR-2 then XOR-1 shuffles. It swaps/adds Half components to form the replicated squared norm, clamps to Half epsilon 0x0410 (0.00006198883056640625), converts to float, executes approximate reciprocal square root, rounds back to Half2 and multiplies every channel pair. Q additionally uses the learned head scalar; K does not; V is not normalized.

The weight matrix occupies 786,432 bytes. Sixteen Half bias tables occupy 16×8192 bytes. Head-2 float scale is at W+917,512, then converted to replicated Half2. These mixed-precision fields are not E4 even in the FP8 entry. Publish Q/K as one K32 E4 fragments. V uses TransposeM8n8 to change each packed word into B-operand orientation, with E4 conversion of the two transposed row halves.

6.5 Consume probabilities as A operands and publish the token

P is published to E4 before P×V; this is an arithmetic boundary without a global P store. The new reduction axis is 64 key positions, requiring two K32 chunks. Matching transposed V words supply B. The final sixteen-query ×32-channel head fragment is published only after the key reduction. Our token/head first vector goes to A+tile·8192+head·512+chunk·512+lane·16, giving A+1,024. One E4 uint4 per lane covers the head. Negative and upper query-tile bounds prevent padded queries from writing.

Reconstruction algorithm

Instruction and evidence boundary

The explicitly managed storage is global allocations, shared stages and per-lane registers. L2 and L1 are hardware-managed caches on relevant accesses. Shared A vectors are loaded with ordinary aligned uint4 dereferences; there is no ldmatrix instruction or extra XOR shared-memory swizzle in these entry bodies. Bank indexing for a 32-bit word is (byteOffset/4)%32. A 16-byte lane vector spans four banks. Repeated bank indices across a whole warp do not alone prove serialization: the actual instruction's transaction decomposition and broadcast behavior matter.

The working storage format on this page is E4M3 FP8. Tensor-core accumulation, residual products, the recovered activation and the reduction trees discussed here use packed Half words. A uint32_t is a bit container for two Half values, not an integer approximation to their sum. HalfMul, HalfAdd and HalfFma express packed-Half source operations; replacing them with FP32 expressions and a final cast changes that arithmetic. However, ordinary CUDA Half intrinsics can be contracted by the compiler. Helper names alone do not prove a separate rounding boundary: the source-correlated SASS below establishes the actual compiled operations. E4 publication calls PackHalfPairsE4 on two Half2 words and produces four bytes. DecodeE4 performs the reverse operand preparation when a residual must participate in Half arithmetic. There is no scale tensor passed to those conversions.

Start with a high-precision scalar oracle to validate which input contributes to which output. Once the connectivity is correct, introduce a second oracle that follows the source’s K chunk order and publication points. A scalar FP32 sum is not a bitwise reference for Half MMA; it is a tool for catching transposes, wrong groups and wrong spatial coordinates. Keep these two correctness goals separate throughout reconstruction.

Reconstruct and check in dependency order

  1. Separate QKV, normalization, scores and P×V in a reference before fusing; distinguish every head and query tile.
  2. Use zero Q/K matrices with varying bias/V to isolate the surrogate and denominator behavior.
  3. Check source-order Half channel norm and row-sum reductions using asymmetric values; uniform values hide lane permutations.
  4. Exercise all origin phases and incomplete boundary windows; retain padded keys but clip invalid query stores.
  5. Check each Q/K/P publication boundary and the final head-specific output offset.

These are reconstruction checks, not a claim that this documentation build ran them. Match layouts and numerical order first; use the attached capture and its exact launch conditions when evaluating performance.

A global allocation is device memory addressed by a pointer; loads can be served by hardware-managed L2 and, depending on the instruction, L1. A cache hit is not another program-visible tensor and the source does not guarantee cache residency. __ldca permits caching at all levels; __ldcg and PTX .cg select global-level caching that bypasses L1. An eviction or no_allocate hint is a performance policy, not a publication barrier.

Shared memory is an explicitly indexed block-local allocation. Another warp may read a producer's values only after the required block barrier or completed asynchronous-copy protocol. A warp shuffle exchanges register values among its active lanes; it does not address shared memory. Arrays named r_… express per-thread values, but only compiler output establishes whether they stay in physical registers or spill to local memory. Tensor-core accumulator fragments are also register operands. These kernels use mma.sync, not TMEM.

131													  [(r_Column % 2) * 2 + r_RowHalf];

133		NormalizeWindow<false>(r_Qkv[1], CONST_HALF2_ONE);
134		r_Query[r_Spatial] = PublishWindow32<bFp8>(r_Qkv[0]);
135		r_Key[r_Spatial] = PublishWindow32<bFp8>(r_Qkv[1]);

146	// packed-Half operations as the smaller window blocks. Attention stays in registers.
147	const auto* g_HeadBias = reinterpret_cast<const unsigned char*>(
148		Parameters.g_PackedWeights + Profile::BiasOffset + TileCoordinates.g_Head * 8192);
149	{
150		// The native softmax transposes two adjacent query tiles together:
151		// one inverse per logical row replaces four identical lane copies.
152		#pragma unroll
153		for (int r_FirstTile = 0; r_FirstTile < 4; r_FirstTile += 2)
154		{
155			FWindowActivationTile<true> r_Attended[2];
156
157			// Two adjacent query tiles share one warp transpose for their four
158			// row-half denominator vectors, matching the recovered native schedule.
159			FWindowAccumulatorTile<64> r_Probabilities[2];
160			#pragma unroll
161			for (int r_LocalTile = 0; r_LocalTile < 2; ++r_LocalTile)
162				r_Probabilities[r_LocalTile] =
163					QueryKeyScores<true>(r_FirstTile + r_LocalTile, g_HeadBias, r_Query, r_Key);
164			SoftmaxWindowPair(r_Probabilities);
165			#pragma unroll
166			for (int r_LocalTile = 0; r_LocalTile < 2; ++r_LocalTile)
167				r_Attended[r_LocalTile] =
168					PublishWindow32<true>(ProbabilityValues<true>(r_Probabilities[r_LocalTile], r_Value));
169			#pragma unroll
170			for (int r_LocalTile = 0; r_LocalTile < 2; ++r_LocalTile)
171			{
172				const int r_Spatial = r_FirstTile + r_LocalTile;
173				const int g_Y = TileCoordinates.g_TileY + r_Spatial / 2,
174						  g_X = TileCoordinates.g_TileX + r_Spatial % 2;
175				if (g_Y < 0 || g_Y >= TileCoordinates.g_TilesHigh || g_X < 0 ||
176					g_X >= TileCoordinates.g_TilesWide)
177					continue;
178				const auto& r_AttendedFragment = r_Attended[r_LocalTile].r_Reduction[0];
179				const uint64_t g_OutputFragmentAddress =
180					Parameters.g_Output + uint64_t(g_Y * TileCoordinates.g_TilesWide + g_X) * 8192 +
181					TileCoordinates.g_Head * 512 + TileCoordinates.Lane * 16;
182				StoreNoAllocate(g_OutputFragmentAddress,
183								make_uint4(r_AttendedFragment.r_Word[0], r_AttendedFragment.r_Word[1],
184										   r_AttendedFragment.r_Word[2], r_AttendedFragment.r_Word[3]));
185			}
186		}
187	}
188#else
189	// Keep the exported entry on older targets, but never silently skip FP8 work.
190	__trap();
191#endif

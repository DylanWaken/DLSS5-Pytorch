01. The model operation: double channels after record 30’s pool

channel_projection_c512_to_c1024_fp16 is the encoder connector from C512 to C1024. Record 30 has already completed local attention, saved its high-resolution C512 skip and pooled its raw output. This entry takes that pooled tensor X, logically [Hlow,Wlow,512], and computes a pointwise [512,1024] projection. At a 3840×2160 input its logical field is [36,60,512] and output [36,60,1024]. There is no further pooling, residual addition, activation, bias, QKV or attention inside this kernel.

The network architecture guide places this operation in the full encoder–bottleneck–decoder. This lesson defines the operation and its physical implementation locally so it can be read independently.

The equation for one low-resolution position p is Y[p,n]=publish(Σk=0…511 X[p,k]·W[k,n]), n=0…1023. The spatial axes remain unchanged. The input field includes the network’s padding: actual half-height 34 was padded to 36 before this call. The projection is still applied to the supplied padded field according to its ordinary tile-domain rules. This page builds that single matrix operation from scalar output ownership through the exact asynchronous CTA schedule.

02. Implement one output dot product, then identify the duplicated reads

A scalar baseline gives each thread one output position/channel and performs 512 multiplies and additions. Its most obvious inefficiency is that 1,024 output channels for the same position repeatedly read the same 512-input vector. We can improve this without changing the model by sharing input data across an output-channel tile and reusing a weight panel across multiple positions. The desired tile must fit the existing packed input/output convention, because inserting a BHWC conversion would create extra traffic before useful work.

The working storage format on this page is IEEE Half / FP16. Tensor-core accumulation, residual products, the recovered activation and the reduction trees discussed here use packed Half words. A uint32_t is a bit container for two Half values, not an integer approximation to their sum. HalfMul, HalfAdd and HalfFma preserve the source’s separately rounded operations; replacing them with FP32 expressions and a final cast changes that contract. The operand and accumulator use the same element type, but their lane-word arrangements still differ by matrix role. Equal dtype does not make an arbitrary row-major uint4 a valid MMA fragment.

Start with a high-precision scalar oracle to validate which input contributes to which output. Once the connectivity is correct, introduce a second oracle that follows the source’s K chunk order and publication points. A scalar FP32 sum is not a bitwise reference for Half MMA; it is a tool for catching transposes, wrong groups and wrong spatial coordinates. Keep these two correctness goals separate throughout reconstruction.

03. Derive the 8 × 8 × 256 CTA from the output tensor

Take an 8 × 8 spatial region and 256 of the 1,024 output channels. Four channel slabs cover the full output. Eight warps divide this CTA as two spatial rows of four output groups. Warp w has channel base 256·slab+64·(w&3), and native tile Y coordinate 2·blockIdx.y+(w>>2). Each warp owns the two horizontally adjacent 4 × 4 tiles in that row, so its matrix result is 32 positions ×64 channels. It therefore needs two M16 fragments and four N16 groups.

Let spatialColumns=ceil(Wlow/8). Grid X encodes both the spatial region and channel slab: slab=blockIdx.x/spatialColumns, tileX=2·(blockIdx.x%spatialColumns). At Wlow=60, spatialColumns=8. For blockIdx.x=19, slab=2 and tileX=6; warp 5 computes output channels 576…639 for native tile row 2·blockIdx.y+1 and native columns 6/7. Keep these arithmetic roles separate when testing: the quotient is a channel selection and the remainder is a spatial selection.

One instruction computes a 16-token × 8-output-channel tile with a reduction of 16 channels. All 32 lanes participate in the same matrix operation. Each lane supplies four 32-bit A words, two 32-bit B words, and two 32-bit C words. Each C word contains two Half accumulators, so a lane owns four output elements. A source loop over output groups or reduction panels repeats this operation; it does not launch a new warp.

The exact instruction on this path is mma.sync.aligned.m16n8k16.row.col.f16.f16.f16.f16. Both the accumulator input and output are Half. Do not replace its numerical contract with FP32 accumulation when constructing an exact oracle. For the FP8 path, packing to E4M3 is a distinct rounding step; for the FP16 path a packed word simply holds two Half values.

Let lane L run from 0 to 31, g = L // 4 and q = L % 4. The matrix coordinates below describe instruction operands after any kernel-specific loads and shuffles. Storage layouts are designed to supply these coordinates cheaply.

The operand and accumulator coordinates follow the NVIDIA PTX matrix-fragment specification. A kernel may permute model channels before supplying these instruction coordinates; its publication and weight-packing rules must agree.

04. Derive byte addresses before writing the fast loop

A native input tile represents sixteen positions in a physical 4 × 4 image patch. Its byte extent is 16·512·2 = 16,384. Tile index q advances by that whole extent, an instruction-K stripe advances by 512 bytes, and lane l selects 16·l bytes within the stripe. Thus one A load is input + q·16384 + stripe·512 + lane·16. For q=7, stripe=1 and lane=13, the base-relative address is 115,408 bytes. The lane reads one uint4 containing eight Half values. These values are already arranged as a matrix operand; they are not simply consecutive channels of one pixel.

The weight record groups output columns into N16 panels and reduction channels into K16 instruction slices. Each instruction slice consumes 16·2=32 bytes per output column. Its lane-vector address is W + reductionStart·1024·2 + outputChannel·32 + lane·16 + panel·512. For reductionStart=16, outputChannel=576, panel=1 and lane=13, this is 51,920 bytes. The panel term is relative to the warp’s output base. Adding a complete K slice advances 32,768 bytes, not 512: 512 advances N16, while 32,768 advances all 1024 output columns.

Write a small host-side address decoder first. Give each logical input element a distinguishable value, encode a single native tile, and check exactly which token/channel arrives in each lane word. Repeat for one weight panel. This isolates layout errors from arithmetic errors: a wrong transpose can still produce plausible values for uniform inputs. In the kernel, all these pointer expressions use byte offsets because the public ABI passes integer addresses rather than typed multidimensional tensor views.

05. Separate copy ownership from compute ownership

The compute ownership above does not mean each warp copies only its own inputs. For copying, warp&1 selects one of the two instruction-K stripes, (warp>>1)&1 selects left/right spatial tile, and warp>>2 selects top/bottom spatial tile. Eight warps each issue one 512-byte stripe, filling a 4 KiB stage. Consumers then select the upper or lower 2 KiB half using warp>>2 and read both K stripes for both of their spatial fragments.

This remapping is the reuse mechanism. Four warps working on distinct 64-channel output groups consume the same input stage half; each loaded A fragment is also reused across four N16 accumulators inside a warp. Each weight fragment is used for both M16 spatial fragments. None of these transformations changes the number of model dot products; they change how many times bytes are fetched to support those products. The tradeoff is a shared-memory allocation and barrier protocol that the scalar baseline did not need.

06. Overlap input movement without reusing live bytes

The scalar baseline reloads input independently for each output. Our tiled version first shares an input stripe among output-panel computations. A synchronous prototype can copy a stage, execute a CTA barrier, consume every fragment, then execute a second barrier before overwriting the stage. That establishes correct producer/consumer ownership. The deployed kernel replaces the idle copy phase with a 3-slot ring. A slot holds 4,096 data bytes; its 8-byte barrier lives after all data slots, so the allocation is 3·(4096+8) = 12,312 bytes.

CopyBulk accepts a shared byte offset, a global address, byte count and barrier offset. On SM90+ it uses a bulk asynchronous copy with transaction-byte completion and an elected producer; BarrierExpect registers the expected bytes. On supported earlier targets the helper distributes 16-byte copies across warp lanes and attaches their completion to the mbarrier. BarrierExpect is then intentionally a no-op because that path does not use the transaction-byte mechanism. Initialize every stage barrier once with the full CTA arrival count, then synchronize before any copy can refer to it. An out-of-domain stripe is filled with zeros by its lane writers; those threads still join the barrier protocol.

The prologue loads W0, issues the first 3 input stages and waits for stage zero. Iteration t reads slot t%3, performs its MMA work, loads the next weights and waits for the next stage. Only then does it issue t+3 into the old slot. The intervening full-CTA arrival/wait establishes that all warps have finished the previous read phase before anyone recycles its storage. Preserve this order even if a local warp has already consumed its own fragment.

The 16 outer iterations stay rolled in the source, while spatial, N-panel and instruction-K fragment loops unroll. That lets fixed array indices select register values without expanding the entire long reduction into a huge instruction stream. More stages can hide more copy latency but consume shared memory; more fragments improve operand reuse but increase live registers. Those are the relevant tradeoffs, not a claim that a larger ring is always faster. __maxnreg__ supplies a compiler limit, not an observed register count. Inspect generated resource reports and time representative shapes before changing either knob.

07. Preserve input order while unrolling only the fragment loops

The output accumulator starts at zero because this is a pure projection. Each of the 16 outer iterations advances 32 input channels, composed of two K16 Half instructions for every N8 result. The two N8 results make one N16 accumulator group. For each of the warp’s two spatial fragments and four N16 groups, the helper consumes K subtile zero then one. Its four Half2 accumulator words remain in place across the complete K=512 reduction.

08. Publish a wider native tile without inventing a spatial transform

Each output native tile now contains sixteen positions ×1,024 channels ×2 bytes, or 32,768 bytes. The first lane vector for tile q and output base c is Y+(q·1024+c)·16·2+16·lane. For q=7,c=576,lane=13, that is 248,016 bytes. The writer emits four direct Half vectors per lane, one per N16 group. Grid/channel ownership gives each output address one writer.

The input resolver broadcasts a singleton tile dimension and otherwise zero-fills invalid 8 × 8 CTA edges. The output check clips to Hlow/4 and Wlow/4 native tiles. At [36,60], the final CTA row includes one valid native tile row and a synthetic one; the final CTA column likewise handles one real and one synthetic native tile. The synthetic inputs may support a convenient fixed compute schedule, but their results must not be stored beyond the field. These are boundary rules of the physical kernel, not extra logical pixels in the model.

09. The helper contracts needed to reconstruct this entry

FMmaAccumulatorTile<M,N> contains [M][N][4] 32-bit words per lane. Each N index means sixteen output channels, built from two N8 MMA instructions; it does not mean a sixteen-byte vector in logical row-major order. AccumulateTile takes an array of four-word A fragments and four-word weight bundles, uses the lower two B words for the first N8 result and upper two for the second, and updates the four Half2 words in place. When two instruction-K subtiles exist, it advances each accumulator through subtile zero before subtile one; the FP16 QKV stage supplies only one K16 subtile. The API’s by-value operands ensure an output update does not change the fragment arguments still being evaluated.

StoreNoAllocate emits an aligned 128-bit global store with an L1 no-allocation request. __ldca loads weights with cache-all policy; residual readers may use __ldcg. These are memory-policy choices rather than barriers or promises that an access reaches a particular cache level. A correct implementation must separately satisfy the synchronization protocol and vector alignment. Direct Half publication preserves the accumulator words, which is precisely why the next packed matrix operation can reuse them without an intermediate logical tensor transpose.

10. Final reconstruction schedule

11. Reconstruction checks, in the order they isolate errors

  1. Use W that copies each input channel to both output halves; decode all 1024 output channels and verify the duplication without any spatial shift.
  2. Use four distinguishable output-channel slabs to catch grid-X quotient/remainder errors. Test the blockIdx.x=19,warp=5 worked ownership example.
  3. Fill one input K stripe at a time; distinguish the two instruction-K halves and verify the 32 KiB weight stride. A constant weight matrix will not detect a wrong panel address.
  4. Exercise [36,60] and inspect the right/bottom synthetic CTA tiles with guarded allocations; only actual native tiles may be stored.
  5. Test zero input, sparse input and alternating-sign large/small values to separate layout errors from Half accumulator rounding differences.
  6. Compare all output addresses against a host enumeration of (native tile,channel panel,lane) and ensure disjoint writes across every CTA/channel slab.

These are concrete tests to implement when rebuilding the kernel, not claims that this documentation run executed GPU comparisons. First establish layout and numerical equivalence; then measure latency with the same weights, geometry, precision and stream behavior. A source-level eliminated allocation establishes avoided traffic, but it does not quantify the speedup or prove absence of register spills.

A global allocation is device memory addressed by a pointer; loads can be served by hardware-managed L2 and, depending on the instruction, L1. A cache hit is not another program-visible tensor and the source does not guarantee cache residency. __ldca permits caching at all levels; __ldcg and PTX .cg select global-level caching that bypasses L1. An eviction or no_allocate hint is a performance policy, not a publication barrier.

Shared memory is an explicitly indexed block-local allocation. Another warp may read a producer's values only after the required block barrier or completed asynchronous-copy protocol. A warp shuffle exchanges register values among its active lanes; it does not address shared memory. Arrays named r_… express per-thread values, but only compiler output establishes whether they stay in physical registers or spill to local memory. Tensor-core accumulator fragments are also register operands. These kernels use mma.sync, not TMEM.

92			}

99		StageInput(s_StageIndex, g_ReductionChannelBase + s_StageIndex * FProfile::ReductionStep, g_TileY,
100				   g_InputTileX, g_Height / 4, g_Width / 4);

105	// unroll, so tile coordinates select registers rather than local memory.
106	#pragma unroll 1

108	{

112		uint4 r_InputFragments[2][2];
113		#pragma unroll
114		for (int r_SpatialTile = 0; r_SpatialTile < 2; ++r_SpatialTile)
115		{
116			#pragma unroll
117			for (int r_KSubtile = 0; r_KSubtile < 2; ++r_KSubtile)
118				r_InputFragments[r_SpatialTile][r_KSubtile] = *reinterpret_cast<const uint4*>(
119					s_Storage + s_InputStageByteOffset + r_SpatialTile * 1024 + r_KSubtile * 512);
120		}
121
122		AccumulateTile<FProfile::Precision>(r_Accumulator, r_InputFragments, r_WeightFragments);
123
124		// Prefetch weights before waiting for the next input stage. That wait
125		// also proves all warps finished reading the stage about to be reused.
126		if (ReductionTile + 1 < FProfile::ReductionSteps)
127		{
128			LoadWeights(g_ReductionChannelBase + (ReductionTile + 1) * FProfile::ReductionStep);
129			WaitStage((ReductionTile + 1) % FProfile::s_StageCount);
130		}
131
132		if (ReductionTile + FProfile::s_StageCount < FProfile::ReductionSteps)
133			StageInput(s_StageIndex,
134					   g_ReductionChannelBase +
135						   (ReductionTile + FProfile::s_StageCount) * FProfile::ReductionStep,
136					   g_TileY, g_InputTileX, g_Height / 4, g_Width / 4);
137	}
138

140	// N16 fragment directly; FP8 merges adjacent N8 fragments after conversion.
141	#pragma unroll
142	for (int r_SpatialTile = 0; r_SpatialTile < 2; ++r_SpatialTile)
143	{
144		if (g_TileY < g_Height / 4 && g_TileX + r_SpatialTile < g_Width / 4)
145		{
146			const int g_TileIndex = g_TileY * (g_Width / 4) + g_TileX + r_SpatialTile;
147			const int g_OutputTileByteBase =
148				(g_TileIndex * FProfile::OutputChannels + g_OutputChannel) * 16 * FProfile::ElementBytes +
149				Lane * 16;
150			{
151				#pragma unroll
152				for (int r_ChannelGroup = 0; r_ChannelGroup < 4; ++r_ChannelGroup)
153				{
154					const auto& r_AccumulatorWords =
155						r_Accumulator.r_AccumulatorWords[r_SpatialTile][r_ChannelGroup];
156					StoreNoAllocate(
157						reinterpret_cast<uint64_t>(g_Output + g_OutputTileByteBase + r_ChannelGroup * 512),
158						make_uint4(r_AccumulatorWords[0], r_AccumulatorWords[1], r_AccumulatorWords[2],
159								   r_AccumulatorWords[3]));
160				}
161			}
162		}
163	}
164#endif

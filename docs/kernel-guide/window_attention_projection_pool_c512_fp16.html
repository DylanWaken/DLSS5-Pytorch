01. The whole problem

The model asks for a pointwise C512 attention output projection: raw[p,n]=Σk Input[p,k]W[k,n]+scale[n]·R[p,n], followed by output publication. Input is the attended head features; the independent R branch is the published FFN output. At 4K each has [68,120,512], W is [512,512], and scale has 512 Half values. Establish these two incoming edges before choosing a fused implementation: using Input as its own residual can produce plausible but incorrect results.

The network architecture guide places this operation in the full encoder–bottleneck–decoder. This lesson defines the operation and its physical implementation locally so it can be read independently.

A first baseline materializes the scaled residual, uses it to initialize a standalone projection, then performs pooling and output publication as separate steps. To match this model's finite-precision execution, its arithmetic oracle must seed C with the rounded scaled residual before the K reduction; a mathematically equivalent residual add afterward can round differently. The record-30 output also averages each raw 2×2 spatial patch before working-format publication. Its pooled field has 34 valid rows padded to 36; the high result is saved as the decoder skip.

The key fusion opportunity is to reuse still-live raw C for both high publication and pooling, without reading quantized high output back. We will reconstruct window_attention_projection_pool_c512_fp16 from that baseline.

02. One CTA: its concrete subproblem

A simple M16×64-output job gives 510 native spatial tiles ×8 channel bands = 4,080 CTAs. Expand to 64 positions ×256 outputs: four bands share staged A and the grid shrinks to 15×9×2=270 jobs. Taking all 512 outputs would leave 135 jobs and double the per-CTA output payload, requiring more warps or more state per thread. There is no timing result for these alternatives; choose the middle job as a resource-bounded candidate to implement.

Encode its two channel slabs and fifteen spatial columns in grid X: slab=blockIdx.x/15, spatial column=blockIdx.x%15. This derives grid=(30,9,1), block=(32,4); the capture will confirm the launched geometry later. CTA (0,0,0) owns pixels 0…7 and channels 0…255, with all K512 reduced locally. Its four raw high tiles also form one 4×4 pooled tile, so assigning both outputs to the same CTA avoids inter-CTA communication. Preserve the source singleton native-tile read policy when checking edges.

03. Warp and thread ownership

Derive ownership from the 64×256 result: it contains 8,192 Half2 words. Four warps retain 64 words per lane, with each warp owning all four M16 spatial fragments and 64 channels. Eight warps retain 32 words per lane, splitting the upper/lower tile rows but requesting each channel band's weights in two warps. This entry chooses four warps, preserving all four spatial fragments in each channel-band owner. That full-window ownership is useful for pooling: the four raw tiles are available within one warp, so no shared exchange is needed for the 2×2 average.

Use channelBase=256·slab+64·(warp%4). Each warp receives four M16 fragments in top-left, top-right, bottom-left, bottom-right order. Fix warp 2 and channel base 128 for the trace. Its lane-0 first C word must begin with R[(0,0),128]·scale[128] and remain the owner of that result throughout K.

One warp's result has 4 M16 spatial fragments and 4 N16 channel panels. For lane l, let g=l/4 and q=l%4, using integer division. In one N16 panel, word 0 holds row g at columns 2q and 2q+1; word 1 holds row g+8 at the same pair; words 2/3 add eight columns. Coordinates in this lesson are (y,x). Native matrix row g maps to physical x=g%4,y=g/4; row g+8 adds two to y. A lane therefore owns pieces of two tokens. It never owns a complete dot product independently.

mma.sync.aligned.m16n8k16.row.col.f16.f16.f16.f16 is a converged 32-lane operation. Four A words and two B words per lane collectively describe its operands; two Half2 accumulator words per lane describe the N8 result. Two N8 instructions build an N16 panel. Input fragments are reused across output panels; a weight bundle is reused across the warp's spatial fragments. The diagram maps Half C/D words in both modes. Half accumulator words can be forwarded to the next A role only where the source helper establishes that layout contract.

04. Resource budget

The chosen A panel has 64 positions ×K32×2 bytes = 4,096 bytes. One/two/three slots plus barriers require 4,104/8,208/12,312 static bytes. The pool candidate uses two slots while retaining four raw tiles and creating a pooled accumulator after projection. A hypothetical shared B panel adds 256×K32×2=16,384 bytes per slot, so direct register B loads avoid that explicit cost at the expense of relying on hardware caching for inter-warp reuse.

Reserve the Half C/D state for the entire K loop. Residual vectors and scales are initialization temporaries, not a second long-lived shared tensor. Raw C remains live until both high publication and pooling consume it; that longer epilogue lifetime must be included in the register hypothesis. The table is a logical allocation worksheet; compiled counts and occupancy appear later in section 6.

Treat this as a resource prediction before compilation. A uint4 needs four 32-bit words if scalarized into registers; one accumulator word holds two Half scalars. These declared arrays describe logical state, not an additive count of physical registers: lifetimes can overlap, compiler temporaries add state, and an array may spill into local memory. A register ceiling constrains the compiler; it does not reserve exactly that many registers.

For a candidate with compiled count R and T threads, begin with R·T register words, round using the device allocation rules, then compare the register, shared-memory, thread and block residency limits. Do not infer occupancy from static shared bytes alone. The recorded launch, physical allocation, local-memory traffic and instruction evidence appear later in section 6, after we have predictions to test.

Residual vectors and scales are temporary register inputs; there is no shared residual tensor. Four raw tiles remain live while the high output is published and the pooled tile is assembled.

05. Execution and scheduling

First build a synchronous residual-seeded GEMM. Initialize C from the correct R allocation and Half scales, load one A/B panel, update C, then retire the shared panel behind a CTA barrier. This separates the easy-to-confuse residual edge from asynchronous input movement. Only after it agrees with the baseline add the 2-slot prefilled ring: prime the slots, wait for the current input, and refill a retired slot after every consumer has advanced.

Add the second output last: publish the high result while retaining raw C, then shuffle/average the four-token neighborhoods. Never validate this fusion against pooling already-published E4 values. The diagram expresses dependencies to implement, and the final evidence will test the resource/instruction predictions.

Now implement the candidate schedule: Load W0, issue input 0 through 1, and wait for input 0. Iteration t loads its A vectors, performs all MMA work, loads W[t+1], and waits for input[t+1]. Only after that full-CTA arrival does it issue input[t+2] into the retired slot. There are 16 K iterations. The invariant is that a consumer reads a completed current slot and no producer overwrites a slot with unfinished readers. Derive the final-iteration predicates from that invariant: no next input means no next copy or wait. First test one iteration and a final partial ring before running the full reduction.

Keep the outer K loop rolled, then unroll the fixed fragment loops so constant M/N/K-subtile indices can become register selections. This predicts a smaller instruction body than unrolling all 16 reduction steps while retaining direct fragment access; confirm the compiled local-memory and instruction evidence later. The arrows show legal dependencies, not measured overlap. Likewise, __ldca requests cache-all global weight loads and StoreNoAllocate requests a 128-bit store without L1 allocation; cache residency and throughput remain measurements.

CopyBulk selects its implementation by target architecture. On SM90+ an elected lane issues the ordinary-address bulk asynchronous transfer and the mbarrier expects its byte count. On SM80/SM89 each warp lane copies sixteen bytes with cp.async.cg.shared.global; the helper attaches completion to the barrier, and transaction-byte expectation is unused. This is not a tensor-map descriptor or a software L2 allocation. The full CTA initializes and arrives at the barriers, including lanes that zero-fill invalid tiles.

06. Trace one token through the source

Follow CTA (0,0,0), warp 2, lane 0, token (0,0), output channel 128. This token has two independent incoming edges: Input[p,:] supplies matrix A and R[p,128] supplies the initial C. Keep those addresses separate.

Milestone 6.1 — Establish the residual seed independently

Set W=0 and give each residual channel a distinct scale. Initialize C and publish it with a diagnostic writer before implementing the K loop. The invariant is that R[p,n] and scale[n] seed the same token/channel word that the matrix result will update. This test must fail if Input is accidentally used as R. For a plane-view residual, compare against an independently decoded native baseline before adding asynchronous A copies.

The matrix record consumes 524,288 bytes, then 1,024 bytes of Half scales. Scale 128 begins at W+524288+2·128 = W+524,544. Scale 129 is its neighboring Half. These remain Half in the FP8 entry. The selected pair seeds word 0 of the first N16 accumulator after HalfMul.

The invariant is that A belongs to the projection branch while R belongs only to C initialization. The native packing is copied unchanged, without XOR swizzle. Its four shared words address banks 0…3. For channel base 128, N16=0 and first K subtile, weight address is 1·32·512·2+128·32 = 36864. Milestone 6.3 — Combine the two verified branches in the correct order

Enable both nonzero W and R, seed C once, and add all K panels without reinitializing it. Compare against a source-order Half oracle rather than a final FP32 residual add. Pick a small residual beside a larger projected contribution to reveal different rounding order. The invariant is stable C/D ownership across every MMA: operand lanes cooperate, but the output word continues to represent the same token/channel pair.

All 32 lanes jointly issue two N8 operations per N16 panel and two instruction-K subtiles per iteration. The selected C/D word remains lane 0, spatial fragment 0, N16 panel 0, word 0, although operands for its dot product are distributed across the warp. Each A fragment participates in four N16 panels; each B bundle serves 4 spatial fragments. This reuse motivates the tiling candidate. The attached capture can establish cache behavior and tensor-pipe utilization for this binary; a speedup from tiling requires a matched A/B comparison with the baseline.

Milestone 6.4 — Fuse the destination-specific epilogue

Use the already-verified raw projection as the epilogue input. For a native writer, independently decode output vectors; for a plane writer, compare with a separate native-to-plane conversion; for pooling, compare with a separate exact raw-Half four-token reduction. Each variant needs distinct spatial/channel tags and boundary guards. The invariant is that publication changes representation, while pooling deliberately changes the spatial dependency and must read raw values. This final milestone can remove the corresponding intermediate allocation only after its comparison passes.

The first writer publishes high token (0,0) at native output offset 4,096. Keep the raw Half result alive. Pooling combines tokens (0,0),(0,1),(1,0),(1,1) into pooled token (0,0), using the exact tree HalfMul(HalfAdd(HalfAdd(TL,TR),HalfAdd(BL,BR)),0.25). Validate the completed candidate against its predictions

The milestones above are a reconstruction plan, not a report that alternative kernels were implemented or benchmarked. Compile the final candidate and check the predicted instructions, physical resources and memory traffic against the recorded capture. A mismatch is a reason to revisit an assumption: local loads may reveal a spilled fragment array; an unexpected lane permutation may reveal a layout conversion; different Half instructions may reveal contraction. A final-candidate capture can identify remaining bottlenecks, but attributing a speedup to a design choice requires a matched baseline experiment.

The explicitly managed storage is global allocations, shared stages and per-lane registers. L2 and L1 are hardware-managed caches on relevant accesses. Shared A vectors are loaded with ordinary aligned uint4 dereferences; there is no ldmatrix instruction or extra XOR shared-memory swizzle in these entry bodies. Bank indexing for a 32-bit word is (byteOffset/4)%32. A 16-byte lane vector spans four banks. Repeated bank indices across a whole warp do not alone prove serialization: the actual instruction's transaction decomposition and broadcast behavior matter.

The working storage format on this page is IEEE Half / FP16. Tensor-core accumulation, residual products, the recovered activation and the reduction trees discussed here use packed Half words. A uint32_t is a bit container for two Half values, not an integer approximation to their sum. HalfMul, HalfAdd and HalfFma express packed-Half source operations; replacing them with FP32 expressions and a final cast changes that arithmetic. However, ordinary CUDA Half intrinsics can be contracted by the compiler. Helper names alone do not prove a separate rounding boundary: the source-correlated SASS below establishes the actual compiled operations. The operand and accumulator use the same element type, but their lane-word arrangements still differ by matrix role. Equal dtype does not make an arbitrary row-major uint4 a valid MMA fragment.

Start with a high-precision scalar oracle to validate which input contributes to which output. Once the connectivity is correct, introduce a second oracle that follows the source’s K chunk order and publication points. A scalar FP32 sum is not a bitwise reference for Half MMA; it is a tool for catching transposes, wrong groups and wrong spatial coordinates. Keep these two correctness goals separate throughout reconstruction.

Reconstruct and check in dependency order

  1. Zero W and distinguish every residual channel/scale: prove that the independent R branch seeds the correct C word.
  2. Use identity and non-diagonal permutation W with zero scales to isolate A/B addressing.
  3. Exercise both channel slabs, upper/lower warp ownership and bottom-edge clipping.
  4. Compare raw-Half pooling with the exact four-token tree, including padding and E4 quantization.

These are reconstruction checks, not a claim that this documentation build ran them. Match layouts and numerical order first; use the attached capture and its exact launch conditions when evaluating performance.

A global allocation is device memory addressed by a pointer; loads can be served by hardware-managed L2 and, depending on the instruction, L1. A cache hit is not another program-visible tensor and the source does not guarantee cache residency. __ldca permits caching at all levels; __ldcg and PTX .cg select global-level caching that bypasses L1. An eviction or no_allocate hint is a performance policy, not a publication barrier.

Shared memory is an explicitly indexed block-local allocation. Another warp may read a producer's values only after the required block barrier or completed asynchronous-copy protocol. A warp shuffle exchanges register values among its active lanes; it does not address shared memory. Arrays named r_… express per-thread values, but only compiler output establishes whether they stay in physical registers or spill to local memory. Tensor-core accumulator fragments are also register operands. These kernels use mma.sync, not TMEM.

156				}
157			}
158		}
159	}

162	// lifecycle. Prefetch next weights before waiting, then recycle the old stage.
163	#pragma unroll 1
164	for (int ReductionTile = 0; ReductionTile < Profile::ReductionTiles; ++ReductionTile)
165	{
166		uint4 r_Input[SpatialTiles][2];
167		#pragma unroll
168		for (int r_Spatial = 0; r_Spatial < SpatialTiles; ++r_Spatial)
169			#pragma unroll

172					*reinterpret_cast<const uint4*>(s_Storage + (ReductionTile % StageCount) * 4096 +

174													r_KSubtile * 512 + TileCoordinates.Lane * 16);

176		if (ReductionTile + 1 < Profile::ReductionTiles)
177		{
178			LoadWeights(ReductionTile + 1);
179			WaitInput(ReductionTile + 1);
180		}

182		if (ReductionTile + StageCount < Profile::ReductionTiles)
183			IssueInput(ReductionTile + StageCount);
184	}

187	#pragma unroll

193			continue;

198				TileCoordinates.g_OutputChannel * 16 * Profile::ElementBytes + TileCoordinates.Lane * 16;
199			{
200				#pragma unroll
201				for (int r_ChannelGroup = 0; r_ChannelGroup < 4; ++r_ChannelGroup)
202				{

207											   r_AccumulatorWords[2], r_AccumulatorWords[3]));
208				}
209			}
210		}
211	}

214		// Pool the unquantized accumulators, then publish the single downsampled tile.
215		FSpatialProjectionAccumulator<1> r_Pooled;
216		#pragma unroll
217		for (int r_ChannelGroup = 0; r_ChannelGroup < 4; ++r_ChannelGroup)
218			#pragma unroll

220				#pragma unroll
221				for (int r_RowHalf = 0; r_RowHalf < 2; ++r_RowHalf)
222				{
223					const auto& r_LeftTileWords =
224						r_Accumulator.r_AccumulatorWords[r_RowHalf * 2][r_ChannelGroup];
225					const auto& r_RightTileWords =
226						r_Accumulator.r_AccumulatorWords[r_RowHalf * 2 + 1][r_ChannelGroup];
227					r_Pooled.r_AccumulatorWords[0][r_ChannelGroup][r_N8 * 2 + r_RowHalf] =
228						PoolHorizontalWords(r_LeftTileWords[r_N8 * 2], r_LeftTileWords[r_N8 * 2 + 1],
229											r_RightTileWords[r_N8 * 2], r_RightTileWords[r_N8 * 2 + 1]);
230				}
231
232		FSpatialProjectionTileCoordinates DownsampledCoordinates = TileCoordinates;
233		DownsampledCoordinates.g_TilesHigh = Arguments.DownsampledHeight / 4;
234		DownsampledCoordinates.g_TilesWide = Arguments.DownsampledWidth / 4;
235		DownsampledCoordinates.g_TileY /= 2;
236		DownsampledCoordinates.g_TileX /= 2;
237		#pragma unroll
238		for (int r_Spatial = 0; r_Spatial < 1; ++r_Spatial)
239		{
240			const int g_Y = DownsampledCoordinates.g_TileY + DownsampledCoordinates.Warp / 4 + r_Spatial / 2;
241			const int g_X = DownsampledCoordinates.g_TileX + r_Spatial % 2;
242			if (g_Y >= DownsampledCoordinates.g_TilesHigh || g_X >= DownsampledCoordinates.g_TilesWide)
243				continue;
244			{
245				const uint64_t g_OutputTileBase =
246					Arguments.g_DownsampledOutput +
247					uint64_t(g_Y * DownsampledCoordinates.g_TilesWide + g_X) * Profile::SpatialTileBytes +
248					DownsampledCoordinates.g_OutputChannel * 16 * Profile::ElementBytes +
249					DownsampledCoordinates.Lane * 16;
250				{
251					#pragma unroll
252					for (int r_ChannelGroup = 0; r_ChannelGroup < 4; ++r_ChannelGroup)
253					{
254						const auto& r_AccumulatorWords =
255							r_Pooled.r_AccumulatorWords[r_Spatial][r_ChannelGroup];
256						StoreNoAllocate(g_OutputTileBase + r_ChannelGroup * 512,
257										make_uint4(r_AccumulatorWords[0], r_AccumulatorWords[1],
258												   r_AccumulatorWords[2], r_AccumulatorWords[3]));
259					}
260				}
261			}
262		}
263	}

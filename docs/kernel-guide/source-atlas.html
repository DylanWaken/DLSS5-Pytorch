The model piece: all deployment entry families

The architecture has 71 numbered records, while the CUDA interface exposes 81 public configurations: 40 paired FP8/FP16 roles plus completion-counter clearing. Many records reuse the same role with different weights, and templates let several public roles share one complete global body. This atlas maps every public configuration to its actual source definition and its self-contained lesson.

Read the architecture guide to identify the tensor operation, then use this table to reach the exact implementation and its standalone reconstruction. Entries link to a fixed source revision. The source census finds 56 complete global definitions; it does not establish runtime or performance coverage.

Additive 310.9.16 entries: two further public configurations bring the guide to 83 entries, 41 paired roles and 58 owning definitions. They are listed in a separate section below and do not alter the 81-row historical mapping or its evidence.

Provenance and scope

The inventory comes from tools/kernel_sources.py; its roster and source-ownership checks run during documentation generation. source-manifest.json records file hashes, excerpt ranges and the public-entry mapping with per-file legacy/runtime provenance. Source excerpts are copied directly from the checked files. Layout calculations marked as examples are derived from those formulas; optimization mechanisms are explained from source. Separate measured evidence accompanies the 81 historical lessons, including compiled resources and source-correlated instruction counts. The two additive lessons have their own evidence-small record and small map manifest; the all-83 registry maps both sets.

The generated HTML is stored in docs/kernel-guide. Its Python content modules and assets live in tools/kernel_docs. Regenerate with python tools/build_kernel_docs.py and validate with python tools/validate_kernel_docs.py. The network architecture and its diagrams are maintained in the same HTML guide as the kernel lessons.

01. Record 39: project, repeat, add the encoder skip

decoder_upsample_c1024_to_c512_fp16 implements the transition-only record 39. Its low input has 1,024 channels. A [1024,512] matrix first reduces channel width, each projected position is repeated into a 2 × 2 high-resolution patch, and a learned channelwise scale multiplies the saved record-30 skip before addition. The published C512 tensor feeds record 40’s ordinary FFN/attention block. There is no ordinary FFN or attention inside record 39 itself.

The network architecture guide, rendered from docs/ARCHITECTURE.md, places this operation in the full encoder–bottleneck–decoder. This lesson defines the operation and its physical implementation locally so it can be read independently.

At the 4K geometry, input is [36,60,1024] and saved skip is [68,120,512]. Projection produces [36,60,512]. Nearest 2× repetition would give [72,120,512]; cropping to the destination field yields [68,120,512]. For high pixel (y,x) and channel n, the conceptual result is Y[y,x,n]=publish((X[floor(y/2),floor(x/2),:] W)[n] + scale[n]·skip[y,x,n]). Projection happens at low resolution so each dot product is evaluated once for four destinations.

02. Separate the three operations before fusing them

A simple reference first computes a complete low-resolution [Hlow,Wlow,512] projection, then launches an upsample/merge kernel that looks up floor(y/2),floor(x/2). This makes the spatial relation explicit. A less careful baseline could repeat X first and run the 1024→512 projection at high resolution, duplicating the same matrix work up to four times. Begin with projection-before-repeat. The optimized entry will additionally remove the low projected global image from the final split and directly shuffle its register values to high destinations.

The working storage format on this page is IEEE Half / FP16. Tensor-core accumulation, residual products, the recovered activation and the reduction trees discussed here use packed Half words. A uint32_t is a bit container for two Half values, not an integer approximation to their sum. HalfMul, HalfAdd and HalfFma preserve the source’s separately rounded operations; replacing them with FP32 expressions and a final cast changes that contract. The operand and accumulator use the same element type, but their lane-word arrangements still differ by matrix role. Equal dtype does not make an arbitrary row-major uint4 a valid MMA fragment.

Start with a high-precision scalar oracle to validate which input contributes to which output. Once the connectivity is correct, introduce a second oracle that follows the source’s K chunk order and publication points. A scalar FP32 sum is not a bitwise reference for Half MMA; it is a tool for catching transposes, wrong groups and wrong spatial coordinates. Keep these two correctness goals separate throughout reconstruction.

03. Split both output channels and input-K work deliberately

A CTA owns one low 4 × 4 tile and 256 output channels. It has two warps, each producing 128 output channels over the same sixteen low positions. Each warp therefore needs one M16 fragment and eight N16 accumulator groups. Grid X has 2·ceil(InputWidth/4) positions: its remainder selects low tile X, its quotient selects output channels 0…255 or 256…511. Grid Y selects low tile Y. Grid Z, or the OrderedSplit parameter, selects one of four 256-input-channel K ranges.

Let columns=ceil(InputWidth/4), tileX=blockIdx.x%columns, and outputBase=256·(blockIdx.x/columns)+128·warp. For InputWidth=60 and blockIdx.x=23, columns=15, tileX=8 and the slab begins at 256. Warp 1 then owns output channels 384…511. Split 2 reads input channels 512…767 for that result. These three independent roles—spatial tile, output slab, K split—must all appear in the correct address terms.

One instruction computes a 16-token × 8-output-channel tile with a reduction of 16 channels. All 32 lanes participate in the same matrix operation. Each lane supplies four 32-bit A words, two 32-bit B words, and two 32-bit C words. Each C word contains two Half accumulators, so a lane owns four output elements. A source loop over output groups or reduction panels repeats this operation; it does not launch a new warp.

The exact instruction on this path is mma.sync.aligned.m16n8k16.row.col.f16.f16.f16.f16. Both the accumulator input and output are Half. Do not replace its numerical contract with FP32 accumulation when constructing an exact oracle. For the FP8 path, packing to E4M3 is a distinct rounding step; for the FP16 path a packed word simply holds two Half values.

Let lane L run from 0 to 31, g = L // 4 and q = L % 4. The matrix coordinates below describe instruction operands after any kernel-specific loads and shuffles. Storage layouts are designed to supply these coordinates cheaply.

The operand and accumulator coordinates follow the NVIDIA PTX matrix-fragment specification. A kernel may permute model channels before supplying these instruction coordinates; its publication and weight-packing rules must agree.

04. Distinguish working-format inputs from always-Half split scratch

A low input native tile is sixteen positions ×1,024 channels ×2 bytes, or 32,768 bytes. Split s contributes a s·4096·2 byte offset, because it owns 256 channels across those sixteen positions. Current iteration t and producer warp w add (2t+w)·512. Thus X+lowTile·32768+split·8192+(2t+warp)·512 names each input stripe. For lowTile=7,split=2,t=1,producer warp=1, it is 247,296 bytes. Both consumer warps then reuse both staged stripes for different output-channel groups.

The weight address is W+(256·split+t·32)·512·2+outputBase·32+16·lane+16384·kSubtile+512·N16. For split=2,t=1,outputBase=128,lane=13,kSubtile=1,N16=3 it gives 579,280 bytes. The full matrix consumes 1024·512·2=1,048,576 bytes, followed by 512 Half scale values. Matrix K slicing does not slice the residual scale array: scale depends only on the final output channel.

05. Introduce split-K only after a complete low projection works

The baseline has few low spatial tiles, so splitting the 1,024-channel reduction into four K256 jobs provides more independent CTAs. Each job computes one quarter of the dot product into Half accumulators. This adds scratch traffic, counters and ordering requirements; it is not a free reduction in work. A correct reconstruction should first implement all K=1024 in one CTA, verify the projection, then introduce four partials and explicitly match the source’s order. Floating-point partial sums cannot be freely rearranged while claiming identical results.

Split 0 stores its accumulator to scratch. Splits 1 and 2 add their accumulators using ReduceHalf4. Split 3 loads the prior scratch into registers and performs four HalfAdd operations with its own N16 words; it does not overwrite scratch. Consequently the source’s final low result is effectively (((partial0+partial1)+partial2)+partial3) with Half reduction/publication boundaries. Each split has its own internal ordered K accumulation. The final upsample and skip merge run only in split 3.

ReduceHalf4 uses a vector Half2 global reduction on SM90+ and scalar Half2 reductions on earlier supported targets. Its no-flush-to-zero modifier and Half addition are part of the numerical contract. The same scratch location is intentionally updated over time by multiple splits, while final output coordinates remain single-writer locations.

06. Overlap input movement without reusing live bytes

The scalar baseline reloads input independently for each output. Our tiled version first shares an input stripe among output-panel computations. A synchronous prototype can copy a stage, execute a CTA barrier, consume every fragment, then execute a second barrier before overwriting the stage. That establishes correct producer/consumer ownership. The deployed kernel replaces the idle copy phase with a 2-slot ring. A slot holds 1,024 data bytes; its 8-byte barrier lives after all data slots, so the allocation is 2·(1024+8) = 2,064 bytes.

CopyBulk accepts a shared byte offset, a global address, byte count and barrier offset. On SM90+ it uses a bulk asynchronous copy with transaction-byte completion and an elected producer; BarrierExpect registers the expected bytes. On supported earlier targets the helper distributes 16-byte copies across warp lanes and attaches their completion to the mbarrier. BarrierExpect is then intentionally a no-op because that path does not use the transaction-byte mechanism. Initialize every stage barrier once with the full CTA arrival count, then synchronize before any copy can refer to it. An out-of-domain stripe is filled with zeros by its lane writers; those threads still join the barrier protocol.

The prologue loads W0, issues X0 and waits for slot zero. Iteration t issues X[t+1] into the other slot before consuming X[t]. It then prefetches W[t+1] and waits on the next slot. Every warp reaches that wait only after reading its current stage, so the later producer phase can recycle it. The final iteration skips both the nonexistent refill and the next wait.

The 8 outer iterations stay rolled in the source, while spatial, N-panel and instruction-K fragment loops unroll. That lets fixed array indices select register values without expanding the entire long reduction into a huge instruction stream. More stages can hide more copy latency but consume shared memory; more fragments improve operand reuse but increase live registers. Those are the relevant tradeoffs, not a claim that a larger ring is always faster. __maxnreg__ supplies a compiler limit, not an observed register count. Inspect generated resource reports and time representative shapes before changing either knob.

07. Make cross-CTA publication an explicit part of the design

The counter address is completionCounters+4·(tileY·2·columns+blockIdx.x). It is shared by all K splits of the same low-tile/output-slab CTA. With columns=15,tileY=3,blockIdx.x=23, it is byte offset 452. Its initial state must come from the launch/counter-clear contract; allocating uninitialized counter bytes is not a valid starting point. Native later splits poll until the predecessor value is observed, and the producer publishes its split index after its CTA’s writes have reached the final synchronization point.

The source has two modes. When OrderedSplit is nonzero, its value minus one selects the logical split; the launcher can run four XY grids in stream order. This provides an easy-to-reason-about rebuild path: a later kernel starts after its predecessor’s writes, and no resident CTA waits on a producer that cannot be scheduled. When OrderedSplit is zero, grid Z supplies the split and the entry uses relaxed GPU-scope counter loads and a release counter store, with CTA barriers around publication. A grid full of polling consumers can prevent an unscheduled producer from running, so this mode also depends on launch-capacity reasoning.

For every split greater than zero, this FP16 body executes a CTA barrier after the conditional poll. OrderedSplit mode skips the poll but retains that barrier; the FP8 body encloses both operations in its native-mode branch. The pinned entry bodies do not invoke the available AcquireSplitPublication helper after polling. Describe that actual source sequence faithfully; do not turn it into a generic proof that any relaxed poll followed by a CTA barrier acquires another CTA’s data. For an independent reconstruction, validate the ordered-stream mode first, then assess the full native counter protocol, memory visibility and resident-grid constraints as a separate change. The tutorial does not invent a missing fence or claim to have formally verified native inter-CTA synchronization.

08. Reconstruct nearest-neighbor repetition as lane selection

A projected low 4 × 4 tile expands into four high 4 × 4 quadrants. Let ox and oy be the quadrant’s horizontal and vertical bits. For destination lane l and row half r, select source lane (l&3)|((l>>1)&4)|(8·ox)|(16·r). Select source accumulator word with row half oy. The low lane’s channel bits l&3 remain unchanged, while token bits select the low value that should repeat at that destination. This replaces an expanded temporary tensor with indexed register shuffles.

For ox=0,oy=0,r=0, destination lanes 0,4,16,20 all select source lane 0. Those lanes correspond to high positions (0,0),(1,0),(0,1),(1,1) for the same channel pair. The value repeats exactly four times; no interpolation weights appear. For a global worked example, high pixel (17,25), channel 137 reads the low projection at (8,12), channel 137, and the skip at the original high coordinate (17,25), channel 137. The low and skip spatial addresses must therefore be derived independently.

Read the saved skip as native C512 vectors, multiply by the channel scale with HalfMul, then add the nearest projected value with HalfAdd. This is a separately rounded skip product followed by addition. It is not a fused skip FMA. The crop occurs when choosing valid high output tiles; at 4K the bottom four rows of the nominal 72-row repetition are excluded. The final publication occurs after this merge, not between projection and repetition.

09. Give the final image a single writer

Only split 3 stores high-resolution output. For high native tile q, output base c and lane l, its first vector begins at Y+q·16384+c·32+16l. For q=12,c=128,l=13, that is 200,912 bytes. Eight Half uint4 vectors cover a warp’s 128 output channels, one per N16 result. Since a low tile’s four output quadrants are unique and channel slabs are disjoint, these stores need no atomics. Keep that property when changing the grid.

10. The helper contracts needed to reconstruct this entry

FMmaAccumulatorTile<M,N> contains [M][N][4] 32-bit words per lane. Each N index means sixteen output channels, built from two N8 MMA instructions; it does not mean a sixteen-byte vector in logical row-major order. AccumulateTile takes an array of four-word A fragments and four-word weight bundles, uses the lower two B words for the first N8 result and upper two for the second, and updates the four Half2 words in place. When two instruction-K subtiles exist, it advances each accumulator through subtile zero before subtile one; the FP16 QKV stage supplies only one K16 subtile. The API’s by-value operands ensure an output update does not change the fragment arguments still being evaluated.

StoreNoAllocate emits an aligned 128-bit global store with an L1 no-allocation request. __ldca loads weights with cache-all policy; residual readers may use __ldcg. These are memory-policy choices rather than barriers or promises that an access reaches a particular cache level. A correct implementation must separately satisfy the synchronization protocol and vector alignment. Direct Half publication preserves the accumulator words, which is precisely why the next packed matrix operation can reuse them without an intermediate logical tensor transpose.

11. A complete source-order reconstruction

12. Reconstruction checks, in the order they isolate errors

  1. Before splitting, compare a full K1024 low projection with a host-decoded matrix reference. Then compare the source-ordered four partials, including Half scratch reductions.
  2. Set the skip scale to zero and project one distinguishable low token: it must appear at exactly the four nearest high positions, subject to cropping.
  3. Set the projection matrix to zero and verify every output channel equals the scaled same-position high skip. This isolates residual layout from repeat addressing.
  4. Verify the lane 0/4/16/20 repetition trace and high pixel (17,25), channel137 example with unique spatial values.
  5. Guard scratch and counter allocations; test both 256-channel slabs, all four splits, and the last low tile’s high crop. Scratch remains Half even in E4 mode.
  6. Run OrderedSplit mode first. Qualify the native counter path separately with its counter initialization, memory-ordering and occupancy assumptions; successful arithmetic tests alone do not prove that synchronization protocol.

These are concrete tests to implement when rebuilding the kernel, not claims that this documentation run executed GPU comparisons. First establish layout and numerical equivalence; then measure latency with the same weights, geometry, precision and stream behavior. A source-level eliminated allocation establishes avoided traffic, but it does not quantify the speedup or prove absence of register spills.

A global allocation is device memory addressed by a pointer; loads can be served by hardware-managed L2 and, depending on the instruction, L1. A cache hit is not another program-visible tensor and the source does not guarantee cache residency. __ldca permits caching at all levels; __ldcg and PTX .cg select global-level caching that bypasses L1. An eviction or no_allocate hint is a performance policy, not a publication barrier.

Shared memory is an explicitly indexed block-local allocation. Another warp may read a producer's values only after the required block barrier or completed asynchronous-copy protocol. A warp shuffle exchanges register values among its active lanes; it does not address shared memory. Arrays named r_… express per-thread values, but only compiler output establishes whether they stay in physical registers or spill to local memory. Tensor-core accumulator fragments are also register operands. These kernels use mma.sync, not TMEM.

51		const uint64_t g_WeightTileBase =
52			g_PackedWeights +
53			uint64_t(TileCoordinates.Split * 256 + ReductionTile * Profile::ReductionStep) * 512 *
54				Profile::ElementBytes +
55			TileCoordinates.g_OutputChannel * 32 + TileCoordinates.Lane * 16;
56		#pragma unroll
57		for (int r_KSubtile = 0; r_KSubtile < 2; ++r_KSubtile)
58			#pragma unroll
59			for (int r_NTile = 0; r_NTile < 8; ++r_NTile)
60				r_Weights[r_KSubtile][r_NTile] = __ldca(
61					reinterpret_cast<const uint4*>(g_WeightTileBase + r_KSubtile * 16384 + r_NTile * 512));
62	};
63
64	const auto IssueStage = [&](int ReductionTile)
65	{
66		const int g_Y = TileCoordinates.g_LowTilesHigh == 1 ? 0 : TileCoordinates.g_TileY;
67		const int g_X = TileCoordinates.g_LowTilesWide == 1 ? 0 : TileCoordinates.g_TileX;
68		const int s_Destination = (ReductionTile % 2) * 1024 + TileCoordinates.Warp * 512;
69		const int s_Barrier = 2048 + (ReductionTile % 2) * 8;
70		if (g_Y < TileCoordinates.g_LowTilesHigh && g_X < TileCoordinates.g_LowTilesWide)
71		{
72			const uint64_t g_Source =
73				g_Input +
74				uint64_t(g_Y * TileCoordinates.g_LowTilesWide + g_X) * 16384 * Profile::ElementBytes +
75				TileCoordinates.Split * 4096 * Profile::ElementBytes +
76				(ReductionTile * 2 + TileCoordinates.Warp) * 512;
77			if (IsCopyProducer(0xffffffffu))
78			{
79				CopyBulk(s_Storage, s_Destination, g_Source, 512, s_Barrier);
80				BarrierExpect(s_Storage, s_Barrier, 512);
81			}
82		}
83		else
84			*reinterpret_cast<uint4*>(s_Storage + s_Destination + TileCoordinates.Lane * 16) =
85				make_uint4(0, 0, 0, 0);
86	};
87
88	// Prime the weight registers and input pipeline before entering the reduction loop.
89	LoadWeights(0);
90	IssueStage(0);
91	ArriveAndWait(s_Storage, 2048);
92	#pragma unroll 1
93	for (int ReductionTile = 0; ReductionTile < Profile::ReductionTiles; ++ReductionTile)
94	{
95		if (ReductionTile + 1 < Profile::ReductionTiles)
96			IssueStage(ReductionTile + 1);
97		uint4 r_Input[1][2];
98		#pragma unroll
99		for (int r_KSubtile = 0; r_KSubtile < 2; ++r_KSubtile)
100			r_Input[0][r_KSubtile] = *reinterpret_cast<const uint4*>(
101				s_Storage + (ReductionTile % 2) * 1024 + r_KSubtile * 512 + TileCoordinates.Lane * 16);
102		AccumulateTile<Profile::Precision>(r_Accumulator, r_Input, r_Weights);
103		if (ReductionTile + 1 < Profile::ReductionTiles)
104		{
105			LoadWeights(ReductionTile + 1);
106			ArriveAndWait(s_Storage, 2048 + ((ReductionTile + 1) % 2) * 8);
107		}
108	}
109
110	if (TileCoordinates.Split > 0)
111	{
112		// The stream boundary orders Half scratch updates without resident peers.
113		if (Parameters.OrderedSplit == 0 && TileCoordinates.Lane == 0 && TileCoordinates.Warp == 0)
114			while (int32_t(CounterLoadRelaxed(g_SplitCounters)) < TileCoordinates.Split - 1)
115				PollSleep(64);
116		__syncthreads();
117	}
118
119	// Split 0 stores Half scratch; splits 1/2 reduce, and split 3 loads without overwriting scratch.
120	if (TileCoordinates.Split < 3)
121	{
122		if (TileCoordinates.g_TileY < TileCoordinates.g_LowTilesHigh &&
123			TileCoordinates.g_TileX < TileCoordinates.g_LowTilesWide)
124		{
125			const uint64_t g_SplitAccumulatorTile =
126				g_SplitAccumulator +
127				uint64_t(TileCoordinates.g_TileY * TileCoordinates.g_LowTilesWide + TileCoordinates.g_TileX) *
128					16384 +
129				TileCoordinates.g_OutputChannel * 32 + TileCoordinates.Lane * 16;
130			#pragma unroll
131			for (int r_NTile = 0; r_NTile < 8; ++r_NTile)
132			{
133				const auto& r_OutputWords = r_Accumulator.r_AccumulatorWords[0][r_NTile];
134				const uint4 r_SplitAccumulatorVector =
135					make_uint4(r_OutputWords[0], r_OutputWords[1], r_OutputWords[2], r_OutputWords[3]);
136				if (TileCoordinates.Split == 0)
137					StoreNoAllocate(g_SplitAccumulatorTile + r_NTile * 512, r_SplitAccumulatorVector);
138				else
139					ReduceHalf4(g_SplitAccumulatorTile + r_NTile * 512, r_SplitAccumulatorVector);
140			}
141		}
142	}
143	else
144	{
145		const int g_Y = TileCoordinates.g_LowTilesHigh == 1 ? 0 : TileCoordinates.g_TileY;
146		const int g_X = TileCoordinates.g_LowTilesWide == 1 ? 0 : TileCoordinates.g_TileX;
147		const bool bValid = g_Y < TileCoordinates.g_LowTilesHigh && g_X < TileCoordinates.g_LowTilesWide;
148		const uint64_t g_SplitAccumulatorTile =
149			g_SplitAccumulator + uint64_t(g_Y * TileCoordinates.g_LowTilesWide + g_X) * 16384 +
150			TileCoordinates.g_OutputChannel * 32 + TileCoordinates.Lane * 16;
151		#pragma unroll
152		for (int r_NTile = 0; r_NTile < 8; ++r_NTile)
153		{
154			const uint4 r_PreviousSplitWords =
155				bValid ? __ldca(reinterpret_cast<const uint4*>(g_SplitAccumulatorTile + r_NTile * 512))
156					   : make_uint4(0, 0, 0, 0);
157			auto& r_OutputWords = r_Accumulator.r_AccumulatorWords[0][r_NTile];
158			r_OutputWords[0] = HalfAdd(r_PreviousSplitWords.x, r_OutputWords[0]);
159			r_OutputWords[1] = HalfAdd(r_PreviousSplitWords.y, r_OutputWords[1]);
160			r_OutputWords[2] = HalfAdd(r_PreviousSplitWords.z, r_OutputWords[2]);
161			r_OutputWords[3] = HalfAdd(r_PreviousSplitWords.w, r_OutputWords[3]);
162		}
163	}
164
165	// Only the final split expands low pixels, adds the scaled residual, and publishes.
166	if (TileCoordinates.Split == 3)
167	{
168		uint32_t r_ResidualScales[8][2];
169		#pragma unroll
170		for (int r_NTile = 0; r_NTile < 8; ++r_NTile)
171			#pragma unroll
172			for (int r_N8 = 0; r_N8 < 2; ++r_N8)
173				r_ResidualScales[r_NTile][r_N8] =
174					*reinterpret_cast<const uint32_t*>(g_PackedWeights + Profile::MatrixBytes +
175													   (TileCoordinates.g_OutputChannel + r_NTile * 16 +
176														r_N8 * 8 + (TileCoordinates.Lane & 3) * 2) *
177														   2);
178
179		// A low 4x4 tile expands into four high 4x4 tiles. Indexed lane shuffles
180		// duplicate each low pixel in X/Y while preserving packed channel ownership.
181		#pragma unroll
182		for (int QuadrantIndex = 0; QuadrantIndex < 4; ++QuadrantIndex)
183		{
184			const int g_OffsetY = QuadrantIndex / 2, g_OffsetX = QuadrantIndex % 2;
185			const int g_OutputY = TileCoordinates.g_TileY * 2 + g_OffsetY,
186					  g_OutputX = TileCoordinates.g_TileX * 2 + g_OffsetX;
187			const int g_SkipY = TileCoordinates.g_HighTilesHigh == 1 ? 0 : g_OutputY;
188			const int g_SkipX = TileCoordinates.g_HighTilesWide == 1 ? 0 : g_OutputX;
189			const bool bValidSkip =
190				g_SkipY < TileCoordinates.g_HighTilesHigh && g_SkipX < TileCoordinates.g_HighTilesWide;
191			const uint64_t g_SkipBase =
192				g_Residual +
193				uint64_t(g_SkipY * TileCoordinates.g_HighTilesWide + g_SkipX) * 8192 * Profile::ElementBytes +
194				TileCoordinates.g_OutputChannel * 16 * Profile::ElementBytes + TileCoordinates.Lane * 16;
195			uint32_t r_Output[8][4];
196			#pragma unroll
197			for (int r_NTile = 0; r_NTile < 8; ++r_NTile)
198			{
199				uint32_t r_ResidualPairs[4];
200				{
201					const uint4 r_PackedResidual =
202						bValidSkip ? __ldca(reinterpret_cast<const uint4*>(g_SkipBase + r_NTile * 512))
203								   : make_uint4(0, 0, 0, 0);
204					r_ResidualPairs[0] = r_PackedResidual.x;
205					r_ResidualPairs[1] = r_PackedResidual.y;
206					r_ResidualPairs[2] = r_PackedResidual.z;
207					r_ResidualPairs[3] = r_PackedResidual.w;
208				}
209				#pragma unroll
210				for (int r_N8 = 0; r_N8 < 2; ++r_N8)
211					#pragma unroll
212					for (int r_RowHalf = 0; r_RowHalf < 2; ++r_RowHalf)
213					{
214						const int r_SourceLane = (TileCoordinates.Lane & 3) |
215												 ((TileCoordinates.Lane >> 1) & 4) | (g_OffsetX * 8) |
216												 (r_RowHalf * 16);
217						const uint32_t r_Nearest =
218							ShuffleIdx(r_Accumulator.r_AccumulatorWords[0][r_NTile][r_N8 * 2 + g_OffsetY],
219									   r_SourceLane, 31, 0xffffffffu);
220						r_Output[r_NTile][r_N8 * 2 + r_RowHalf] =
221							HalfAdd(r_Nearest, HalfMul(r_ResidualPairs[r_N8 * 2 + r_RowHalf],
222													   r_ResidualScales[r_NTile][r_N8]));
223					}
224			}
225			if (g_OutputY >= TileCoordinates.g_HighTilesHigh || g_OutputX >= TileCoordinates.g_HighTilesWide)
226				continue;
227			const uint64_t g_OutputBase = g_Output +
228										  uint64_t(g_OutputY * TileCoordinates.g_HighTilesWide + g_OutputX) *
229											  8192 * Profile::ElementBytes +
230										  TileCoordinates.g_OutputChannel * 16 * Profile::ElementBytes +
231										  TileCoordinates.Lane * 16;
232			#pragma unroll
233			for (int r_Panel = 0; r_Panel < (bFp8 ? 4 : 8); ++r_Panel)
234			{
235				uint4 r_Published;
236				{
237					const auto& r_OutputWords = r_Output[r_Panel];
238					r_Published =
239						make_uint4(r_OutputWords[0], r_OutputWords[1], r_OutputWords[2], r_OutputWords[3]);
240				}
241				StoreNoAllocate(g_OutputBase + r_Panel * 512, r_Published);
242			}
243		}
244	}
245
246	__syncthreads();
247	if (TileCoordinates.Lane == 0 && TileCoordinates.Warp == 0)
248		CounterStoreRelease(g_SplitCounters, TileCoordinates.Split);
249#endif
250}

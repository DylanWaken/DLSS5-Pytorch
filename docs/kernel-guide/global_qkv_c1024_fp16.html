01. The whole problem

global_qkv_c1024_fp16 follows the dense FFN residual in C1024 bottleneck records 31–38. Its input Z is logically [T,1024]. A [1024,3072] matrix produces 32 heads, each containing adjacent Q32,K32,V32 columns. For each token t and head h, Qraw[t,h,:],Kraw[t,h,:],V[t,h,:] = Z[t,:]·W[:,h·96:h·96+96]. Q and K are independently normalized over 32 channels; Q also receives √32 and a learned head scale. V is not normalized. Outputs Q,K,V each have logical shape [T,32,32].

At 4K the bottleneck has 36×60 tokens, T=2160. The kernel uses BatchCount·TokensPerBatch as one physical token extent; the prepared plan uses batch one. This entry’s matrix operands and final publications use FP16; intermediate matrix sums and norm arithmetic are Half. The packed weight record starts with 32 FP32 head scales (128 bytes), followed by the Q/K/V matrix. There is no relative-position bias or attention score calculation in this entry. Its job ends when consumer-ready Q/K/V are published. The surrounding model is described by the architecture document.

Establish the mathematical dependency before choosing a tile

Build the baseline as projection, then Q/K normalization, then consumer-layout publication. It has two different reductions: a 1024-channel dot for each projected value, and a 32-channel squared norm for one token/head. A one-hot input validates projection; changing one head’s values must leave every other head’s norm unchanged. Keeping these tests separate prevents a layout error from being mistaken for normalization error.

The straightforward baseline materializes 2160·3072 Half raw QKV values, or 13,271,040 bytes, before later kernels read them for norm and layout conversion. That write and later reads motivate a fused epilogue. But fusion requires the complete 32-channel head vector to have a local owner. We therefore derive channel tiling from the norm’s communication boundary, instead of taking a square GEMM tile and trying to attach normalization afterward.

02. One CTA: its concrete subproblem

A generic 128-column GEMM tile cuts through 96-column head records. It can leave Q or K’s 32-channel norm spread across ownership regions that must exchange data. Derive N from the epilogue instead: give each warp complete Q32/K32/V32 channel sets. One head is 96 columns, so consider one, two or four heads per CTA, keeping 128 token rows and four warps. The table counts Half accumulators as M·N/(128 threads·2 Half/word).

Two heads produce a 128×192 tile with 96 accumulator words per lane. One head halves accumulator pressure but doubles XY blocks and repeated input-panel reads. Four heads halve XY blocks but use 192 accumulator words before operands, addresses and norm temporaries. The source chooses two heads, then halves the 1024-channel reduction: two K512 partials give 544 logical CTAs instead of 272. This creates another result-sized Half write/read path and ordering dependency. It supplies more independent matrix work only when the launch protocol allows useful concurrency; it does not remove accumulator registers.

Define when the nonlinear epilogue becomes legal

With two K512 candidates, a projected vector is still incomplete after either dot alone. Norm(P₀+P₁) generally differs from Norm(P₀)+Norm(P₁), so delay the epilogue. Let split 0 store ordinary Half Q/K/V fragments and split 1 load and Half-add them, then normalize Q/K and transpose V. Use each Half output allocation as scratch, but document that its layout changes when the final split publishes it. Each K512 slice advances in 16 K32 steps, using two K16 Half instructions per native output fragment per step.

Freeze the numerical boundary as HalfAdd(first 512,last 512), each side already accumulated by Half MMA. A complete-K FP32 GEMM can remain a mathematical baseline, but cannot be the bit-exact oracle for this chosen split program. A diagnostic saved P₀/P₁ fixture should establish the merge before adding norm. In the final implementation split 0 returns before the epilogue; split 1 publishes Q, K, then V.

03. Warp and thread ownership

Keep the whole 96-column head record within one warp, then divide token rows between two warps per head. Warps 0/2 own head 2·headPair and warps 1/3 own the other; warps 0/1 cover rows 0…63 and warps 2/3 rows 64…127. Four M16 ×six N16 fragments require Accumulator[4][6][4], or 96 Half2 words per lane. Four neighboring lanes hold a token’s channel pieces, so its 32-channel norm needs only warp exchanges.

Separate Q, K and V projection kernels would each need fewer live accumulator columns, but would load the input panels for each component and still need a layout/norm publication path. Here keeping all three in one warp reuses A across six N16 panels and permits a register-only epilogue. That saving has a visible cost: 96 C words instead of the ordinary dense kernel’s 64, plus norm and transpose temporaries. The budget in the next section must accommodate them.

One instruction computes a 16-token × 8-output-channel tile with a reduction of 16 channels. All 32 lanes participate in the same matrix operation. Each lane supplies four 32-bit A words, two 32-bit B words, and two 32-bit C words. Each C word contains two Half accumulators, so a lane owns four output elements. A source loop over output groups or reduction panels repeats this operation; it does not launch a new warp.

The exact instruction on this path is mma.sync.aligned.m16n8k16.row.col.f16.f16.f16.f16. Both the accumulator input and output are Half. Do not replace its numerical contract with FP32 accumulation when constructing an exact oracle. For the FP8 path, packing to E4M3 is a distinct rounding step; for the FP16 path a packed word simply holds two Half values.

Let lane L run from 0 to 31, g = L // 4 and q = L % 4. The matrix coordinates below describe instruction operands after any kernel-specific loads and shuffles. Storage layouts are designed to supply these coordinates cheaply.

04. Resource budget

Choose the reduction step and storage role together. K32 gives one A stage of 128·32·2=8,192 bytes. The step is a whole number of native MMA K panels, so producer copies need no partial-panel rearrangement. A synchronous one-stage candidate needs 8,200 bytes including its barrier; two need 16,400; three need 24,600. Each added slot buys a possible future operand, not an automatic amount of latency hiding.

Staging B as well is a plausible alternative: its CTA panel is 192·32·2=12,288 bytes, so a 2-stage B ring would add 24,576 data bytes to the allocation below. The source instead loads packed B directly into registers and reuses it over four M16 fragments. That avoids B shared copies and shared capacity, but the two token warps load the same B panel separately and depend on hardware caching. Keep both costs in the design ledger; a cache hint is not evidence that those duplicate loads are free.

Now express the chosen candidate as actual source objects. A uint4 is four 32-bit words; a Half2 word holds two values. The resulting declaration is exactly 16,400 shared bytes per CTA, including every 8-byte barrier. Alignment constrains the base address; it does not add 512 bytes to the declared size.

05. Execution and scheduling

Build the matrix loop with one blocking slot first, and execute the two split planes in stream order. That isolates the GEMM and merge. Next alternate two A slots so a future panel can be transferred while current work advances; keep B in registers until consumed. Finally allow resident splits only when the host capacity check permits them. Norm and V transpose remain after the final Half merge in either schedule.

Derive two separate conditions for reusing a shared slot

A correct blocking loop already waits after filling a slot and after consuming it. An asynchronous version must preserve both meanings: new bytes have arrived and old readers have retired. Give each of the 2 slots its own 8-byte mbarrier. Lane 0 of warp 0 initializes it for 128 thread arrivals, then synchronize the CTA before any copy. On SM90+, IsCopyProducer elects one lane per participating warp to issue ordinary-address cp.async.bulk with the expected completion byte count. On SM80/89, every lane instead issues 16-byte cp.async.cg stripes and attaches its copies with cp.async.mbarrier.arrive. Thus a 512-byte producer panel takes one stripe/lane and a 1024-byte panel takes two.

Use ArriveAndWait to obtain and wait on the current phase token. Reusing a barrier address does not reuse its previous ready state; attached copy completion also belongs to that phase. To test the resulting schedule, compare a blocking single-slot diagnostic implementation with the ring across several wraparounds, including missing groups. A mismatch appearing only after wraparound points first to slot retirement or phase reuse. The final NCU copy/barrier opcodes can verify that asynchronous instructions executed; they cannot prove absence of a race for all schedules.

Do not add an XOR swizzle or ldmatrix merely because another GEMM tutorial uses them. Those solve a different shared-to-register map. Here the producer provides native fragment vectors, and consumers load those vectors directly. Likewise, this path does not allocate TMEM or use a tensor-map descriptor or warp-group MMA. Each extra transform would need to preserve the already-derived operand map and justify its added work.

06. Trace one token through the source

Follow token 83 and, within it, Q[83,7,18]. Token 83 is group 5, row 3; it belongs to token CTA 0, warp 3, M16 fragment 1, lane 13’s first output row. Lane 13 also carries token 91 because the instruction’s output fragment has two row halves. We retain token 83 as the trace identity throughout: global packed input → shared operand stage → A/B registers → Half accumulator → split partial → normalized Q publication. Adjacent channels and lanes appear only when the collective instruction requires them.

A global allocation is device memory addressed by a pointer; loads can be served by hardware-managed L2 and, depending on the instruction, L1. A cache hit is not another program-visible tensor and the source does not guarantee cache residency. __ldca permits caching at all levels; __ldcg and PTX .cg select global-level caching that bypasses L1. An eviction or no_allocate hint is a performance policy, not a publication barrier.

Shared memory is an explicitly indexed block-local allocation. Another warp may read a producer's values only after the required block barrier or completed asynchronous-copy protocol. A warp shuffle exchanges register values among its active lanes; it does not address shared memory. Arrays named r_… express per-thread values, but only compiler output establishes whether they stay in physical registers or spill to local memory. Tensor-core accumulator fragments are also register operands. These kernels use mma.sync, not TMEM.

Build and test one synchronous projection split

Implement this blocking loop first and save each split’s Half fragments. A small one-hot matrix can validate the multiply independently from norm and transpose. The following milestones fill in every address and epilogue operation; the ring is added only after this version passes.

Implementation milestone 1: make a packed panel round-trip correctly

Before issuing a matrix instruction, implement the scalar pack/decode map and round-trip distinct token/channel tags. The deployment pointers are opaque packed buffers, so a dense row-major fixture would test the wrong contract. Group 16 rows together. One native M16×K16 A panel consumes 512 bytes, distributed as 32 lanes ×16 bytes. For input width K and element size E, group g begins at g·16·K·E. Advance a reduction step in whole panels, and give lane L the vector at L·16. This places four words in the instruction’s required register order without an in-kernel transpose.

A packed B panel for 16 output channels also occupies 512 bytes. One lane’s uint4 supplies two N8 fragments: the first two words belong to the first N8, the next two words to the second. Across K panels, the record advances by N·32 bytes, where this kernel’s N is 3072. The equality follows from 16 reduction values × 2 bytes per value =32 bytes per output column. A cache-all vector load fetches those words directly to registers.

For FP16 weights, packed_f16_weight_index(k,n,N) returns a Half-element offset: panel=(k//16)·ceil(N/16)+n//16; lane=4·(n mod8)+floor((k mod8)/2); within-lane index=4·floor((n mod16)/8)+2·[k mod16≥8]+(k mod2). Multiply the result by two to obtain bytes. This gives you a scalar packer independent of the kernel’s vector-load formula.

Implementation milestone 2: map a complete head before fusing its norm

Use the pack/decode test to isolate the interleaved 96-column head record. Set one matrix row to recognizable Q/K/V channel tags, run the synchronous projection, and inspect token 83/head 7 in each Half partial. Until those tags decode correctly, leave normalization disabled in the diagnostic scaffold: it would destroy the easy-to-recognize values.

A group contains 16 tokens. At split s and step i, A’s slab begins at Z+(g·1024+s·512+i·32)·16·2. Its 1024-byte group slab feeds 2 native panels. The shared stage contains eight groups, or 8192 bytes. Producer copies are 512 bytes: copySlot=warp+4·Copy; group=firstGroup+floor(copySlot/2); subpanel=copySlot mod2. Destination is stage·8192+copySlot·512. Invalid groups receive zero vectors in exactly those shared locations.

For the warp’s register A vectors use (i mod2)·8192+floor(warp/2)·4·1024+lane·16+m·1024+kSubtile·512. Its B vector is W+128+(s·512+i·32)·3072·2+outputChannel·32+lane·16+kSubtile·98304+n16·512. The 128 skips head scales. The 98304 stride is 3072 columns ×32 bytes per native K panel. There are six N16 panels to load, rather than a normal projection’s four.

The selected Q[83,7,18] scalar is at final byte offset 171728: word 0, low Half of the upper-N16 vector at 171728. Its V counterpart changes lanes during the register transpose shown below.

For component p, its Half partial base is the corresponding Q,K or V allocation. Group g/head h/N16 n/lane L writes at base+g·32768+h·1024+n·512+L·16. The second split reads this same map before changing it. That ordering is especially important for V: its first split uses ordinary accumulator order, not the final transposed order. Implementation milestone 3: replace a global norm pass with warp exchanges

The completed projection puts every head vector in four neighboring lanes. A shared reduction array would add stores, reloads and a CTA synchronization for values whose owners are already within one warp. Instead combine each lane’s channel pieces, exchange the four lane partials, and return the norm locally. Validate one nonzero channel and then distinct values in all 32 channels; the first tests ownership, while the second tests the complete reduction and rounding order.

For Q or K, select the component’s lower and upper N16 groups. The source writes each paired contribution as HalfAdd(HalfMul(lower,lower),HalfMul(upper,upper)). In the measured SM120 binary this becomes a packed HMUL2 followed by HFMA2: one square rounds to Half, while the other square and addition fuse before their Half rounding. Inline helper names do not force two separately rounded squares. A bit-exact reconstruction must reproduce this compiled contraction, then the remaining reduction order.

Combine words 2+0 for one token row and 3+1 for the other. Then SumHeadChannels performs Half-add butterflies with lane XOR2 and XOR1 and adds the word with its Half components swapped. This is a reduction across four lanes’ channel pieces of the same row, followed by the two scalar components. It does not exchange tokens or heads.

The squared sum is floored at 0x0410 (6.198883056640625×10⁻⁵) before approximate reciprocal square root. The FP16 specialization calls RsqrtHalf2, which converts each packed component to FP32 for the approximate reciprocal square root and rounds back to Half. Each projected channel is Half-multiplied by its row’s inverse norm. Q is then Half-multiplied by the approximate √32 rounded to Half and the header’s FP32 head scale converted to Half, in that order. The floor and ordering differ from the simplified floating training formula.

The source supports two protocols. With OrderedSplit=0, blockIdx.z is the logical split. A later split may compute its matrix partial while its predecessor runs, but before touching the predecessor’s global partial it polls the corresponding counter until the recorded split is available. The counter starts at −1, and each producer performs a release counter store after its publication and a CTA synchronization. This entry polls relaxed counters and uses a CTA barrier, but does not call the separate acquire helper in this source snapshot. The description records that protocol; it is not a new formal memory-order proof.

The launcher selects this path when the complete dependent grid cannot fit its occupancy-derived capacity; otherwise waiting consumers could occupy resources needed by unscheduled producers. Verify projection, normalization and transpose separately

  1. Projection before norm: use weights with nonzero rows in both K512 halves and compare the raw Half sum after split 1. Normalizing each half independently must fail this test.
  2. Head isolation: make only head 7’s matrix nonzero. Only head 7 Q/K/V should change. Set two different learned scales; Q changes, while K/V remain unchanged.
  3. Norm domain: use a single nonzero channel, an all-zero head, and values near the epsilon floor. The inverse is based on the 32-channel squared sum and remains finite for zero input; zero projected vectors remain zero.
  4. Transpose identity: populate V with distinct token/channel tags in representable values. Decode the final M16 V layout using the consumer’s load map; each tag must return to the intended token/channel, with no accidental Q/K permutation applied.
  5. Precision boundary: compare Half partials, Half-normalized Q/K and final Half words separately. Check Q’s two scale multiplications in order.
  6. Tail/scheduling: exercise legal group tails, two ring wraps, and resident versus ordered launch modes. Keep canaries beyond Q/K/V and Half scratch. The tiny T≤16 broadcast behavior needs a separate fixture.

01. The precise model suboperation: attention output projection

window_attention_projection_output_view_c512_fp16 consumes the attended head tensor A, logically [H,W,512], applies a dense [512,512] channel matrix, and combines a separate learned 512-channel residual scale with the published FFN output Z. Its role is record 47, whose output must be a channel-plane view for the next decoder transition. At the documented 4K input the C512 field is [68,120,512]. Every output position mixes channels from the same position; the projection itself does not read spatial neighbors. Any earlier attention or grouped MLP work has already produced the input tensor.

The network architecture guide, rendered from docs/ARCHITECTURE.md, places this operation in the full encoder–bottleneck–decoder. This lesson defines the operation and its physical implementation locally so it can be read independently.

Write its graph as Yraw[p,n] = Σk Input[p,k]·W[k,n] + scale[n]·R[p,n], then publish Y in Half. R is specifically the published FFN output Z, not the projection input. The formula describes connectivity. The implementation seeds its accumulator with the rounded scaled residual before accumulating K, which defines a more specific numerical sequence than evaluating the sum and adding a residual afterward.

02. Start from a scalar projection plus its exact residual branch

A straightforward first kernel assigns one (pixel,output-channel) pair to a thread, loads 512 inputs and weights, forms a dot product, scales the residual and writes the result. This is an easy correctness baseline but repeats input loads for every output and exposes little reuse. A separate residual-add baseline is also possible, provided its arithmetic is explicitly matched later; it would add an extra read/write pass over the result. The reconstruction will remove those extra passes by putting the scaled residual into C before matrix multiplication.

The working storage format on this page is IEEE Half / FP16. Tensor-core accumulation, residual products, the recovered activation and the reduction trees discussed here use packed Half words. A uint32_t is a bit container for two Half values, not an integer approximation to their sum. HalfMul, HalfAdd and HalfFma preserve the source’s separately rounded operations; replacing them with FP32 expressions and a final cast changes that contract. The operand and accumulator use the same element type, but their lane-word arrangements still differ by matrix role. Equal dtype does not make an arbitrary row-major uint4 a valid MMA fragment.

Start with a high-precision scalar oracle to validate which input contributes to which output. Once the connectivity is correct, introduce a second oracle that follows the source’s K chunk order and publication points. A scalar FP32 sum is not a bitwise reference for Half MMA; it is a tool for catching transposes, wrong groups and wrong spatial coordinates. Keep these two correctness goals separate throughout reconstruction.

03. Give each warp a rectangular matrix result

One CTA owns an 8 × 8 position region and 256 output channels. Let columns=ceil(W/8). The spatial X tile is 2·(blockIdx.x%columns), while blockIdx.x/columns selects the 256-channel slab. Warp channel base is 256·slab+64·(warp%4). There are two channel slabs to cover all 512 outputs. Four warps each own 64 channels over all four M16 spatial fragments. This full-window ownership is useful here because the per-pixel view conversion can be performed directly from all its tile accumulators. The public block shape is (32,4); do not choose a different warp count while retaining these coordinate formulas.

One instruction computes a 16-token × 8-output-channel tile with a reduction of 16 channels. All 32 lanes participate in the same matrix operation. Each lane supplies four 32-bit A words, two 32-bit B words, and two 32-bit C words. Each C word contains two Half accumulators, so a lane owns four output elements. A source loop over output groups or reduction panels repeats this operation; it does not launch a new warp.

The exact instruction on this path is mma.sync.aligned.m16n8k16.row.col.f16.f16.f16.f16. Both the accumulator input and output are Half. Do not replace its numerical contract with FP32 accumulation when constructing an exact oracle. For the FP8 path, packing to E4M3 is a distinct rounding step; for the FP16 path a packed word simply holds two Half values.

Let lane L run from 0 to 31, g = L // 4 and q = L % 4. The matrix coordinates below describe instruction operands after any kernel-specific loads and shuffles. Storage layouts are designed to supply these coordinates cheaply.

The operand and accumulator coordinates follow the NVIDIA PTX matrix-fragment specification. A kernel may permute model channels before supplying these instruction coordinates; its publication and weight-packing rules must agree.

04. Derive byte addresses before writing the fast loop

A native input tile represents sixteen positions in a physical 4 × 4 image patch. Its byte extent is 16·512·2 = 16,384. Tile index q advances by that whole extent, an instruction-K stripe advances by 512 bytes, and lane l selects 16·l bytes within the stripe. Thus one A load is input + q·16384 + stripe·512 + lane·16. For q=7, stripe=1 and lane=13, the base-relative address is 115,408 bytes. The lane reads one uint4 containing eight Half values. These values are already arranged as a matrix operand; they are not simply consecutive channels of one pixel.

The weight record groups output columns into N16 panels and reduction channels into K16 instruction slices. Each instruction slice consumes 16·2=32 bytes per output column. Its lane-vector address is W + reductionStart·512·2 + outputChannel·32 + lane·16 + panel·512. For reductionStart=16, outputChannel=128, panel=1 and lane=13, this is 21,200 bytes. The panel term is relative to the warp’s output base. Adding a complete K slice advances 16,384 bytes, not 512: 512 advances N16, while 16,384 advances all 512 output columns.

Write a small host-side address decoder first. Give each logical input element a distinguishable value, encode a single native tile, and check exactly which token/channel arrives in each lane word. Repeat for one weight panel. This isolates layout errors from arithmetic errors: a wrong transpose can still produce plausible values for uniform inputs. In the kernel, all these pointer expressions use byte offsets because the public ABI passes integer addresses rather than typed multidimensional tensor views.

05. Place the residual in accumulator order before the reduction

The packed record holds 512·512·2 = 524,288 matrix bytes, followed by 512 Half scale values, another 1,024 bytes. For an output channel c, the scale address is W+524288+2c. Four lanes cooperate on an N8 row; each lane reads the two scale values corresponding to its channel pair, then uses the same pair for both row halves. Scales remain Half even when the large matrix uses E4. This small but essential mixed-precision field makes “every byte in an FP8 weight record is FP8” an incorrect assumption.

06. Overlap input movement without reusing live bytes

The scalar baseline reloads input independently for each output. Our tiled version first shares an input stripe among output-panel computations. A synchronous prototype can copy a stage, execute a CTA barrier, consume every fragment, then execute a second barrier before overwriting the stage. That establishes correct producer/consumer ownership. The deployed kernel replaces the idle copy phase with a 3-slot ring. A slot holds 4,096 data bytes; its 8-byte barrier lives after all data slots, so the allocation is 3·(4096+8) = 12,312 bytes.

CopyBulk accepts a shared byte offset, a global address, byte count and barrier offset. On SM90+ it uses a bulk asynchronous copy with transaction-byte completion and an elected producer; BarrierExpect registers the expected bytes. On supported earlier targets the helper distributes 16-byte copies across warp lanes and attaches their completion to the mbarrier. BarrierExpect is then intentionally a no-op because that path does not use the transaction-byte mechanism. Initialize every stage barrier once with the full CTA arrival count, then synchronize before any copy can refer to it. An out-of-domain stripe is filled with zeros by its lane writers; those threads still join the barrier protocol.

The prologue loads W0, issues the first 3 input stages and waits for stage zero. Iteration t reads slot t%3, performs its MMA work, loads the next weights and waits for the next stage. Only then does it issue t+3 into the old slot. The intervening full-CTA arrival/wait establishes that all warps have finished the previous read phase before anyone recycles its storage. Preserve this order even if a local warp has already consumed its own fragment.

The 16 outer iterations stay rolled in the source, while spatial, N-panel and instruction-K fragment loops unroll. That lets fixed array indices select register values without expanding the entire long reduction into a huge instruction stream. More stages can hide more copy latency but consume shared memory; more fragments improve operand reuse but increase live registers. Those are the relevant tradeoffs, not a claim that a larger ring is always faster. __maxnreg__ supplies a compiler limit, not an observed register count. Inspect generated resource reports and time representative shapes before changing either knob.

Notice what does not enter shared memory: the weight fragments and the residual accumulator. Weights are fetched as lane vectors and reused across the warp’s spatial fragments. The input stage is shared because several output-group warps need those same bytes. This asymmetry is the optimization: stage the operand with cross-warp reuse, keep independent output ownership in registers, and choose weight cache policy without inventing a second staging ring. It also explains why doubling shared memory for weights is not an automatically beneficial change.

07. Write the destination view directly from accumulator words

The destination is a channel-plane view, selected specifically at record 47 so the C512→C256 decoder transition can gather spatial pixels. A baseline would publish native tiles and then run a tensor-layout conversion. This kernel eliminates that intermediate write/read by choosing the final address separately for each row-half word. For tile coordinates ty,tx, pixel y is 4ty+lane/16+2·rowHalf and x is 4tx+(lane/4)%4. The word address is output+((panel·H+y)·W+x)·16+4(lane&3).

Each N16 group is two N8 Half channel panels. Word 0/1 selects the lower-N8 panel at the two y coordinates; word 2/3 selects the upper panel. The two panel halves are separated by an entire H×W×16-byte plane. For lane=13,tile=(1,2),rowHalf=0, output base=128 and N16 group=2, the lower-N8 panel is 20. With H=68,W=120 its word offset is 2,619,060 bytes. Verify this address independently before attempting a full image.

08. The helper contracts needed to reconstruct this entry

FMmaAccumulatorTile<M,N> contains [M][N][4] 32-bit words per lane. Each N index means sixteen output channels, built from two N8 MMA instructions; it does not mean a sixteen-byte vector in logical row-major order. AccumulateTile takes an array of four-word A fragments and four-word weight bundles, uses the lower two B words for the first N8 result and upper two for the second, and updates the four Half2 words in place. When two instruction-K subtiles exist, it advances each accumulator through subtile zero before subtile one; the FP16 QKV stage supplies only one K16 subtile. The API’s by-value operands ensure an output update does not change the fragment arguments still being evaluated.

StoreNoAllocate emits an aligned 128-bit global store with an L1 no-allocation request. __ldca loads weights with cache-all policy; residual readers may use __ldcg. These are memory-policy choices rather than barriers or promises that an access reaches a particular cache level. A correct implementation must separately satisfy the synchronization protocol and vector alignment. Direct Half publication preserves the accumulator words, which is precisely why the next packed matrix operation can reuse them without an intermediate logical tensor transpose.

09. Final reconstruction, preserving every lifetime

10. Reconstruction checks, in the order they isolate errors

  1. Use zero W and distinguishable R/scale channels: the output must be the correctly published scaled published FFN output Z, not a scaled copy of the projection input.
  2. Use identity W with zero residual scales to prove the 512-channel projection and byte layout independently. Then test a non-diagonal permutation to detect K/N transposes.
  3. Use one nonzero lane-owned channel at a time, including both N8 halves and both row halves; validate the numeric address example and both 256-channel slabs.
  4. Exercise H=68,W=120, the last native tile row, and any supported singleton tile case. Compare every published position with decoded logical output.
  5. Compare direct output-plane publication against an independently decoded native result, including plane boundaries and row-half y offsets.
  6. Vary CTA scheduling and run a synchronization checker after any change to stage recycling. Confirm the final iteration neither waits on nor loads a nonexistent K panel.

These are concrete tests to implement when rebuilding the kernel, not claims that this documentation run executed GPU comparisons. First establish layout and numerical equivalence; then measure latency with the same weights, geometry, precision and stream behavior. A source-level eliminated allocation establishes avoided traffic, but it does not quantify the speedup or prove absence of register spills.

A global allocation is device memory addressed by a pointer; loads can be served by hardware-managed L2 and, depending on the instruction, L1. A cache hit is not another program-visible tensor and the source does not guarantee cache residency. __ldca permits caching at all levels; __ldcg and PTX .cg select global-level caching that bypasses L1. An eviction or no_allocate hint is a performance policy, not a publication barrier.

Shared memory is an explicitly indexed block-local allocation. Another warp may read a producer's values only after the required block barrier or completed asynchronous-copy protocol. A warp shuffle exchanges register values among its active lanes; it does not address shared memory. Arrays named r_… express per-thread values, but only compiler output establishes whether they stay in physical registers or spill to local memory. Tensor-core accumulator fragments are also register operands. These kernels use mma.sync, not TMEM.

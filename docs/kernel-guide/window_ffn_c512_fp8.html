01. The model operation this kernel must implement

window_ffn_c512_fp8 implements the premix and grouped MLP portion of a C512 FFN. It receives native tiled X with logical shape [H,W,512] and produces the contracted branch tensor B of the same shape. This is the ordinary C512 path used where the input already has native 4 × 4 tile storage, within records 23–30 and 40–47 according to launch selection. At the documented 4K geometry H=68 and W=120. Its output still needs a separate 512→512 postmix and scaled residual before becoming the block’s FFN result. Neither attention nor that postmix is silently included here.

The network architecture guide, rendered from docs/ARCHITECTURE.md, places this operation in the full encoder–bottleneck–decoder. This lesson defines the operation and its physical implementation locally so it can be read independently.

For one position p, compute u[p,:] = X[p,:] Wpre. Partition the 512 premixed channels into eight distinct slices u[p,64g:64g+64]. Group g computes B[p,64g:64g+64] = φ(u_g Wexpand_g) Wcontract_g, with matrices [64,256] and [256,64]. All eight groups execute. The first matrix is [512,512]; its purpose is to mix original channels before slicing. This differs from a full-input branch model: each grouped expansion reads only its own 64 premixed channels.

02. Build the simplest correct graph before tiling it

A first implementation can materialize u, a [H,W,8,256] hidden tensor and B. Assign one scalar output element to a thread and sum its input channels. This makes the grouping unambiguous: contraction for group 3 must read group 3’s hidden values, not any other group. It also exposes the costs we will remove: writing and rereading the dense premix, materializing a four-times-expanded hidden tensor, and fetching the same input vector independently for each output channel.

The working storage format on this page is E4M3 FP8. Tensor-core accumulation, residual products, the recovered activation and the reduction trees discussed here use packed Half words. A uint32_t is a bit container for two Half values, not an integer approximation to their sum. HalfMul, HalfAdd and HalfFma preserve the source’s separately rounded operations; replacing them with FP32 expressions and a final cast changes that contract. E4 publication calls PackHalfPairsE4 on two Half2 words and produces four bytes. DecodeE4 performs the reverse operand preparation when a residual must participate in Half arithmetic. There is no scale tensor passed to those conversions.

Start with a high-precision scalar oracle to validate which input contributes to which output. Once the connectivity is correct, introduce a second oracle that follows the source’s K chunk order and publication points. A scalar FP32 sum is not a bitwise reference for Half MMA; it is a tool for catching transposes, wrong groups and wrong spatial coordinates. Keep these two correctness goals separate throughout reconstruction.

03. Tile output ownership so a group’s intermediates stay local

A CTA covers one 8 × 8 position region and four groups. Grid Z selects groups 0–3 or 4–7, and group ownership is (warp%4)+4·blockIdx.z. The block is (32,8). Eight warps divide the region into upper and lower halves: warp/4 chooses the two-fragment row, while warp%4 chooses the group. Each warp therefore retains 32 positions × 64 outputs. This arrangement makes expansion and contraction warp-local once the premix finishes; no inter-warp hidden exchange is required.

One instruction computes a 16-token × 8-output-channel tile with a reduction of 32 channels. All 32 lanes participate in the same matrix operation. Each lane supplies four 32-bit A words, two 32-bit B words, and two 32-bit C words. Each C word contains two Half accumulators, so a lane owns four output elements. A source loop over output groups or reduction panels repeats this operation; it does not launch a new warp.

The exact instruction on this path is mma.sync.aligned.m16n8k32.row.col.f16.e4m3.e4m3.f16. Both the accumulator input and output are Half. Do not replace its numerical contract with FP32 accumulation when constructing an exact oracle. For the FP8 path, packing to E4M3 is a distinct rounding step; for the FP16 path a packed word simply holds two Half values.

Let lane L run from 0 to 31, g = L // 4 and q = L % 4. The matrix coordinates below describe instruction operands after any kernel-specific loads and shuffles. Storage layouts are designed to supply these coordinates cheaply.

Per-lane operandLogical matrix coordinates

The operand and accumulator coordinates follow the NVIDIA PTX matrix-fragment specification. A kernel may permute model channels before supplying these instruction coordinates; its publication and weight-packing rules must agree.

Under the microscope: what exactly enters one MMA?

For lane L, let g=L//4 and q=L%4. The highlighted A scalar uses g=3,q=1; B uses g=2,q=1. The output scalar uses g=3,q=1 again. These are three operand ownership maps, not a chain of thread-to-thread scalar multiplies. The selected result is the low Half of D word 0. For a pointwise projection, the row stays the same model token and N labels learned output channels; in QKᵀ, N instead labels key tokens.

In this repository’s native E4 activation packing, instruction K=4 corresponds to model channel 2: packed_input_index(4)=2. The packed weights use the matching inverse permutation. A physical byte labeled K=4 must not be read as model channel 4. For probability-times-value, apply the same distinction to the key axis.

04. Derive byte addresses before writing the fast loop

A native input tile represents sixteen positions in a physical 4 × 4 image patch. Its byte extent is 16·512·1 = 8,192. Tile index q advances by that whole extent, an instruction-K stripe advances by 512 bytes, and lane l selects 16·l bytes within the stripe. Thus one A load is input + q·8192 + stripe·512 + lane·16. For q=7, stripe=1 and lane=13, the base-relative address is 58,064 bytes. The lane reads one uint4 containing sixteen E4 values. These values are already arranged as a matrix operand; they are not simply consecutive channels of one pixel.

The weight record groups output columns into N16 panels and reduction channels into K32 instruction slices. Each instruction slice consumes 32·1=32 bytes per output column. Its lane-vector address is W + reductionStart·512·1 + outputChannel·32 + lane·16 + panel·512. For reductionStart=32, outputChannel=128, panel=1 and lane=13, this is 21,200 bytes. The panel term is relative to the warp’s output base. Adding a complete K slice advances 16,384 bytes, not 512: 512 advances N16, while 16,384 advances all 512 output columns.

Write a small host-side address decoder first. Give each logical input element a distinguishable value, encode a single native tile, and check exactly which token/channel arrives in each lane word. Repeat for one weight panel. This isolates layout errors from arithmetic errors: a wrong transpose can still produce plausible values for uniform inputs. In the kernel, all these pointer expressions use byte offsets because the public ABI passes integer addresses rather than typed multidimensional tensor views.

05. Compute premix once, then stream hidden panels

For a single instruction-K step, an input A fragment is reused across four N16 output panels, and each weight B bundle is reused across the warp’s 2 spatial fragments. That is the first improvement over scalar outputs: input and weight fetches pay for multiple independent MMA results. Four-word accumulators remain live across the full K=512 reduction. When it completes, they already represent the group’s 64 premixed channels in the order needed by the next multiply.

The hidden tensor is the next expensive allocation. We do not need all 256 hidden channels at once: the contraction is a sum over them. Visit eight panels of 32 hidden channels, allocate only that panel’s accumulator, expand from the 64-channel group, activate it, and immediately add its contraction contribution to B. This keeps the complete premix slice and final output but only one hidden panel. The tradeoff is a longer lifetime for output accumulators; the benefit is removing the full hidden image write/read and the premix image write/read.

The packed record contains 262,144 premix elements, then eight 16,384-element expansions, then eight 16,384-element contractions. Group g’s bases are (262144+16384g)·1 and (393216+16384g)·1 bytes. For group 5 these are 344,064 and 475,136 bytes. Add lane·16 and the selected hidden/K/N panel offsets only after selecting that group’s matrix. This prevents the common bug of treating each group’s expansion and contraction as interleaved in the record.

06. Overlap input movement without reusing live bytes

The scalar baseline reloads input independently for each output. Our tiled version first shares an input stripe among output-panel computations. A synchronous prototype can copy a stage, execute a CTA barrier, consume every fragment, then execute a second barrier before overwriting the stage. That establishes correct producer/consumer ownership. The deployed kernel replaces the idle copy phase with a 2-slot ring. A slot holds 4,096 data bytes; its 8-byte barrier lives after all data slots, so the allocation is 2·(4096+8) = 8,208 bytes.

CopyBulk accepts a shared byte offset, a global address, byte count and barrier offset. On SM90+ it uses a bulk asynchronous copy with transaction-byte completion and an elected producer; BarrierExpect registers the expected bytes. On supported earlier targets the helper distributes 16-byte copies across warp lanes and attaches their completion to the mbarrier. BarrierExpect is then intentionally a no-op because that path does not use the transaction-byte mechanism. Initialize every stage barrier once with the full CTA arrival count, then synchronize before any copy can refer to it. An out-of-domain stripe is filled with zeros by its lane writers; those threads still join the barrier protocol.

The prologue loads W0, issues X0 and waits for slot zero. Iteration t issues X[t+1] into the other slot before consuming X[t]. It then prefetches W[t+1] and waits on the next slot. Every warp reaches that wait only after reading its current stage, so the later producer phase can recycle it. The final iteration skips both the nonexistent refill and the next wait.

The 8 outer iterations stay rolled in the source, while spatial, N-panel and instruction-K fragment loops unroll. That lets fixed array indices select register values without expanding the entire long reduction into a huge instruction stream. More stages can hide more copy latency but consume shared memory; more fragments improve operand reuse but increase live registers. Those are the relevant tradeoffs, not a claim that a larger ring is always faster. __maxnreg__ supplies a compiler limit, not an observed register count. Inspect generated resource reports and time representative shapes before changing either knob.

Shared-memory address bits and banks

The layout already matches uint4 fragment loads. A producer places lane L’s four words at panel+16L, and the consumer reads that same vector. No lane XOR row transformation is applied here. The 32-bank, four-byte-word model follows the CUDA shared-memory bank description. A bank-conflict diagnosis must use the emitted instruction and its transaction grouping; the same bank number across a whole warp is insufficient evidence.

07. Publish only the contracted branch tensor

For native output tile q, group g and lane l, the first vector goes to B+q·8192+g·1024+16l. Two E4 vectors per lane cover the 64-channel group; each packs two N16 accumulator groups. For q=7, g=5 and l=13, the first vector address is 62,672 bytes from B. Clip spatial tiles before storing. Every valid output group is written by exactly one warp, so no atomic is necessary.

08. The helper contracts needed to reconstruct this entry

FMmaAccumulatorTile<M,N> contains [M][N][4] 32-bit words per lane. Each N index means sixteen output channels, built from two N8 MMA instructions; it does not mean a sixteen-byte vector in logical row-major order. AccumulateTile takes an array of four-word A fragments and four-word weight bundles, uses the lower two B words for the first N8 result and upper two for the second, and updates the four Half2 words in place. When two instruction-K subtiles exist, it advances each accumulator through subtile zero before subtile one; the FP16 QKV stage supplies only one K16 subtile. The API’s by-value operands ensure an output update does not change the fragment arguments still being evaluated.

StoreNoAllocate emits an aligned 128-bit global store with an L1 no-allocation request. __ldca loads weights with cache-all policy; residual readers may use __ldcg. These are memory-policy choices rather than barriers or promises that an access reaches a particular cache level. A correct implementation must separately satisfy the synchronization protocol and vector alignment. PackHalfPairsE4 changes both element width and which channel pairs occupy the low and high halves of a word. Its order is part of the layout; substituting any four E4 conversions without matching that order is incorrect.

09. A complete reconstruction checklist in executable order

10. Reconstruction checks, in the order they isolate errors

  1. Pack an identity premix and group-distinguishing expansion/contract matrices; prove that group g reads only its own premixed 64 channels and that all eight output groups appear.
  2. Validate the numeric input and output addresses above with a single nonzero token/channel; compare native storage with a decoded logical [H,W,512] view.
  3. Run H=68,W=120 and a small multi-tile shape to exercise an incomplete 8×8 bottom edge; separately exercise the explicitly supported singleton-tile broadcast policy.
  4. Check both grid-Z group slabs and, for an eight-warp launch, both upper/lower spatial halves. Make every warp’s expected output visibly different.
  5. Use values near Half and E4 rounding boundaries to test the premix-publication, post-activation-publication and final-publication locations. Do not validate only with ones.
  6. Use synchronization checking when altering the copy loop; an input stage may be overwritten only after every participating consumer has finished.

These are concrete tests to implement when rebuilding the kernel, not claims that this documentation run executed GPU comparisons. First establish layout and numerical equivalence; then measure latency with the same weights, geometry, precision and stream behavior. A source-level eliminated allocation establishes avoided traffic, but it does not quantify the speedup or prove absence of register spills.

A global allocation is device memory addressed by a pointer; loads can be served by hardware-managed L2 and, depending on the instruction, L1. A cache hit is not another program-visible tensor and the source does not guarantee cache residency. __ldca permits caching at all levels; __ldcg and PTX .cg select global-level caching that bypasses L1. An eviction or no_allocate hint is a performance policy, not a publication barrier.

Shared memory is an explicitly indexed block-local allocation. Another warp may read a producer's values only after the required block barrier or completed asynchronous-copy protocol. A warp shuffle exchanges register values among its active lanes; it does not address shared memory. Arrays named r_… express per-thread values, but only compiler output establishes whether they stay in physical registers or spill to local memory. Tensor-core accumulator fragments are also register operands. These kernels use mma.sync, not TMEM.

17													(int(threadIdx.y) % 4) + int(blockIdx.z) * 4,
18													int(threadIdx.x),
19													int(threadIdx.y)};
20
21	// Initialize the shared copy barriers before any warp issues input transactions.
22	if (TileCoordinates.Lane == 0 && TileCoordinates.Warp == 0)
23	{
24		BarrierInit(s_Storage, 8192, Profile::Warps * 32);
25		BarrierInit(s_Storage, 8200, Profile::Warps * 32);
26	}
27
28	__syncthreads();
29
30	uint4 r_Weights[2][4];
31
32	// Prefill and refill share the same addressing and native copy protocol.
33	const auto LoadWeights = [&](int ReductionTile)
34	{
35		const uint64_t g_WeightTileBase =
36			Parameters.g_PackedWeights +
37			uint64_t(ReductionTile * Profile::ReductionStep) * 512 * Profile::ElementBytes +
38			TileCoordinates.g_ExpertGroup * 2048 + TileCoordinates.Lane * 16;
39		#pragma unroll
40		for (int r_KSubtile = 0; r_KSubtile < 2; ++r_KSubtile)
41			#pragma unroll
42			for (int r_NTile = 0; r_NTile < 4; ++r_NTile)
43				r_Weights[r_KSubtile][r_NTile] = __ldca(
44					reinterpret_cast<const uint4*>(g_WeightTileBase + r_KSubtile * 16384 + r_NTile * 512));
45	};
46
47	// Stage bounded input tiles with async copies; reuse the same addressing on refill.
48	const auto IssueInput = [&](int ReductionTile)
49	{
50		{
51			const int s_StageOffset = (ReductionTile % 2) * 4096;
52			const int s_BarrierOffset = 8192 + (ReductionTile % 2) * 8;
53			const int KSubtileIndex = TileCoordinates.Warp & 1;
54			const int g_LocalX = (TileCoordinates.Warp / 2) % 2;
55
56			// Eight FP8 warps each transfer 512 bytes; four Half warps each transfer
57			// two rows. Singleton dimensions broadcast, other incomplete edges zero-fill.
58			#pragma unroll
59			for (int CopyIndex = 0; CopyIndex < (bFp8 ? 1 : 2); ++CopyIndex)
60			{
61				const int g_LocalY = bFp8 ? TileCoordinates.Warp / 4 : CopyIndex;
62				const int g_Y = TileCoordinates.g_TilesHigh == 1 ? 0 : TileCoordinates.g_TileY + g_LocalY;
63				const int g_X = TileCoordinates.g_TilesWide == 1 ? 0 : TileCoordinates.g_TileX + g_LocalX;
64				const int s_CopyOffset =
65					s_StageOffset + g_LocalY * 2048 + g_LocalX * 1024 + KSubtileIndex * 512;
66				if (g_Y < TileCoordinates.g_TilesHigh && g_X < TileCoordinates.g_TilesWide)
67				{
68					const uint64_t g_Source =
69						Parameters.g_Input +
70						uint64_t(g_Y * TileCoordinates.g_TilesWide + g_X) * Profile::SpatialTileBytes +
71						(ReductionTile * 2 + KSubtileIndex) * 512;
72					if (IsCopyProducer(0xffffffffu))
73					{
74						CopyBulk(s_Storage, s_CopyOffset, g_Source, 512, s_BarrierOffset);
75						BarrierExpect(s_Storage, s_BarrierOffset, 512);
76					}
77				}
78				else
79					*reinterpret_cast<uint4*>(s_Storage + s_CopyOffset + TileCoordinates.Lane * 16) =
80						make_uint4(0, 0, 0, 0);
81			}
82		}
83	};
84
85	// Wait for the selected shared-memory stage before its fragments are consumed.
86	const auto WaitInput = [&](int ReductionTile)
87	{
88		const int s_BarrierOffset = 8192 + (ReductionTile % 2) * 8;
89		{
90		}
91
92		ArriveAndWait(s_Storage, s_BarrierOffset);
93	};
94
95	// Prime the weight registers and input pipeline before entering the reduction loop.
96	LoadWeights(0);
97	IssueInput(0);
98	WaitInput(0);
99	FMmaAccumulatorTile<Profile::SpatialFragments, 4> r_Projected{};
100
101	// Two-stage pipeline: issue the next input before current MMA work, then
102	// fetch its weights and wait. The final iteration neither refills nor waits.
103	#pragma unroll 1
104	for (int ReductionTile = 0; ReductionTile < Profile::ReductionTiles; ++ReductionTile)
105	{
106		if (ReductionTile + 1 < Profile::ReductionTiles)
107		{
108			IssueInput(ReductionTile + 1);
109		}
110
111		uint4 r_Input[Profile::SpatialFragments][2];
112		#pragma unroll
113		for (int r_Spatial = 0; r_Spatial < Profile::SpatialFragments; ++r_Spatial)
114			#pragma unroll
115			for (int r_KSubtile = 0; r_KSubtile < 2; ++r_KSubtile)
116				r_Input[r_Spatial][r_KSubtile] = *reinterpret_cast<const uint4*>(
117					s_Storage + (ReductionTile % 2) * 4096 +
118					(bFp8 && !bInputView ? (TileCoordinates.Warp / 4) * 2048 : 0) + r_Spatial * 1024 +
119					r_KSubtile * 512 + TileCoordinates.Lane * 16);
120		AccumulateTile<Profile::Precision>(r_Projected, r_Input, r_Weights);
121		if (ReductionTile + 1 < Profile::ReductionTiles)
122		{
123			LoadWeights(ReductionTile + 1);
124			WaitInput(ReductionTile + 1);
125		}
126	}
127
128	FMmaAccumulatorTile<Profile::SpatialFragments, 4> r_Output{};
129
130	// Grouped MLP keeps each hidden panel in registers through expansion and contraction.
131	const uint64_t g_Expand = Parameters.g_PackedWeights +
132							  (262144 + TileCoordinates.g_ExpertGroup * 16384) * Profile::ElementBytes +
133							  TileCoordinates.Lane * 16;
134	const uint64_t g_Contract = Parameters.g_PackedWeights +
135								(393216 + TileCoordinates.g_ExpertGroup * 16384) * Profile::ElementBytes +
136								TileCoordinates.Lane * 16;
137
138	// Hidden activations stay in registers. Processing 32 hidden channels at a
139	// time avoids materializing the 256-channel intermediate in shared/global memory.
140	#pragma unroll 1
141	for (int HiddenTileIndex = 0; HiddenTileIndex < 8; ++HiddenTileIndex)
142	{
143		FMmaAccumulatorTile<Profile::SpatialFragments, 2> r_Hidden{};
144		#pragma unroll
145		for (int r_KPair = 0; r_KPair < 2; ++r_KPair)
146		{
147			{
148				uint4 r_Input[Profile::SpatialFragments], r_Weights[2];
149				#pragma unroll
150				for (int r_Spatial = 0; r_Spatial < Profile::SpatialFragments; ++r_Spatial)
151					r_Input[r_Spatial] = LoadWindowFfnInputFragment<true>(r_Projected, r_Spatial, r_KPair);
152				#pragma unroll
153				for (int r_NTile = 0; r_NTile < 2; ++r_NTile)
154					r_Weights[r_NTile] = __ldca(reinterpret_cast<const uint4*>(
155						g_Expand + HiddenTileIndex * 1024 + r_KPair * 8192 + r_NTile * 512));
156				AccumulateWindowFfnSingleFp8(r_Hidden, r_Input, r_Weights);
157			}
158		}
159
160		#pragma unroll
161		for (int r_Spatial = 0; r_Spatial < Profile::SpatialFragments; ++r_Spatial)
162			#pragma unroll
163			for (int r_NTile = 0; r_NTile < 2; ++r_NTile)
164				#pragma unroll
165				for (int r_Word = 0; r_Word < 4; ++r_Word)
166					r_Hidden.r_AccumulatorWords[r_Spatial][r_NTile][r_Word] =
167						FfnActivation(r_Hidden.r_AccumulatorWords[r_Spatial][r_NTile][r_Word]);
168
169		{
170			uint4 r_Input[Profile::SpatialFragments], r_Weights[4];
171			#pragma unroll
172			for (int r_Spatial = 0; r_Spatial < Profile::SpatialFragments; ++r_Spatial)
173				r_Input[r_Spatial] = LoadWindowFfnInputFragment<true>(r_Hidden, r_Spatial, 0);
174			#pragma unroll
175			for (int r_NTile = 0; r_NTile < 4; ++r_NTile)
176				r_Weights[r_NTile] = __ldca(
177					reinterpret_cast<const uint4*>(g_Contract + HiddenTileIndex * 2048 + r_NTile * 512));
178			AccumulateWindowFfnSingleFp8(r_Output, r_Input, r_Weights);
179		}
180	}
181
182	// Publish contracted expert fragments only for valid spatial tiles.
183	#pragma unroll
184	for (int r_Spatial = 0; r_Spatial < Profile::SpatialFragments; ++r_Spatial)
185	{
186		const int g_Y =
187			TileCoordinates.g_TileY + (bFp8 && !bInputView ? TileCoordinates.Warp / 4 : r_Spatial / 2);
188		const int g_X = TileCoordinates.g_TileX + (bFp8 && !bInputView ? r_Spatial : r_Spatial % 2);
189		if (g_Y >= TileCoordinates.g_TilesHigh || g_X >= TileCoordinates.g_TilesWide)
190			continue;
191		const uint64_t g_OutputTileBase =
192			Parameters.g_Output +
193			uint64_t(g_Y * TileCoordinates.g_TilesWide + g_X) * Profile::SpatialTileBytes +
194			TileCoordinates.g_ExpertGroup * 1024 * Profile::ElementBytes + TileCoordinates.Lane * 16;
195		#pragma unroll
196		for (int r_NTile = 0; r_NTile < (bFp8 ? 2 : 4); ++r_NTile)
197			StoreNoAllocate(g_OutputTileBase + r_NTile * 512,
198							LoadWindowFfnInputFragment<bFp8>(r_Output, r_Spatial, r_NTile));
199	}
200#else
201	// Keep the exported entry on older targets, but never silently skip FP8 work.
202	__trap();
203#endif
204}

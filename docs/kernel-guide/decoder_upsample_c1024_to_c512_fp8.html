01. The whole problem

The transition contract is L[p,n]=Σk=0…1023 X[p,k]W[k,n], followed by Y[y,x,n]=publish(L[floor(y/2),floor(x/2),n]+scale[n]·skip[y,x,n]). X is [36,60,1024], W is [1024,512], and the high skip/output is [68,120,512]. Repeating the low result nominally produces [72,120,512]; crop its last four rows. The skip contribution is specific to each high destination even though four destinations share one projected low token.

The network architecture guide places this operation in the full encoder–bottleneck–decoder. This lesson defines the operation and its physical implementation locally so it can be read independently.

Build the first baseline as a complete K1024 projection, followed by nearest repetition and skip merge. This separates channel arithmetic from spatial addressing and computes each expensive dot product once per low token. There is no grouped FFN or attention here. After that baseline works, ask whether the small low-resolution field supplies enough independent blocks. Splitting K can supply more work, but requires additional reduction storage, ordering and Half rounding boundaries. We will derive that tradeoff before adopting the four-split implementation decoder_upsample_c1024_to_c512_fp8.

02. One CTA: its concrete subproblem

Choose a first job of one low 4×4 tile and 256 outputs, with the full K1024 reduction. Fifteen tile columns, nine rows and two channel slabs yield 270 independent CTAs. A K4 split gives each CTA only K256, exposing 1,080 partial jobs; a hypothetical K8 split gives K128 and 2,160 jobs. The additional jobs are not free: an analogous ordered K4 scratch protocol performs one initialization store, two read-modify-writes and one final read per result, six logical Half element transfers. K8 would need fourteen; unsplit K needs none. These are logical payload operations, not measured DRAM bytes.

Implement K4 only after the unsplit oracle works. Grid XY=(30,9), block=(32,2); native grid Z gives grid=(30,9,4), while OrderedSplit mode uses four stream-ordered launches of grid=(30,9,1). Decode tileX=blockIdx.x%15 and slab=blockIdx.x/15. At blockIdx.x=23, tile column is 8 and slab base is 256; warp 1 owns channels 384…511. Split 2 covers channels 512…767. Only split 3 may publish the high result. Section 6 will compare these derived launch modes with the recorded one.

03. Warp and thread ownership

The 16×256 partial result needs 2,048 Half2 words per CTA. One warp would hold 64 words per lane, two warps 32, and four warps 16. Two warps give a useful middle candidate while matching two producer stripes. Each owns the same sixteen positions and a distinct 128-channel band: one M16 fragment and eight N16 panels. A four-warp variant would need a revised copy assignment and more participating barrier threads; lower C state alone is not proof of a faster kernel.

Set channelBase=256·slab+128·warp. Producer warp 0 fills the first instruction-K stripe and warp 1 the second; both consumers need both stripes. This gives one complete spatial fragment in each owner, so nearest repetition can later shuffle low values directly to high destinations. The worked trace uses CTA (0,0), warp 1, lane 0, low token (0,0), channel 128.

One warp's result has 1 M16 spatial fragments and 8 N16 channel panels. For lane l, let g=l/4 and q=l%4, using integer division. In one N16 panel, word 0 holds row g at columns 2q and 2q+1; word 1 holds row g+8 at the same pair; words 2/3 add eight columns. Coordinates in this lesson are (y,x). Native matrix row g maps to physical x=g%4,y=g/4; row g+8 adds two to y. A lane therefore owns pieces of two tokens. It never owns a complete dot product independently.

mma.sync.aligned.m16n8k32.row.col.f16.e4m3.e4m3.f16 is a converged 32-lane operation. Four A words and two B words per lane collectively describe its operands; two Half2 accumulator words per lane describe the N8 result. Two N8 instructions build an N16 panel. Input fragments are reused across output panels; a weight bundle is reused across the warp's spatial fragments. The diagram maps Half C/D words in both modes. FP8 A bytes are formed by explicit E4 publication; do not reinterpret a Half accumulator array as FP8 without that conversion.

04. Resource budget

A K-stage has sixteen positions ×K64×1 bytes = 1,024 bytes. One/two/three slots including their barriers need 1,032/2,064/3,096 static bytes. Two slots are enough to express a next-panel pipeline; a third is an experiment rather than an automatic improvement. Register pressure comes mainly from 32 accumulator words and the eight-N16 B bundle; lowering shared size does not remove that pressure.

Splitting K introduces a different resource domain: a shared-by-CTAs global scratch field of 36×60×512 Half values, 2,211,840 bytes in both precision modes, and 270 independent four-byte counters, 1,080 bytes. The scratch is not four times larger for four splits because ordered writers reuse one allocation. Initialize the counters as part of the launch contract. Keep these costs visible when comparing against the scratch-free unsplit baseline.

Treat this as a resource prediction before compilation. A uint4 needs four 32-bit words if scalarized into registers; one accumulator word holds two Half scalars. These declared arrays describe logical state, not an additive count of physical registers: lifetimes can overlap, compiler temporaries add state, and an array may spill into local memory. A register ceiling constrains the compiler; it does not reserve exactly that many registers.

For a candidate with compiled count R and T threads, begin with R·T register words, round using the device allocation rules, then compare the register, shared-memory, thread and block residency limits. Do not infer occupancy from static shared bytes alone. The recorded launch, physical allocation, local-memory traffic and instruction evidence appear later in section 6, after we have predictions to test.

The global scratch is a model-launch resource, not shared memory and not E4 storage. Split 0 initializes it; splits 1/2 reduce into it; split 3 reads it without storing its final low result back. Counter initialization belongs to the launch contract.

05. Execution and scheduling

There are two independent scheduling problems. Inside a CTA, first implement a synchronous K256 partial, then alternate two A slots over 4 K64 steps with the no-overwrite invariant. Across CTAs, establish deterministic scratch ownership: split 0 initializes, 1/2 reduce, 3 reads and completes the low result. Validate four ordered stream launches before allowing four splits to compete in one grid.

Only after both schedules are correct should the final split fuse nearest repetition and skip merge. That saves the expanded projection allocation while preserving one writer per high token. More partial CTAs may increase available work, but polling and scratch traffic may offset it; no timing comparison of K1/K4/K8 is asserted here.

Now implement the candidate schedule: Load W0, issue input 0, and wait for it. Iteration t issues input[t+1] into the other slot before reading its own A vectors and performing MMA. It then loads W[t+1] and waits for the next input. When a slot comes around again, every warp has already passed the intervening wait after reading the previous contents. There are 4 K iterations. The invariant is that a consumer reads a completed current slot and no producer overwrites a slot with unfinished readers. Derive the final-iteration predicates from that invariant: no next input means no next copy or wait. First test one iteration and a final partial ring before running the full reduction.

Keep the outer K loop rolled, then unroll the fixed fragment loops so constant M/N/K-subtile indices can become register selections. This predicts a smaller instruction body than unrolling all 4 reduction steps while retaining direct fragment access; confirm the compiled local-memory and instruction evidence later. The arrows show legal dependencies, not measured overlap. Likewise, __ldca requests cache-all global weight loads and StoreNoAllocate requests a 128-bit store without L1 allocation; cache residency and throughput remain measurements.

This is not a tensor-map descriptor or a software L2 allocation. The full CTA initializes and arrives at the barriers, including lanes that zero-fill invalid tiles.

Milestone 6.1 — Start unsplit, then prove one K256 partial

Keep the full-K1024 implementation as the connectivity oracle. Restrict its input channels to 512…767 to obtain a reference for split 2, and first stage this partial synchronously. Tagged channels at both ends of the range falsify a wrong split base or step limit. The invariant is that a partial covers exactly its K256 interval while retaining the same low token and output channel as the unsplit operation.

Milestone 6.3 — Add cross-CTA control only after ordered launches work

Begin with stream ordering, initialize every counter and guard each scratch slab. Native grid-Z polling is a separate optimization candidate with memory-visibility and scheduling obligations; passing numerical tests in the ordered mode does not prove those obligations. A stale counter, an unscheduled producer, or a visibility assumption unsupported by the memory model falsifies this candidate even if its address arithmetic is correct. The following source is the actual protocol to audit, including its limitations.

Counter byte address is 4·(tileY·2·columns+blockIdx.x); all four splits for this XY output slab share it. With columns=15,tileY=3,blockIdx.x=23, the offset is 452. OrderedSplit−1 selects the split when nonzero, allowing stream-ordered launches. Native mode uses grid Z and polls predecessor completion with a GPU-scope relaxed no-L1-allocation load; publication uses a release store after CTA synchronization.

The FP8 entry skips both polling and its associated CTA barrier in OrderedSplit mode.

The pinned entry does not call the available AcquireSplitPublication helper after its relaxed poll. Therefore this source walkthrough does not assert that an arbitrary relaxed poll plus CTA barrier acquires a predecessor's writes. Native mode also needs launch-capacity reasoning: resident polling consumers must not exclude their unscheduled producers. Rebuild and validate the ordered-stream mode first; evaluate native visibility, counter initialization and scheduling assumptions separately.

Validate the completed candidate against its predictions

The milestones above are a reconstruction plan, not a report that alternative kernels were implemented or benchmarked. Compile the final candidate and check the predicted instructions, physical resources and memory traffic against the recorded capture. A mismatch is a reason to revisit an assumption: local loads may reveal a spilled fragment array; an unexpected lane permutation may reveal a layout conversion; different Half instructions may reveal contraction. A final-candidate capture can identify remaining bottlenecks, but attributing a speedup to a design choice requires a matched baseline experiment.

The explicitly managed storage is global allocations, shared stages and per-lane registers. L2 and L1 are hardware-managed caches on relevant accesses. Shared A vectors are loaded with ordinary aligned uint4 dereferences; there is no ldmatrix instruction or extra XOR shared-memory swizzle in these entry bodies. Bank indexing for a 32-bit word is (byteOffset/4)%32. A 16-byte lane vector spans four banks. Repeated bank indices across a whole warp do not alone prove serialization: the actual instruction's transaction decomposition and broadcast behavior matter.

The working storage format on this page is E4M3 FP8. Tensor-core accumulation, residual products, the recovered activation and the reduction trees discussed here use packed Half words. A uint32_t is a bit container for two Half values, not an integer approximation to their sum. HalfMul, HalfAdd and HalfFma express packed-Half source operations; replacing them with FP32 expressions and a final cast changes that arithmetic. However, ordinary CUDA Half intrinsics can be contracted by the compiler. Helper names alone do not prove a separate rounding boundary: the source-correlated SASS below establishes the actual compiled operations. E4 publication calls PackHalfPairsE4 on two Half2 words and produces four bytes. DecodeE4 performs the reverse operand preparation when a residual must participate in Half arithmetic. There is no scale tensor passed to those conversions.

Start with a high-precision scalar oracle to validate which input contributes to which output. Once the connectivity is correct, introduce a second oracle that follows the source’s K chunk order and publication points. A scalar FP32 sum is not a bitwise reference for Half MMA; it is a tool for catching transposes, wrong groups and wrong spatial coordinates. Keep these two correctness goals separate throughout reconstruction.

Reconstruct and check in dependency order

  1. Implement a full K1024 projection first, then match four source-ordered partials including Half scratch boundaries.
  2. Set skip scales to zero; one tagged low token must appear at four nearest high positions unless cropped.
  3. Set W to zero; high output must equal the same-position scaled skip; match the compiled Half arithmetic when requiring bitwise agreement.
  4. Guard the always-Half scratch and counter allocations. Test four splits and both channel slabs.
  5. Validate ordered launches first; audit native counter visibility and residency assumptions independently of numerical tests.

These are reconstruction checks, not a claim that this documentation build ran them. Match layouts and numerical order first; use the attached capture and its exact launch conditions when evaluating performance.

A global allocation is device memory addressed by a pointer; loads can be served by hardware-managed L2 and, depending on the instruction, L1. A cache hit is not another program-visible tensor and the source does not guarantee cache residency. __ldca permits caching at all levels; __ldcg and PTX .cg select global-level caching that bypasses L1. An eviction or no_allocate hint is a performance policy, not a publication barrier.

Shared memory is an explicitly indexed block-local allocation. Another warp may read a producer's values only after the required block barrier or completed asynchronous-copy protocol. A warp shuffle exchanges register values among its active lanes; it does not address shared memory. Arrays named r_… express per-thread values, but only compiler output establishes whether they stay in physical registers or spill to local memory. Tensor-core accumulator fragments are also register operands. These kernels use mma.sync, not TMEM.

150			g_SplitAccumulator + uint64_t(g_Y * TileCoordinates.g_LowTilesWide + g_X) * 16384 +

182		#pragma unroll

186			const int g_OutputY = TileCoordinates.g_TileY * 2 + g_OffsetY,

188			const int g_SkipY = TileCoordinates.g_HighTilesHigh == 1 ? 0 : g_OutputY;
189			const int g_SkipX = TileCoordinates.g_HighTilesWide == 1 ? 0 : g_OutputX;

195				TileCoordinates.g_OutputChannel * 16 * Profile::ElementBytes + TileCoordinates.Lane * 16;
196			uint32_t r_Output[8][4];
197			#pragma unroll

199			{

201				{
202					const uint4 r_PackedResidual =

204								   : make_uint4(0, 0, 0, 0);
205					const uint32_t r_PackedResidualWords[4] = {r_PackedResidual.x, r_PackedResidual.y,
206															   r_PackedResidual.z, r_PackedResidual.w};
207					const uint32_t r_LowerWords = r_PackedResidualWords[(r_NTile % 2) * 2],
208								   r_UpperWords = r_PackedResidualWords[(r_NTile % 2) * 2 + 1];

210					r_ResidualPairs[1] = DecodeE4(uint16_t(r_UpperWords));
211					r_ResidualPairs[2] = DecodeE4(uint16_t(r_LowerWords >> 16));
212					r_ResidualPairs[3] = DecodeE4(uint16_t(r_UpperWords >> 16));
213				}
214				#pragma unroll
215				for (int r_N8 = 0; r_N8 < 2; ++r_N8)
216					#pragma unroll
217					for (int r_RowHalf = 0; r_RowHalf < 2; ++r_RowHalf)
218					{

220												 ((TileCoordinates.Lane >> 1) & 4) | (g_OffsetX * 8) |
221												 (r_RowHalf * 16);
222						const uint32_t r_Nearest =
223							ShuffleIdx(r_Accumulator.r_AccumulatorWords[0][r_NTile][r_N8 * 2 + g_OffsetY],
224									   r_SourceLane, 31, 0xffffffffu);
225						r_Output[r_NTile][r_N8 * 2 + r_RowHalf] =
226							HalfAdd(r_Nearest, HalfMul(r_ResidualPairs[r_N8 * 2 + r_RowHalf],
227													   r_ResidualScales[r_NTile][r_N8]));
228					}
229			}
230			if (g_OutputY >= TileCoordinates.g_HighTilesHigh || g_OutputX >= TileCoordinates.g_HighTilesWide)
231				continue;
232			const uint64_t g_OutputBase = g_Output +
233										  uint64_t(g_OutputY * TileCoordinates.g_HighTilesWide + g_OutputX) *
234											  8192 * Profile::ElementBytes +
235										  TileCoordinates.g_OutputChannel * 16 * Profile::ElementBytes +
236										  TileCoordinates.Lane * 16;
237			#pragma unroll
238			for (int r_Panel = 0; r_Panel < (bFp8 ? 4 : 8); ++r_Panel)
239			{
240				uint4 r_Published;
241				{
242					const auto& r_LowerWords = r_Output[r_Panel * 2];
243					const auto& r_UpperWords = r_Output[r_Panel * 2 + 1];
244					r_Published = make_uint4(PackHalfPairsE4(r_LowerWords[0], r_LowerWords[2]),
245											 PackHalfPairsE4(r_LowerWords[1], r_LowerWords[3]),
246											 PackHalfPairsE4(r_UpperWords[0], r_UpperWords[2]),
247											 PackHalfPairsE4(r_UpperWords[1], r_UpperWords[3]));
248				}
249				StoreNoAllocate(g_OutputBase + r_Panel * 512, r_Published);
250			}
251		}
252	}
253

256		CounterStoreRelease(g_SplitCounters, TileCoordinates.Split);
257#else

259	__trap();
260#endif
